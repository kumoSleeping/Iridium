# 频道

频道是人和 agent 说话的地方，有自己的 ID 和记录，可以没有 agent。会话是一个托管 agent 的私有上下文，也就是 agent 用户 `agent:<会话ID>`，不属于任何频道。用户定的（2026-11-13，取代 11-12 的“频道就是最初那个会话”）。代码：`internal/channel`（记录、成员）、`internal/deliver`（叫起谁）、`internal/ctx/strategy`、`internal/ctx/assemble`、`internal/prompts`（给 agent 的上下文）、`internal/activity`（活动）、`internal/search`（搜索）、`internal/server/channels.go`（接口、路由）。

- 资料卡、角色、记忆见本文“资料”“角色”“记忆”“agent 知道的自己”。
- 每个会话有一个自己的频道，ID 就是会话 ID：agent 在回合里说的话直接进这个频道（直出）。没人改过成员时，它的成员是所有登录加这个 agent，和以前的会话完全一样。
- 会话可以订阅别的频道（`channel_members` 一行：收、发、已读位置）。在那里它只看到说出来的话；被叫起后直接回复就行，回合结束时最后一句由 Iridium 替它说进频道，中途要说话用 `ir api message.create channel_id=<频道>`。回合里其余的输出留在自己的频道里。一个会话只有自己的频道是直出的。
- 无 agent 的频道（`channels` 表一行）：`channel.create` 不带 `_data.agent`。列在它的文件夹里（`Session.bare`），里面的 agent 都是订阅来的。
- 每个会话在侧栏只有一行。

## 记录

- 频道只记“说出来的话”：人说的、agent 说的、提问、报错、Iridium 自己的一行。每条一个编号，从 1 起，不重用；Satori 的 `message.id` 就是这个编号（`#12`）。
- agent 的思考和工具调用不进频道，留在它自己的记录里：`POST /v1/internal/block.list`、`block.get`（`docs/satori.md`“记录”）。
- 人的话在发送时写进频道（引用是输入的 ID）；agent 用 `ir` 发的、替它说的也在发送时写，记成 agent 的话（`said`，`_data.sent`），不是人的。agent 的话从它的记录读进来（`Sync`，读到哪一行记在 `channel_sync`）；记录还没写到时先按听到的写，记录跟上后认作同一条。
- 以前的会话：频道第一次被读或写时，把整份记录读进来。读进来的不发事件。
- 终端里直接对 agent 打的话，读记录时补进频道，作者是 `terminal`。

## 成员

- agent 是 `agent:<会话ID>`。人有三种写法：`*`（所有应用的所有登录）、`应用/*`（一个应用的全部登录）、`应用/登录`。
- 人：2026-11-13 起新建的频道默认是面板的登录和 Iridium 的（`ir_web/*`、`local/*`），不带 Bot；建它的应用自己也在。新建页里可改（`channel.create` 的 `_data.members.people`）。之前的、没选过的频道是 `*`。选了人以后，没被选进来的仍然在侧栏看到、能读，但不能发消息、不能答提问和审批、不能停 agent、不能改成员（403）。Iridium（`local`）始终在里面；频道里的 agent 也在。群里任何人都能改成员（`PUT …/people`），改的人自己留在里面。agent 的 `ir` 不能改人、不能移出成员；`DELETE …/members/{member}` 只收 `agent:`。改 agent 的称呼要有用那个会话的权限。
- agent 的 `user.name` 是它现在用什么跑的（`Claude Opus 5.5 High`），`nick` 是叫它的名字：字母、数字、`_`、`-`，至多 32 个。称呼是会话的（`agent_nicks`），整个 Iridium 里唯一（不分大小写），在哪个频道都一样；第一次进有别的 agent 的频道时自动起（`claude`、`claude2`）。`@` 只认 `nick`；Satori 的 `<at id="agent:<会话>"/>` 等同 `@nick`。
- 每个 agent 一个 `recv`：`all` 收人说的每句话；`at` 只收点到它的。频道自己的 agent 是 `all`，订阅来的默认 `at`。`send`：`direct`（频道自己的 agent）或 `ir`（订阅来的：用 `ir` 发，或回合结束时替它说）。
- 一个频道至多 8 个邀请的 agent，拉起的（`spawned` 的 `by` 是频道里的 agent）不占这 8 个；连同拉起的至多 32 个（加入时逐个数，同时加入不会超）。
- 邀请：`POST …/members`，`session` 给已有的会话（要能用它），否则新开一个会话再订阅（`agent`、`model`…，`cwd`、`machine` 不给就是频道的文件夹）。新开的是为频道开的：侧栏不列，从频道顶栏的成员键进去，跳转框能搜到（kumo，2026-11-15）；移出后照常列在它的文件夹。邀请时可带 `text`：它进来后由邀请者在频道里说一句“@称呼 text”叫起它，它的回话照常说在频道里（agent 拉人一起干活就这样做：先邀请，再 @，kumo，2026-11-16）；带了 `text` 就不打招呼。页面上邀请的 agent（`greet`）进来后先说一句：Iridium 给它一回合“X 邀请你加入了这个频道，打个招呼，说说你是谁”，它的话照常说在频道里；`ir` 和 agent 邀请的不说（kumo，2026-11-16）。别人的“在干活”只在回合里（`running`、`compacting`）画，进程启动（`starting`）不画，免得头像闪一下就没了。`Session.spawned {by, channel}` 记谁拉起的（会话）和在哪拉起的（频道）。别的机器上的会话也能邀请。
- 拉起（kumo，2026-11-15）：会话里 `ir new` 开的，就是邀请进拉起者当前所在的频道：它正在为哪个频道干活（被那个频道叫起，`calls:`）就进那个，否则进它自己的频道。新会话记成 `spawned`、`recv` 是 `at`，和邀请新开的一样；`launcher` 只记谁开的，不再挂在谁下面。拉起者归档，它拉起的一起归档、一起恢复。拉起时没给称呼（也不是角色），用 `data.name` 去掉标点空格当称呼；都没有时是临时称呼“种类名-会话 ID 的 4 位十六进制”（`Claude-b134`、`DeepSeek-c54b`，重了多取几位），不再是 claude2（kumo，2026-11-16）。用着临时称呼的 agent 第一次被频道叫起，先被要求给自己起个称呼（`ir api PATCH internal/self nick=…`）再回答，改名照常在频道里记一行；没有 `ir` 的不要求。拉起时的第一句话（`_data.text`）不直接进它自己的会话，而是加入后在频道里作为拉起者的话叫它（`#n` 加频道上下文），它的回答说在频道里（kumo，2026-11-16）。不在频道里干活的会话（人的 `ir`、页面）照旧。提示词（kumo，2026-11-16）：系统提示和“Helpers”教 agent 在群里再要一个 agent 就邀请（带称呼、介绍和 `text`）再 @，`channel.create` 只开群外的会话；`--wait` 只在它自己的帮助里说清楚：占着自己的回合等对方回合结束，只用于群外替自己干活的会话，群里的 agent 说的话群里已有、回它的话会叫醒它，不用等。
- 移出只是退订，会话照旧。频道自己的 agent 移不出。
- 清空会话（`/clear`）：新会话接替旧的。旧会话订阅的频道、称呼、头像、资料、角色、记忆、`spawned`，和它自己频道的成员，都转给新会话，并记下新会话是从哪个会话接下来的；旧会话归档，不再在任何频道里。
- 订阅来的 agent 的会话归档了：不叫起，不占名额；恢复后照旧（选的是路由时跳过，不退订）。
- 建会话时可以一次配好：`channel.create` 的 `_data.members {agents, people, nick, recv}`；第一句话在成员都到齐后才说，点到谁就给谁。
- 会话列表里：`Session.agents` 是它的频道里的全部 agent（两个以上时；无 agent 的频道一个也列），`Session.in` 是它订阅的频道。
- 接口见 `docs/api.md`“频道”。agent 自己也能加：`ir api POST internal/channels/self/members agent=codex`。

## 提问（kumo，2026-11-15）

- 频道里的 agent（自己的、订阅来的、拉起的）的提问、审批、计划都进这个频道；一个 agent 在几个频道里，几个频道都进。
- 频道页输入框上方排成一队：按提出的先后，最早的在前面展开，其余收成一行“还有 N 个”。每条带提问者的头像和称呼，点头像进它的会话。
- 频道里能答提问的人（见“成员”）和频道里的应用都能答，先答的算；答了或撤了，各处一起结束。
- 频道记一条（`kind` 是 `ask`），所有成员的未读都加一；应用收到 `message-created`（`_data.kind` 是 `ask`），结束时 `message-updated`。没有指定谁来答：全量推给频道里的人和应用。
- 报错也一样：agent 的报错进它自己的频道和它所在的每个频道（`_data.kind` 是 `error`）。

## 频道里的事

成员变了，频道里记一行 Iridium 自己的话（`kind` 是 `note`），文字给只认字的应用看，消息的 `_data.event` 给页面按自己的语言说：`join`（agent 加入：`member`、`nick`、`name`）、`leave`、`rename`（`from` 旧名、`nick` 新名）、`recv`、`people`（`added`、`removed`、`everyone`）、`undelivered`（`seq` 没送到 `nick`）、`stopped`（`seq` 没转交）、`silent`（`nick` 被 `seq` 叫起，回合结束时没在频道发话；回合因出错结束时 `reason` 写原因：余额不足、认证失败、请求太频繁，或错误的第一行，文字里接在“未在频道发话：”后面，kumo，2026-11-15）；`by` 是谁做的。建会话时一并配好的成员不记。这些行不进给 agent 的上下文。

## 叫起谁（两个以上 agent，或无 agent 的频道）

- 人的消息：点了名（`@nick`）就只叫起点到的 agent；没点名，叫起 `recv` 是 `all` 的。
- `@全体成员`、`@全体Agent`：叫起频道里所有 agent（发话的除外），和每个都点了名一样；Satori 里是 `<at type="all"/>`、`<at role="agent"/>`。这两个名字不能当称呼。
- 引用（Satori 的 `<quote id="编号"/>`）：被引用的是某个 agent 的话，就当点了它的名；给它的消息里在原话前写上引用的那条（编号、谁、头 200 字）。频道记下引用的编号（`_data.quote`，内容开头的 `<quote id/>`）。单 agent 的会话里，引用的话写成 `>` 引用行放在前面。没被叫起的，下次被叫到时在上下文里读到。
- agent 的话：只叫起它 `@nick` 点到的。频道自己的 agent 说的话直接算；订阅来的 agent 用 `ir` 发的、和回合结束时替它说的那句才算。agent 不会因为别的 agent 说了话就被叫起。
- `@nick` 要独立成词，不在代码块、行内代码和引用行里。
- 给 agent 的说明里有一句：agent 之间只在需要对方回答时才 @，话说完了就不带 @ 回复，到此为止（防止来回不停）。
- 从人最后一次在这个频道说话算起，agent 之间至多连续转交 4 次（按频道计，人一说话重新算，不带到别的频道）；再转，频道里记一行“未转交”（直出的、替它说的）或 `ir` 被拒（400），不再叫起谁。拉起者和它拉起的 agent（`Session.spawned`）在拉起它的那个频道里的往来另计，至多连续 12 次；在别的频道里和普通 agent 一样。
- Claude：人要有 Claude 的权限才能点它；没有权限的人说话，`recv` 是 `all` 的 Claude 不被叫起。agent 点 Claude 不受限。
- 订阅来的 agent 被叫起后（谁在哪个频道被叫起记在库里，`calls:<会话>`，重启不丢），可以直接回复：回合结束时它没用 `ir` 在频道发过话，最后一句回复由 Iridium 替它说进频道（2026-11-13）。用 `ir` 说过了就不再转。每次叫起记着给它的那条输入：收下这条输入的回合结束才算数，别的回合结束时它还在排队就接着等。回合结束时什么也没说、回合被掐断（进程停了）、或重启期间回合已经结束：频道里记一行（`silent`）；它是另一个 agent 为这个频道拉起的，拉起者另收到一条通知。被另一个 agent 叫起、没什么要说的，不记这一行（只有人叫它、或回合出错时才记）；agent 也可以用 `ir api POST internal/sessions/self/interrupt` 停掉自己这一回合，叫它的那些就算答过了，什么都不替它说，也不记（kumo，2026-11-16）。页面上它的“在干活”框先淡出再收起（`.g-depart`），不是一下消失。agent 在群里说的话给别的 agent 时标的是它的称呼（`[@称呼]`），不是它会话的 ID；会话标题去掉这个标签和 `<channel-context>`。“加入了频道”由 agent 拉的记成那个 agent 的称呼。
- 以 `/` 开头的话：只有频道自己那个 agent 的命令（`/clear`、`/compact`、它握手时报的那些）才单独交给它，其余（`/home/x 坏了 @codex`）照常说进频道。
- 只有自己一个 agent 的会话和以前完全一样。

## 收和发

- 默认只收点到它的（`recv` 是 `at`）。agent 自己能改：`ir api PATCH internal/channels/<频道>/members/agent:<自己> recv=all` 收人说的每句话（只能改自己的 `recv`）。
- 跟随：`ir api POST internal/channels/<频道>/follow user=<称呼|用户ID|*> count:=N seconds:=T`，接下来 `user` 说的 N 条（默认 1，至多 50）在 T 秒内（默认 600，至多 3600）不点名也给它。只记在内存里，重启就没了。
- 发话：`ir api message.create channel_id=<频道> content='正文'`：单引号里可以多行，shell 不解释其中任何字符，正文里的 `'` 写成 `'\''`（kumo，2026-11-15：不再有 `k=@-`，只留这一种写法）。在自己所在的频道里这样发话，手动审批下也不弹审批（`session.speaksOnly`：只认这一条命令：`channel_id`、`content`（或 `_data.text`）各一个，值不带引号，或在单引号里，或在不含 `$`、反引号、`\` 的双引号里；带别的参数、接别的命令照常问）。
- 发送检查：agent 用 `ir` 发话时，它没读过的消息随回答一起给它（`_data.unseen`，`ir` 直接印出来），已读位置前移。没读过的超过 12 条，或其中有点到它的：不发，回 409 `behind`，正文是这些消息；读完再发。

## 给 agent 的上下文

被叫起的 agent 收到一条消息：`#编号: 原话`，后面一个 `<channel-context>` 块。

- 它是谁、频道里有哪些 agent、怎么叫别的 agent。订阅来的 agent 另外被告知这是哪个频道（名字和 ID）、直接回复就会替它说进频道；有 `ir` 的还被告知中途要说话用 `ir api message.create channel_id=<ID>`。
- 它上次读过之后的消息里的附件只给名字（“（附件：a.png、b.pdf）”），不给路径、不给图片，免得没叫它的 agent 去读；叫它的那条照旧给全（路径和图片），要看早先的用 `message.get`（kumo，2026-11-16）。人发在频道里的附件跟着消息存下（`_data.files`），无 agent 的频道也能发。
- 它上次读过之后的消息：近的给原文（`#431 [谁 · 时间 · 做了什么]: 正文`），只在消息之间切；单条超过 2000 字截断，写明怎么取全文。更早的按回合一行（谁问、头几个字、谁答），至多 30 个回合；再早的只写数量。总量约 24KB（`strategy.Default`）。
- 每个 agent 在这段时间里做了什么的合计，和改过的文件。
- 怎么查更多：`ir api message.list channel_id=<频道>`（自己的频道是 `self`）、`_data.q`、`message.get`。没有 `ir` 的没有这一行。
- 每个 agent 一个已读位置（`channel_members.seen`），给过就往前移。同一个 agent 一次只给一条。
- 增量（2026-11-13）：频道的固定说明（它是谁、频道、有哪些 agent、怎么回答，加上怎么查更多）只在这些时候给：第一次被这个频道叫起；说明变了（agent 换了、频道改名、提示改了，按说明全文的哈希比）；上次给过之后它压缩过上下文（读它的记录，看有没有压缩那一行）。别的时候只给一行“仍在「频道」里”（订阅来的）或什么都不给（频道自己的 agent）。注入单记着 `static`（说明的哈希）、`full`（这次给没给）、`line`（当时它的记录到哪）。清空会话是换了新会话，自然从头给。

## 分层和可追溯

| 层 | 在哪 | 管什么 |
| --- | --- | --- |
| 文字 | `internal/prompts/texts/*.md` | 给 agent 的每个固定的字，一段一个文件，文件名是 ID |
| 策略 | `internal/ctx/strategy`、`assemble/policy.go`、`internal/deliver` | 纯函数：给什么、给谁；不产生字 |
| 组装 | `internal/ctx/assemble` | 策略的结果加文字，成一份注入（`Injection`），每段记着出处 |
| 投递 | `internal/agent/*`、`session` | 只收 `Injection`，不改内容 |

每次给 agent 的东西留一份注入单（`injections` 表，每个会话留最近 200 份）：用了哪些片段、片段的哈希、填进去的值、引用了哪些消息，还有它实际收到的全文（`text`；kumo，2026-11-16，原来不存正文，看不出它收到了什么）。记的不只是频道叫它的那条：每次起进程时的系统提示、写给它的每一行（频道消息连同发送者标签、私下发来的消息、Iridium 自己的恢复提示），和它的 `ir` 在频道里得到的回执（“你上次读过之后说了……”、发送被拒）。页面“注入记录”按新到旧列出，每条写是什么（系统提示、`#n`、消息、ir 回执）、时间、全文（长的折起），片段来源收在“来源”里。`GET /v1/internal/sessions/{id}/injections`。

## 活动

读 agent 的记录时数它的工具调用（`internal/activity`），挂在它下一句话上：bash 几次、失败几次、各是什么程序开头的；读了几次；网页搜索和抓取；子 agent；用编辑工具改的文件和增删行数。不记命令原文、搜索词和结果。shell 命令改的文件数不到。别的机器上的 agent 改的文件写成 `机器名:路径`。消息内容后面跟 `<iridium:activity>`，文件路径只给网页和 Iridium。

## 搜索

`message.list` 的 `_data.q`：有这些词的消息，最近的若干条。索引是 SQLite 的 FTS5；中文按单字和相邻两字切，不用词典。索引的是正文，加上 agent 改过的文件路径和跑过的程序名。

## 已读

- 每个成员在每个频道有一个已读位置（读到第几条）。人：页面看到哪条就 `POST …/read {seq}`，按登录记（`channel_reads`），只进不退。agent：给过它的最后一条（`channel_members.seen`）。只有它一个 agent 的会话算全读（`recv` 设成什么都一样，话都直接给它）；多个 agent 时，频道自己的 agent 是给过它的和它自己说的最后一条里靠后的那条（点别人的话没给它）。
- `GET …/reads` 和携带状态 `reads:<频道>`：`ChannelReads {end, readers[]}`。某条消息谁读了：`seq` 不小于它的那些。

## 有人 @ 我（2026-11-16）

- 算点到一个登录的：消息里写了 `@它的名字`（规则同 `@nick`，名字里可以有空格和点，取最长的）或 Satori 的 `<at id="它的用户ID"/>`；`@全体成员`（`<at type="all"/>`，只算频道里的人）；引用了它说的话。人说的、agent 说的（直出、用 `ir` 发、替它说的）都算；自己的话不算自己。单 agent 的会话也算。应用（Bot）没有。
- 每个登录在每个频道记一条：第一条点到它、它还没读的消息（`channel_ats`：`seq`、`everyone`）。先有 `@全体成员` 再被单独点到，`everyone` 去掉，位置不变。消息写进频道时就记，没发出去的撤掉。
- 已读位置过了这条（`POST …/read`）就清掉；读到频道末尾，一并清掉。网页打开那个会话就上报读到这条（单 agent 的会话也报）。
- 页面：携带状态 `ats`（每条连接只带自己的），`GET /v1/internal/ats`。跨设备一致。
- 侧栏那一行第二行前面加红字“[@我]”，只是全体的是“[@全体成员]”，后面照常是“谁: 最后一句”。
- 有标记的频道：免打扰时未读角标也是红的，标题和应用角标把它算进去。
- 推送：点到谁就推给谁的浏览器（`kind` 是 `at`），不看这个会话的推送规则和免打扰，只看总开关；不推给说话的人。
- 只记第一条：读到它就清掉，它之后、还没读到的点名不再有标记。

## 资料（kumo，2026-11-16）

- 人、agent、应用、频道各有一张资料卡：称呼、介绍、头像、背景。agent 的称呼就是 `nick`，频道的是频道名；人的称呼和头像仍是登录自己的（资料页）。
- 介绍至多 200 字。agent 的介绍同时是它的人设：写进它的系统提示（“Who you are”）。会话自己的频道也有自己的介绍、头像、背景，和它那个 agent 的分开；频道没设头像、背景时显示 agent 的（kumo，2026-11-16）；有几个 agent 时没设头像，侧栏、标题前、频道卡显示前两个 agent 各自的头像（左上、右下叠着），不是它们的图标（用户，2026-11-16）。
- 头像和背景可以是图片（PNG、JPEG、WebP，至多 2 MB；背景存成 720×270；页面先缩小压缩再发，不让用户自己压），也可以是一个表情或一个颜色（`#2f4f6f`）：服务端把它画成 SVG，从同一个地址给出，页面不用区分。
- 存在 `profiles` 表：agent 和频道是 `c:<ID>`，人和应用是 `u:<ID>`，角色是 `r:<ID>`；背景图在 `avatars` 表的 `b:<键>`。
- 谁能改：频道里的任何成员（人、agent）都能改这个频道和里面任何 agent 的资料；人和应用还要有用那个会话的权限。人的资料只有本人能改。
- 接口：`GET`、`PATCH /v1/internal/self`（自己）；`GET`、`PATCH /v1/internal/members/{称呼|会话|登录名}`；`GET /v1/internal/channels/{id}/profile`、`PATCH /v1/internal/channels/{id}`（`here` 是 agent 正在为之干活的频道）。`ir api help profile`。
- 开会话时一并给：`channel.create` 的 `_data.nick`、`_data.intro`、`_data.avatar`、`_data.background`；邀请同理。agent 开会话没给资料时，`ir` 在标准错误里提示一句。
- 改了资料，频道里记一行灰字（`event.type` 是 `profile`，`what` 列出改了哪几项），不计未读、不推送；同一个人接连改同一张卡只留一行。改称呼仍是 `rename`。
- 告诉 agent：不叫起谁。每个 agent 在每个频道记着上次告诉它的资料（`profile_told`），下次被叫起时和现在的比，不同的写在 `<channel-context>` 里“Profiles changed”一节：改名、新的介绍、头像或背景换了。它自己改的不再告诉它。频道的固定说明不再因为改名、改介绍重给：说明的键只看片段文字、是哪个频道、有哪些 agent。
- 固定说明里 agent 的名字后面带介绍的头 80 字；另有一行列出频道里写了介绍的人（至多 8 个）。

## 角色（kumo，2026-11-16）

- 角色是存下来用来开会话的一张卡：称呼、介绍、头像、背景，加上 agent、模型、思考强度（`roles` 表）。平常开的会话不是角色；在“编辑资料”里点“存为角色”才是（`POST /v1/internal/roles {session}`）。
- 以角色开会话（`channel.create` 的 `_data.role`，邀请的 `role`）：卡抄一份给会话，称呼用角色名，被占用时后面加数字；模型和强度可以当场另给，只管这一次。会话里之后改的资料不回写角色，“更新角色”才回写（`PATCH /v1/internal/roles/{id} {session}`）；“移出角色”是 `DELETE /v1/internal/sessions/{id}/role`。
- 同一个角色可以同时开几个会话。
- 网页：新会话页的“角色”一行（点一个加进阵容），邀请菜单最前面，设置里“角色”一页。

## 记忆（kumo，2026-11-16）

- agent 自己写的短句，一条至多 300 字：`ir api internal/remember text='…'`；`GET /v1/internal/memory` 列出，`DELETE /v1/internal/memory/{id}` 删。只有 agent 主动写，Iridium 不替它总结。
- 归属：会话是某个角色的，记忆就是角色的，这个角色的所有会话共用；否则是会话的，清空后转给接替的会话，存为角色时一并带过去。
- 每条记着出处：哪个会话写的、当时为哪个频道干活、那个频道到第几条、什么时候。
- 何时写（写在系统提示里）：用户要求记住、一件大事做完、用户明显在意、发现明确的偏好、遇到值得下次知道的严重问题；一回合至多一次，放在回合末尾，统筹成一条，写明出处。优先用它，而不是 agent 自带的记忆文件。
- 人在“编辑资料”（卡里原地切换的编辑）里看和删。

## agent 知道的自己（kumo，2026-11-16）

每次 agent 进程启动时，系统提示末尾带一段（`assemble.Self`，约 200–600 token），全部直接取自记录，没有总结：

- 称呼和介绍。
- 它写下的记忆，最近 12 条，带日期和出处；更多的写明条数。
- 它所在的频道（至多 8 个，最近发过话的在前）：上次发话的日期、当时还有谁在说话、它那句的开头。
- 清空之前的上下文（至多 3 份）：何时清空、多少回合、第一句的开头、会话 ID。清空时记下上一份是哪个会话（`session_before`）。
- 四行用法：查记录、写记忆、改资料、找帮手（能用自家的子代理就先用自家的；要另一种 agent 或模型、要一个角色、要留在频道里让人对话的，才用 `ir` 开会话；kumo，2026-11-16）。日期只写到日，没有新的事时提示不变，不废缓存。

查记录的命令（只读，手动审批下不问，`session.looksUpOnly`；`remember` 也不问）：

| 命令 | 作用 |
| --- | --- |
| `ir api GET internal/self` | 自己的卡、所在频道、之前的上下文、记忆 |
| `ir api internal/recall q='词'` | 先搜记忆，再搜它所在的频道和清空前的上下文的消息；`all:=true` 搜它看得见的全部；每条带取全文的写法 |
| `ir api GET internal/members/<称呼>` | 一个成员：卡、同在的频道、最近说的话 |

只有一个 agent 的会话没有频道上下文，这一段是它知道资料和记忆的唯一途径；所以别人改了它的资料，它要到进程下次启动才知道。

## 元素

消息里 Markdown 和 Satori 的元素可以混着写（2026-11-13）：Markdown 没有的用 Satori 的（`<at>`），两边都有的随便用哪个（图片 `![](…)` 或 `<img src/>`）。Iridium 叫起谁时把 `<at>` 读成 `@称呼`（`satori.AtWords`），网页显示时把 Satori 元素换成 Markdown 再画（`web/src/chat/refs.ts` `fromSatori`）；代码里的照原样。

## 记录里的转发

agent 自己的记录里，频道转给它的那条，`block.list` 给成 Satori 的合并转发：`<iridium:relay channel name seq full>说明</iridium:relay><message forward>…</message>`，转发里每条是一个带 `<author>` 的 `<message id="编号">`，是这次给它的那些消息（按注入单），叫它的那条在最后；说明只在这次给了时才有（`full`）。只认 Satori 的客户端看到的就是一条合并转发。注入单已经不在的（每个会话留最近 200 份）照原文给。

## 读别的 agent 的记录

agent 的 `ir` 能读它看得见的任何会话的记录：只读，密钥照常打码。三层：

- 活动：频道消息后面的 `<iridium:activity>`（做了什么的计数、改的文件）。
- 提要：`POST /v1/internal/block.outline {channel_id, from?, to?, limit?}`，一回合一行：谁问的、头几个字，这回合做了什么（同活动），最后一句的头几个字，以及这回合在记录里从哪块到哪块。
- 全文：`block.list`、`block.get`。

## 指向

频道里 agent 的消息带出处（`message.list` 的 `_data`），网页展开和 agent 读取用同一份：`session` 是哪个会话；直出的话带 `block`（记录里的那一块）；用 `ir` 发的带 `from`、`to`（它被叫起之后到发话时，自己记录里的行号范围）。拿去 `block.outline`、`block.list` 读那一段。

## 私聊

`POST /v1/internal/dm {user}`：调用者和 `user`（一个登录的 Satori 用户 ID，Iridium 是 `local`）两个人的频道，回 `{channel}`。同样两个人永远是同一个（记在 `dm:<两人>`）；第一次建：无 agent，成员就是这两人，放在 Iridium 那台机器的家目录那个文件夹，名字“甲 · 乙”（2026-11-13）。只有这两个人看得到、读得到（不看文件夹范围；Iridium 不是其中之一时也看不到）；同样两人同时来开，得到的是同一个。还没做：侧栏单独一组。

## 头像

- 频道有头像。会话（它的 agent）的头像存在 `avatars` 表 `c:<ID>`；会话自己的频道作为频道的头像、介绍、背景另存在 `g:<ID>`，`GET …/avatar?of=channel`、`…/background?of=channel` 取，没有就是 agent 的；侧栏、标题栏、频道资料卡用这个。`PUT /v1/internal/channels/{id}/avatar`（图片本身，或 JSON `{avatar: base64}`；存成 128px）、`DELETE`、`GET`。只给频道里的人；agent 改头像走资料的接口（见“资料”）。
- 给会话换头像时同时记为它那个模型的头像（`m:<agent>:<model>`）：同模型、自己没头像的会话都用它，以后新开的也是。没指定模型或只指定了一族（Claude 的 `opus`）、没在跑的会话，模型是它上次跑的（用量记录里最后一回合的），不是空着或族名等它再跑（用户，2026-11-16：群里的 Claude、选了 opus 的会话显示成图标）。
- Satori 里 agent 用户的 `avatar` 就是这个地址；携带状态 `avatars` 是一个只增的数，只有头像、背景变了才加一（它在每个头像的地址里，一加所有头像都重取）；称呼、介绍变了加的是 `cards`，资料卡按它重取（kumo，2026-11-16：给一个会话起名，侧栏所有头像都闪了一下）。头像换地址时先留着旧图，新图到了再换。

## 正在看的人

页面订阅携带状态 `viewers:<频道>` 就算在看这个频道，状态的值是现在在看的登录（`Viewer {member, name, pages, since}`）。

## 网页

- 新会话页（kumo，2026-11-16）：组一个阵容再开，点一下不直接开。文件夹一行下面是“Bot”一行（写着带进来的 Bot，点开先列已接入应用的 Bot：整个应用或其中的登录，下面是“人”：面板用户；默认面板用户和 Iridium，不列电脑）、“角色”一行（点开列出角色，点一个加进阵容），再下面一排 agent（第一个是“不带 agent”，图标是一组人，点了加进阵容、再点去掉），点一个加一个，同一个角色、同一种 agent 可以加几次。阵容每行：头像、称呼（直接打字，按 nick 的规则检查，重名或不合规标红；不填用服务端的默认称呼）、模型一行（点开改这次的模型和思考强度）、接收（“点名”或“全部”，点了切换；第一个 agent 是会话自己的，默认全部，其余默认点名；只有一行时不显示）；右键或长按一行：接收、移出。行出现、移出都是高度滑开、收起。最后加的是角色时，下面展开它的资料卡（背景、头像、称呼、介绍）。“开始”一个：一行就是原来的开会话；几行：第一个是会话自己的 agent，其余随会话一起邀请（`members.agents`，`members.recv` 是第一个的接收）；不带 agent：开一个频道，每行都是邀请进来的。别的电脑的文件夹：那台电脑的 agent，邀请的也在那台电脑上（频道的电脑）。
- 输入框里 `@` 列频道成员，agent、人、应用平级（2026-11-13）：agent 的称呼，频道里的每个登录（头像、名字）和整个应用，最后是 `全体成员`、`全体Agent`。点人和应用只是写上 `@名字`，不叫起 agent；被点到的登录有标记和推送（见“有人 @ 我”）。提及会话和文件夹用 `&`。单 agent 的会话里 `@` 也列成员（有称呼的 agent、频道里的人和应用），不列全体。
- 消息里的 `@名字` 三种成员一样画：`@`、头像（agent 的和它说话时旁边的一样：自己的、它模型的，都没有才是图标；@ 列表里也是，用户，2026-11-16）、名字，带下划线，点了弹出它的资料卡（和点头像是同一张）；`@全体成员`、`@全体Agent` 是图标加名字，不能点（2026-11-14）。
- 点别人（人、应用）的头像也弹资料卡：头像、名字，“私聊”（两人的频道；只有登录和 Iridium 有，应用和不是登录的作者没有）、“提及”。
- 消息右键（长按）：引用、复制；引用的那条显示在输入框上方，发出的消息上面一行灰字写它引用的哪条。
- 标题下不排头像。电脑上标题前是频道头像（没有就是 agent 图标），点它从头像弹出资料卡（会话的频道就是它 agent 的那张卡；没有自己 agent 的频道是频道名、介绍、背景），卡上“编辑资料”在同一个弹窗里换成编辑，不进单独页面（kumo，2026-11-16）；未加入的人也能看卡，没有“编辑资料”；手机上标题前是 Iridium 的标，点它打开会话列表，“编辑资料”在“⋯”里，从“⋯”弹出。顶栏右侧：正在看的人（各自的头像，点开看名字）、成员（键上写人数：agent 加人，一个登录算一个；点开：每个 agent 名字前一个上下文圆环（不写数字），各自收什么、直出还是 `ir`、查看会话、移出；不列“人 / 所有人”（kumo，2026-11-16）；最后是“邀请”：agent 的种类 → 它的模型和思考强度，选定就加入；人：应用一层、登录一层，不列电脑）。输入框底部不列邀请过的 agent。移出有两个入口（成员列表、agent 头像的菜单），是同一张确认卡，确认后才移出；被移出的会话保留。“⋯”：第一行是所在文件夹（点了复制），然后是原来的会话操作（手机上另有“编辑资料”）。
- 用量在每条 agent 消息头上、模型名后面，单独一小条（2026-11-13）：上下文圆环和额度细条，和手机上一样不写数字，各自点了弹出详情（`/context` 打开 agent 最后一回合那个；还没有 agent 回合时交给 agent）。输入框里不再放用量和上下文，也不放模式、模型、预设（kumo，2026-11-16，一个 agent 还是几个都一样）：模式和模型在 agent 头像的菜单里，预设在阵容和邀请里选；`/mode`、`/model` 仍在原处打开这两个菜单。
- 频道页里只有自己的话在右侧；别的登录、应用、agent 都在左侧，各自的头像。点 agent 的头像弹出它的资料卡（像 QQ）：头像、称呼、模型、状态（不放上下文、用量：它们在消息头的小条上）；“发消息”去它自己的频道（会话，和它绑定的那个频道），“提及”在这里 @ 它；频道自己的 agent 是“换头像”和“查看会话”。agent 头像的右键（长按）菜单：提及、压缩、模型（就是输入框下那个模型菜单：模型列表、强度条、UltraCode，不做只列名字的简版，不另设“强度”一项；kumo，2026-11-16）、模式、停止、接收、改名、换头像、查看会话、注入记录（频道每次给了它什么；从头像展开的弹窗）、移出。未加入的人没有“提及”。
- 已读标记现在不显示（kumo，2026-11-16；`SHOW_READS`），已读位置照常记。原先的画法：每个成员（agent、人、应用）自己的小头像停在它读到的那条下面，前面写“已读”，叠在消息之间的空白里，晚到也不把内容顶开；点一下列出谁读了。自己的不显示。页面回到前台时也上报已读位置。
- agent 的每条消息上面是它这一段的思考和工具调用，从它自己的记录里取（按“指向”），和单 agent 会话一样折叠（只有思考、没有工具调用的也显示）；取不到时是一行计数。
- 消息的时间在消息头里名字的内侧（小灰字）：左边的消息在名字后面，自己的（右边）在名字前面（kumo，2026-11-16）。平常不显示，位置留着：电脑上鼠标移到这条消息上才显示，手机上点这条消息所在位置的空白（不是字、键、图、气泡）显示，再点收起。灰色的事件行（加入、移出、未发话等）放不下时点一下展开全文，再点收起。
- 无 agent 的频道不显示附件键，拖入、粘贴的文件不收。
- 单 agent 的会话里，别人（人、应用）的头像也弹资料卡（私聊、提及）；自己会话的 AI 资料卡有“发消息”（回到输入框）和“换头像”。
- 单 agent 的会话里 agent 也有头像：两条消息之间它做的和说的是一段，头像在左，上面是称呼和模型；右键菜单同频道页。
- agent 自己的记录里，别的频道叫它的那条不折叠：左侧是 Iridium 发来的一条（“转自「频道」· #编号”，点了去那个频道），内容是一张“聊天记录 · N 条”卡片：这次补给它的消息一条一行（谁、说了什么，前面的灰、最多三行），叫它的那条在最后；这次给了说明的，卡片右上角有“频道说明”，点开看全文。接着是它这一回合，和平常一样。没有注入单的旧记录照原文显示（原话加“上下文补充”）。
- 侧栏的会话行（2026-11-13）：左边是头像（频道头像，没有就是 agent 图标），右边两行：上面名称，下面“谁: 最后一句”（自己是“你：”，agent 用称呼，没有称呼用种类名）。未读条数是头像右上角的角标，最多 `99+`：红底白字；免打扰的是灰底，有人 @ 我时仍是红底。自己开的会话默认提醒，别的应用或登录开的（`Session.opener`，连同它们拉起的）默认免打扰；会话菜单里“免打扰 / 取消免打扰”可改，记在本浏览器。标题和应用角标只数不免打扰的会话，和有人 @ 我的会话。未读由网页计数，记在本浏览器（刷新还在）：不在眼前的会话每来一句（不是自己说的）加一，回合结束而没数到话的算一条，页面关着时说过话的算一条；打开它、或打开它所在的频道就清零。
- 会话页不换页（kumo，2026-11-15）：会话的页面一直是同一个，多一个 agent 只是多一个成员。别的 agent、没交给它的人话、Iridium 的事件行，按时间插在它自己的记录之间；一回合还只有思考和工具调用、没说话时，这一段按它开始的时间排（叫它的那句在上面）；它自己的话只从它的记录来，只有它中途用 `ir` 发进自己频道的话从频道记录来（记录里那只是一个步骤；用户，2026-11-16）。频道有了第二个 agent 时才读频道记录（代码和最新一页一起取，到了才画）；往上翻时频道记录跟着翻到同一时间。无 agent 的频道仍是频道页。
- 交接（kumo，2026-11-15）：被叫起的 agent 的“在干活”框，等叫它的那句话上了屏、自己 agent 那句写完才出来（最多等 1.5 秒），从那句话下面展开再升起（`g-arrive`）。
- 输入框是人的，不跟着在跑的 agent 变（kumo，2026-11-16）：发送键不变成停止键，没打字时是不可点的发送键；自己的 agent 在回合中时，打的字照旧插入或排队。停止键在那个 agent“在干活”那一行的右侧，自己的 agent 和频道里别的 agent 一样；头像菜单的“停止”、`/stop`、Esc（停自己的 agent）不变。
- 子代理是派遣来的人（kumo，2026-11-16）：harness 自己的子代理（Claude 的 Agent 工具、Codex 的子线程）在父会话页里算一个临时成员，头像是 agent 图标加子代理角标，名字是任务名。父 agent 派它的那句和后来给它的话（SendMessage）画成一行“→ 头像 名字 开头几个字”，点开看全文，不再是工具行。它交回的是它自己的一条消息：头像、名字、“派遣”，后面小灰字写用时和 token（记录里有才写），正文折成三行，点开展开。干活时是它自己的一轮，在父 agent 那一轮外面，实时画它的步骤和话（同主 agent），交回后换成交回的消息。点头像弹只读资料卡（同一张卡）：名字、“派遣”和模型、在干活或已交回、派遣方，“查看会话”；不能 @、不能私聊、不能改。成员键里只在“在干活的子代理”一节，头像名字同上。pi、dsh 没有子代理，不变。只是画法，记录和接口不变：交回的正文从子代理自己的记录取（它最后一次 SubagentHandback，没有就是最后一句话）；通知按任务名对上派它的那次调用，同名的按先后；派它的调用不在已加载的页里时只按名字找会话。Codex 的记录里只有派出那一步，交回按子线程结束算。
- 侧栏：为频道开的会话（邀请新开的、拉起的）不列（见“成员”）。
- 邀请菜单（kumo，2026-11-15）：成员键一打开就把各种 agent 的模型取好，浏览器里也存一份，下次直接显示；服务端先回存下的，再去问会话。不写“默认”（kumo，2026-11-16）：agent 那一行写它会用的模型（`Claude · Opus 5.5`），点这一行（鼠标）就用它加入；悬停打开子菜单，那个模型排第一、勾着，点一个模型就用它加入。agent 没说默认是哪个时，用这台机器上这种 agent 上次跑的模型；都不知道就只写 agent 的名字。思考强度在子菜单底下，dsh 的模式（预设）排在模型下面。手机上点那一行打开子菜单。没有“添加”键。
