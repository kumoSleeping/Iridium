# 频道

频道是人和 agent 说话的地方，有自己的 ID 和记录，可以没有 agent。会话是一个托管 agent 的私有上下文，也就是 agent 用户 `agent:<会话ID>`，不属于任何频道。用户定的（2026-11-13，取代 11-12 的“频道就是最初那个会话”）。代码：`internal/channel`（记录、成员）、`internal/deliver`（叫起谁）、`internal/ctx/strategy`、`internal/ctx/assemble`、`internal/prompts`（给 agent 的上下文）、`internal/activity`（活动）、`internal/search`（搜索）、`internal/server/channels.go`（接口、路由）。

- 资料卡、角色、记忆见本文“资料”“角色”“记忆”“agent 知道的自己”。
- 每个会话有一个自己的频道，ID 就是会话 ID：agent 在回合里说的话直接进这个频道（直出）。没人改过成员时，它的成员是所有登录加这个 agent，和以前的会话完全一样。
- 会话可以订阅别的频道（`channel_members` 一行：收、发、已读位置）。在那里它只看到说出来的话。agent 写的话发到最近一次叫它的频道，和聊天一样：谁在哪里叫它，就在哪里回（kumo，2026-11-17，取代回合结束时替它补说最后一句）。工具调用和输出留在自己的频道里。`ir api message.create` 用来去别的频道说话。
- 无 agent 的频道（`channels` 表一行）：`channel.create` 不带 `_data.agent`。列在它的文件夹里（`Session.bare`），里面的 agent 都是订阅来的。
- 每个会话在侧栏只有一行。

## 记录

- 频道只记“说出来的话”：人说的、agent 说的、提问、报错、Iridium 自己的一行。每条一个编号，从 1 起，不重用；Satori 的 `message.id` 就是这个编号（`#12`）。
- agent 的思考和工具调用不进频道，留在它自己的记录里：`POST /v1/internal/block.list`、`block.get`（`docs/satori.md`“记录”）。
- 人的话在发送时写进频道（引用是输入的 ID）；agent 用 `ir` 发的、在被叫起的频道里写的也在发送时写，记成 agent 的话（`said`，`_data.sent`），不是人的。agent 的话从它的记录读进来（`Sync`，读到哪一行记在 `channel_sync`）；记录还没写到时先按听到的写，记录跟上后认作同一条。
- 以前的会话：频道第一次被读或写时，把整份记录读进来。读进来的不发事件。
- 终端里直接对 agent 打的话，读记录时补进频道，作者是 `terminal`。

## 成员

- agent 是 `agent:<会话ID>`。人有三种写法：`*`（所有应用的所有登录）、`应用/*`（一个应用的全部登录）、`应用/登录`。
- 人：2026-11-13 起新建的频道默认是面板的登录和 Iridium 的（`ir_web/*`、`local/*`），不带 Bot；建它的应用自己也在。新建页里可改（`channel.create` 的 `_data.members.people`）。之前的、没选过的频道是 `*`。选了人以后，没被选进来的仍然在侧栏看到、能读，但不能发消息、不能答提问和审批、不能停 agent、不能改成员（403）。Iridium（`local`）始终在里面；频道里的 agent 也在。群里任何人都能改成员（`PUT …/people`），改的人自己留在里面。agent 的 `ir` 不能改人、不能移出成员；`DELETE …/members/{member}` 只收 `agent:`。改 agent 的称呼要有用那个会话的权限。
- agent 的 `user.name` 是它现在用什么跑的（`Claude Opus 5.5 High`，给人看）；给 agent 的频道上下文和成员接口只写 agent 种类、模型 ID 和思考强度（`agent claude, model claude-opus-5-5, effort high`），不写模型名（kumo，2026-11-24）。`nick` 是叫它的名字：字母、数字、`_`、`-`，至多 32 个。称呼是会话的（`agent_nicks`），整个 Iridium 里唯一（不分大小写），在哪个频道都一样；第一次进有别的 agent 的频道时自动起（`claude`、`claude2`）。`@` 只认 `nick`；Satori 的 `<at id="agent:<会话>"/>` 等同 `@nick`。
- 每个 agent 在每个频道有自己的 `on`（见“唤醒”）。频道自己的 agent 默认是建会话的那一方说的话（2026-11-23 前建的会话是 `["*"]` 迁来的“全体成员”），邀请和拉起的默认 `[]`（只有被 @）。
- 一个频道至多 8 个邀请的 agent，拉起的（`spawned` 的 `by` 是频道里的 agent）不占这 8 个；连同拉起的至多 32 个（加入时逐个数，同时加入不会超）。
- 邀请：`POST …/members`，`session` 给已有的会话（要能用它），否则新开一个会话再订阅（`agent`、`model`…，`cwd`、`machine` 不给就是频道的文件夹）。新开的是为频道开的：侧栏不列，从频道顶栏的成员键进去，跳转框能搜到（kumo，2026-11-15）；移出后照常列在它的文件夹。邀请时可带 `text`：它进来后由邀请者在频道里说一句“@称呼 text”叫起它，它的回话照常说在频道里（agent 拉人一起干活就这样做：先邀请，再 @，kumo，2026-11-16）；带了 `text` 就不打招呼。页面上邀请的 agent（`greet`）进来后先说一句：Iridium 给它一回合“X 邀请你加入了这个频道，打个招呼，说说你是谁”，它的话照常说在频道里；`ir` 和 agent 邀请的不说（kumo，2026-11-16）。别人的“在干活”只在回合里（`running`、`compacting`）画，进程启动（`starting`）不画，免得头像闪一下就没了。`Session.spawned {by, channel}` 记谁拉起的（会话）和在哪拉起的（频道）。别的机器上的会话也能邀请。
- 拉起（kumo，2026-11-15）：会话里 `ir new` 开的，就是邀请进拉起者当前所在的频道：它正在为哪个频道干活（被那个频道叫起，`calls:`）就进那个，否则进它自己的频道。新会话记成 `spawned`、`on` 是 `[]`，和邀请新开的一样；`launcher` 只记谁开的，不再挂在谁下面。拉起者归档，它拉起的一起归档、一起恢复。拉起时没给称呼（也不是角色），用 `data.name` 去掉标点空格当称呼；都没有时是临时称呼“种类名-会话 ID 的 4 位十六进制”（`Claude-b134`、`DeepSeek-c54b`，重了多取几位），不再是 claude2（kumo，2026-11-16）。用着临时称呼的 agent 第一次被频道叫起，先被要求给自己起个称呼（`ir api PATCH internal/self nick=…`）再回答，改名照常在频道里记一行；没有 `ir` 的不要求。拉起时的第一句话（`_data.text`）不直接进它自己的会话，而是加入后在频道里作为拉起者的话叫它（`#n` 加频道上下文），它的回答说在频道里（kumo，2026-11-16）。不在频道里干活的会话（人的 `ir`、页面）照旧。提示词（kumo，2026-11-16）：系统提示和“Helpers”教 agent 在群里再要一个 agent 就邀请（带称呼和 `text`）再 @，`channel.create` 只开群外的会话；`--wait` 只在它自己的帮助里说清楚：占着自己的回合等对方回合结束，只用于群外替自己干活的会话，群里的 agent 说的话群里已有、回它的话会叫醒它，不用等。
- 移出：确认卡上是“移出并归档”（主键）和“仅移出”；为这个频道开的会话（`spawned` 是这个频道）默认移出并归档，它拉起的会话一并归档，卡上写明几个；不是为它开的（别处的会话被 `ir` 拉进来的）只有“移出”，不给归档（otae，2026-11-23）。仅移出只是退订，会话照旧。频道自己的 agent 移不出。
- 清空会话（`/clear`）：新会话接替旧的。旧会话订阅的频道、称呼、头像、资料、角色、记忆、`spawned`，和它自己频道的成员，都转给新会话，并记下新会话是从哪个会话接下来的；旧会话归档，不再在任何频道里。
- 订阅来的 agent 的会话归档了：不叫起，不占名额；恢复后照旧（选的是路由时跳过，不退订）。
- 建会话时可以一次配好：`channel.create` 的 `_data.members {agents, people, nick, on}`；第一句话在成员都到齐后才说，点到谁就给谁。其中一个 agent 起不来（kumo，2026-11-18）：频道照常建好、照常回答，频道里 Iridium 写一行“称呼（电脑） 未加入：原因”；不再回错误（那样页面留在原处，每点一次“开始”多建一个频道）。
- 会话列表里：`Session.agents` 是它的频道里的全部 agent（两个以上时；无 agent 的频道一个也列），`Session.in` 是它订阅的频道。
- 接口见 `docs/api.md`“频道”。agent 自己也能加：`ir api POST internal/channels/self/members agent=codex`。

## 提问（kumo，2026-11-15）

- 频道里的 agent（自己的、订阅来的、拉起的）的提问、审批、计划都进这个频道；一个 agent 在几个频道里，几个频道都进。
- 频道页输入框上方排成一队：按提出的先后，最早的在前面展开，其余收成一行“还有 N 个”。每条带提问者的头像和称呼，点头像进它的会话。
- 频道里能答提问的人（见“成员”）和频道里的应用都能答，先答的算；答了或撤了，各处一起结束。
- 频道记一条（`kind` 是 `ask`），所有成员的未读都加一；应用收到 `message-created`（`_data.kind` 是 `ask`），结束时 `message-updated`。没有指定谁来答：全量推给频道里的人和应用。
- 报错也一样：agent 的报错进它自己的频道和它所在的每个频道（`_data.kind` 是 `error`）。

## 撤回（kumo，2026-11-21）

- 能在频道里发话的成员（人、应用、agent 一样）都能撤回频道里任何一条话（人的、agent 的、脚本的），不限时间：Satori 的 `message.delete`，`message_id` 是编号。提问和 Iridium 自己的行不能撤。
- 撤回后所有人那里都没有了：内容、表情、指向它的“有人 @ 我”标记一起去掉，搜索不到，`block.list` 里它那一块也不给（agent 自己的记录还在）；编号和出处（`ref`）留着，记录再读进来时不会重新出现。存在 `channel_recalls`（迁移 45）。
- 频道记一行 Iridium 自己的话“X 撤回了一条消息”（`event` 是 `recall`，`seq`、`member`、`by`），不算未读、不给 agent。发 `message-deleted`。侧栏那一行的最后一句重算；引用它的消息，引用框写“#n（已撤回）”。
- 还在 agent 队列里的副本撤下。已经给过的 agent，下次在这个频道被叫起时，频道上下文里有一行“这些编号撤回了”（`channel.context.recalled`）。只告诉 agent 用法：`ir api help message.delete`，系统提示里不提。
- 网页：消息右键（长按）菜单最后一项“撤回”，按一次变红“确认撤回”，再按才撤。单 agent 的会话也有（它的频道也是频道）。

## 表情（kumo，2026-11-21）

- 任何能发话的成员都能给频道里的话贴表情：Satori 的 `reaction.create`、`reaction.delete`、`reaction.list`、`reaction.clear`，事件 `reaction-added`、`reaction-removed`。只收一个 Unicode 表情。存在 `channel_reactions`（迁移 45，每人每个表情一条）。撤回的消息表情一起去掉。
- 给 agent：表情按 `on` 给（不按点名）：订阅了贴表情那一方的话（不带 `words`），就叫起它，它收到一行“#n [谁 reacted 👍 to: 原话开头]”（`channel.reaction`），后面照常是频道上下文；单 agent 的会话只给这一行。agent 贴的只给接收集里有 `agent:<它>` 的，算进连续叫起的 8 次；自己贴的不给自己。撤下不叫起谁。被表情叫起后什么也没说，不记“未发话”。
- 给 agent 的频道说明里有一句怎么贴（`ir api reaction.create channel_id=… message_id=N emoji=👍`），这条命令手动审批下也不弹审批（`session.reactsOnly`）。
- 网页：每条消息下面一排表情（表情和人数，自己贴过的加深）；按表情是贴上或撤下自己的，按人数（或长按、右键）弹出谁贴的。消息右键菜单最下面一行是最近用过的 5 个表情（记在本浏览器，开始是一组常用的），行尾一个笑脸加号的图标是“更多”，二级菜单里是内置的常用表情表，分组（kumo，2026-11-25：原来最上面两行加一行“更多”，并成最下面一行）。

## 频道里的事

成员变了，频道里记一行 Iridium 自己的话（`kind` 是 `note`），文字给只认字的应用看，消息的 `_data.event` 给页面按自己的语言说：`recall`（`seq` 被 `by` 撤回，见“撤回”）、`join`（agent 加入：`member`、`nick`、`name`）、`leave`、`rename`（`from` 旧名、`nick` 新名）、`on`（`on` 是新的唤醒；2026-11-23 前是 `recv`，`recv` 是接收集）、`people`（`added`、`removed`、`everyone`）、`script`（`name`；`what`：`add`、`remove`、`enabled`、`disabled`，或改了的字段；改名时 `from` 旧名）、`undelivered`（`seq` 没送到 `nick`）、`stopped`（`seq` 没转交）、`silent`（`nick` 被 `seq` 叫起，回合结束时没在频道发话；回合因出错结束时 `reason` 写原因：余额不足、认证失败、请求太频繁，或错误的第一行，文字里接在“未在频道发话：”后面，kumo，2026-11-15）；`by` 是谁做的。建会话时一并配好的成员不记。这些行不进给 agent 的上下文。

## 叫起谁（两个以上 agent，或无 agent 的频道）

- 点了名（`@nick`）的消息只叫起点到的 agent；没点名，叫起 `on` 命中它的 agent（见“唤醒”）。人和 agent 的话同一条规则。只有一个 agent 的会话也一样（kumo，2026-11-23：以前单 agent 时不看接收集）。
- `@全体成员`、`@全体Agent`：叫起频道里所有 agent（发话的除外），和每个都点了名一样；Satori 里是 `<at type="all"/>`、`<at role="agent"/>`。这两个名字不能当称呼。
- 引用（Satori 的 `<quote id="编号"/>`）不叫起谁（kumo，2026-11-21，取代“引用 agent 的话就当点了它的名”）：叫起谁只看话里的 @。被叫起的 agent 收到的消息里，原话前写上引用的那条（编号、谁、头 200 字）。频道记下引用的编号（`_data.quote`，内容开头的 `<quote id/>`）。单 agent 的会话里，引用的话写成 `>` 引用行放在前面。没被叫起的，下次被叫到时在上下文里读到。网页上按“引用”同时在输入框开头写上 `@作者`（见“网页”）。
- agent 的话：点名照常算（频道自己的 agent 说的话直接算；订阅来的 agent 用 `ir` 发的、和回合结束时替它说的那句）。按 `on` 叫起只认回合的最后一句（kumo，2026-11-17）：中途说的、用 `ir` 发的，只叫起点到的。
- `@nick` 要独立成词，不在代码块、行内代码和引用行里。
- 给 agent 的说明里有一句：agent 之间只在需要对方回答时才 @，话说完了就不带 @ 回复，到此为止（防止来回不停）。
- 从人最后一次在这个频道说话算起，agent（和它们触发的命令、事件）连续互相叫起，到 30 次暂停（kumo，2026-11-26；此前 4 次、更早 8 次）；其中 agent 连续 4 个回合都没调用任何工具、只有对话（客套来回、原地打转），也暂停。点名和 `on` 一起算（按频道计，人一说话重新算，不带到别的频道）。暂停时不再叫起谁：频道里记一行“已连续协作 30 轮，已暂停 #n”或“已连续 4 轮只有对话，已暂停 #n”，带「继续」；`ir` 发的被拒（400）。频道里的人按「继续」（`POST internal/channels/{id}/continue {seq}`），计数从头算，那条照原样转交，每条只能继续一次。同一件事对同一个 agent 只叫起一次：消息叫起了它，同一条消息触发的命令再 @ 它不再叫起。
- 同一频道的 agent 可以停掉彼此当前的回合：`ir api POST internal/sessions/<昵称>/interrupt`（昵称前可带 @），用于对方明显在打转、跑偏或要做有害的事；提示词要求停后说一句为什么。
- 人要有用那个 agent 的权限才能点它；没有权限的人说话，订阅了他的那个 agent 不被叫起。agent 点 agent 不受限；脚本按最后改它的人（或 agent 的会话）的权限算。
- 订阅来的 agent 被叫起后（谁在哪个频道被叫起记在库里，`calls:<会话>`，重启不丢），它写的每一段话写出来就发进频道：中间的记成进度，回合最后一段记成回复（只有回复叫起接收集里的 agent，进度只叫点名的）。发到哪个频道：写这段话之前它已经收下的那些叫起里最近的一个（输入还在排队的、回合结束后才插进来的不算）；没有就只在自己的频道。先后按 Iridium 收到的顺序算：输入交给 agent 之前先发一条“收下”通知（`taken`），所以 agent 的回话一定排在它后面。同一段话从实时输出和记录里各读到一次时，只转一次。不去重：它再用 `ir` 往同一个频道发一遍，就是说了两次（kumo，2026-11-17）。每次叫起记着给它的那条输入：收下这条输入的回合结束才算数，别的回合结束时它还在排队就接着等。回合结束时什么也没说、回合被掐断（进程停了）、或重启期间回合已经结束：频道里记一行（`silent`）；它是另一个 agent 为这个频道拉起的，拉起者另收到一条通知。被另一个 agent 叫起、没什么要说的，不记这一行（只有人叫它、或回合出错时才记）；agent 也可以用 `ir api POST internal/sessions/self/interrupt` 停掉自己这一回合，叫它的那些就算答过了，不记这一行（kumo，2026-11-16）。页面上它的“在干活”框先淡出再收起（`.g-depart`），不是一下消失。agent 在群里说的话给别的 agent 时标的是它的称呼（`[@称呼]`），不是它会话的 ID；会话标题去掉这个标签和 `<channel-context>`。“加入了频道”由 agent 拉的记成那个 agent 的称呼。
- 后台任务（kumo，2026-11-26）：收下叫起的回合结束时，agent 自己的后台任务（子代理、后台命令）还在跑，这次叫起不关，记着它等的任务（`held`、`tasks`），期间不记 `silent`。任务结束后 agent 自己开的回合（没有输入）写的话发进这个频道，那个回合结束才关。几个频道各有任务在跑时，汇报发到任务已结束的那次叫起所在的频道。期间收下别的输入的回合照常：答新的叫起，自己会话里的话不进频道。任务没了而没有汇报回合（被停掉、进程停了），等 30 秒后关。重启后任务还在跑的接着等，已结束的按“重启期间回合已经结束”处理。agent 用 `interrupt` 停自己的回合不关这种叫起。没有任何叫起时，agent 自己开的回合写的话发进它被拉起的那个频道（只在这一个频道里时）。
- 以 `/` 开头的话：频道里某个脚本的命令（`/名字`）交给那个脚本，说进频道，不给 agent（见“命令”）；频道自己那个 agent 的命令（`/clear`、`/compact`、它握手时报的那些）才单独交给它，其余（`/home/x 坏了 @codex`）照常说进频道。
- 只有自己一个 agent 的会话和以前完全一样。

## 收和发

- 发话：`ir api message.create channel_id=<频道> content='正文'`：单引号里可以多行，shell 不解释其中任何字符，正文里的 `'` 写成 `'\''`（kumo，2026-11-15：不再有 `k=@-`，只留这一种写法）。在自己所在的频道里这样发话，手动审批下也不弹审批（`session.speaksOnly`：只认这一条命令：`channel_id`、`content`（或 `_data.text`）各一个，值不带引号，或在单引号里，或在不含 `$`、反引号、`\` 的双引号里；带别的参数、接别的命令照常问）。
- 别的会话的 agent（不是这个频道的成员）用 `ir` 发进来的话，记成那个 agent 说的（作者 `agent:<会话>`，`_data.session`），不是它那一回合代表的登录的；叫起谁照旧，和一封信一样（kumo，2026-11-21：这样的话显示成了他说的）。
- 发送检查：agent 用 `ir` 发话时，它没读过的消息随回答一起给它（`_data.unseen`，`ir` 直接印出来），已读位置前移。没读过的超过 12 条，或其中有点到它的：不发，回 409 `behind`，正文是这些消息；读完再发。

## 给 agent 的上下文

被叫起的 agent 收到一条消息：`#编号: 原话`，后面一个 `<channel-context>` 块。

- 写法（kumo，2026-11-26）：固定说明在前、变的在后。临时称呼的先一段改名要求；然后 `Channel: … | You: …`、`Agents:` 每个一行（种类、模型、强度、唤醒、位置）、`Rules:`、`Commands:`（有 `ir` 才有）；再是没读过的消息、资料变化、撤回、各 agent 做了什么。频道会话的系统提示不再另有一份说明，标题规则人人都给。
- 它是谁、频道里有哪些 agent、怎么叫别的 agent。订阅来的 agent 另外被告知这是哪个频道（名字和 ID）、它写的话边写边说进频道，不要再用 `ir` 发一遍；`ir api message.create` 只用来去别的频道说话。
- 它上次读过之后的消息里的附件只给名字（“（附件：a.png、b.pdf）”），不给路径、不给图片，免得没叫它的 agent 去读；叫它的那条照旧给全（路径和图片），要看早先的用 `message.get`（kumo，2026-11-16）。人发在频道里的附件跟着消息存下（`_data.files`），无 agent 的频道也能发。
- 它上次读过之后的消息：近的给原文（`#431 [谁 · 时间 · 做了什么]: 正文`），只在消息之间切；单条超过 2000 字截断，写明怎么取全文。更早的按回合一行（谁问、头几个字、谁答），至多 30 个回合；再早的只写数量。总量约 24KB（`strategy.Default`）。
- 位置（kumo，2026-11-18）：频道里有 agent 不在频道的文件夹（别的文件夹，或别的电脑）时，说明里写频道的文件夹（`host:/home/k/ir`），不在的 agent 后面写 `at 电脑:路径`；被叫起的那个自己不在时，另告诉它活在那边干、话在频道里读，自己的文件要带位置写。都在频道文件夹时不写。位置变了算说明变了，重给。
- 每个 agent 在这段时间里做了什么的合计，和改过的文件。
- 怎么查更多：`ir api message.list channel_id=<频道>`（自己的频道是 `self`）、`_data.q`、`message.get`。没有 `ir` 的没有这一行。
- 每个 agent 一个已读位置（`channel_members.seen`），给过就往前移。同一个 agent 一次只给一条。
- 增量（2026-11-13）：频道的固定说明（它是谁、频道、有哪些 agent、怎么回答，加上怎么查更多）只在这些时候给：第一次被这个频道叫起；说明变了（agent 换了、频道改名、提示改了，按说明全文的哈希比）；上次给过之后它压缩过上下文（读它的记录，看有没有压缩那一行）。别的时候只给一行“仍在「频道」里”（订阅来的）或什么都不给（频道自己的 agent）。注入单记着 `static`（说明的哈希）、`full`（这次给没给）、`line`（当时它的记录到哪）。清空会话是换了新会话，自然从头给。

## 分层和可追溯

| 层 | 在哪 | 管什么 |
| --- | --- | --- |
| 文字 | `internal/prompts/texts/*.md` | 给 agent 的每个固定的字，一段一个文件，文件名是 ID |
| 策略 | `internal/ctx/strategy`、`assemble/policy.go`、`internal/deliver` | 纯函数：给什么、给谁；不产生字 |
| 组装 | `internal/ctx/assemble` | 策略的结果加文字，成一份注入（`Injection`），每段记着出处 |
| 投递 | `internal/agent/*`、`session` | 只收 `Injection`，不改内容 |

每次给 agent 的东西留一份注入单（`injections` 表，每个会话留最近 200 份）：用了哪些片段、片段的哈希、填进去的值、引用了哪些消息，还有它实际收到的全文（`text`；kumo，2026-11-16，原来不存正文，看不出它收到了什么）。记的不只是频道叫它的那条：每次起进程时的系统提示、写给它的每一行（频道消息连同发送者标签、私下发来的消息、Iridium 自己的恢复提示），和它的 `ir` 在频道里得到的回执（“你上次读过之后说了……”、发送被拒）。没有单独的“注入记录”页（kumo，2026-11-26）：频道成员的 agent 的会话记录里，每条给它的消息照注入单的全文原封不动地画（按输入 id 对上；发送者标签、`#n: ` 开头、整个 `<channel-context>`、后面附的行都在），系统提示原文放在会话最上面；注入单已经不在的照会话记录的原文。`<channel-context>` 画成“频道上下文”一块，按原文顺序分说明、新消息（转发的样子，一行一条）、工作、命令，右上角“原文”看整块原文，不折叠。只有收到过频道回合（`turn-prefix`）的会话这样画，一个人和一个 agent 的私聊照旧。`GET /v1/internal/sessions/{id}/injections`（留着的全部）。

## 活动

读 agent 的记录时数它的工具调用（`internal/activity`），挂在它下一句话上：bash 几次、失败几次、各是什么程序开头的；读了几次；网页搜索和抓取；子 agent；用编辑工具改的文件和增删行数。不记命令原文、搜索词和结果。shell 命令改的文件数不到。别的机器上的 agent 改的文件写成 `机器名:路径`。消息内容后面跟 `<iridium:activity>`，文件路径只给网页和 Iridium。

## 搜索

`message.list` 的 `_data.q`：有这些词的消息，最近的若干条。索引是 SQLite 的 FTS5；中文按单字和相邻两字切，不用词典。索引的是正文，加上 agent 改过的文件路径和跑过的程序名。

## 已读

- 每个成员在每个频道有一个已读位置（读到第几条）。人：页面看到哪条就 `POST …/read {seq}`，按登录记（`channel_reads`），只进不退。agent：给过它的最后一条（`channel_members.seen`）。只有它一个 agent 的会话：被唤醒时连同攒下的一起给它，算全读；多个 agent 时，频道自己的 agent 是给过它的和它自己说的最后一条里靠后的那条（点别人的话没给它）。
- `GET …/reads` 和携带状态 `reads:<频道>`：`ChannelReads {end, readers[]}`。某条消息谁读了：`seq` 不小于它的那些。

## 有人 @ 我（2026-11-16）

- 算点到一个登录的：消息里写了 `@它的名字`（规则同 `@nick`，名字里可以有空格和点，取最长的）或 Satori 的 `<at id="它的用户ID"/>`；`@全体成员`（`<at type="all"/>`，只算频道里的人）。引用它说的话不算（kumo，2026-11-21）。人说的、agent 说的（直出、用 `ir` 发、替它说的）都算；自己的话不算自己。单 agent 的会话也算。应用（Bot）没有。
- 每个登录在每个频道记一条：第一条点到它、它还没读的消息（`channel_ats`：`seq`、`everyone`）。先有 `@全体成员` 再被单独点到，`everyone` 去掉，位置不变。消息写进频道时就记，没发出去的撤掉。
- 已读位置过了这条（`POST …/read`）就清掉；读到频道末尾，一并清掉。网页打开那个会话就上报读到这条（单 agent 的会话也报）。
- 页面：携带状态 `ats`（每条连接只带自己的），`GET /v1/internal/ats`。跨设备一致。
- 侧栏那一行第二行前面加红字“[@我]”，只是全体的是“[@全体成员]”，后面照常是“谁: 最后一句”。
- 有标记的频道：免打扰时未读角标也是红的，标题和应用角标把它算进去。
- 推送：Web Push 已删（2026-11-26），点到谁只记标记、算未读，不推。
- 只记第一条：读到它就清掉，它之后、还没读到的点名不再有标记。

## 资料（kumo，2026-11-16）

- 人、agent、应用、频道各有一张资料卡：称呼、头像（agent 另有设定）。没有介绍（kumo，2026-11-24：实际用下来没用，全部删掉；库里的列留着不读）。没有背景（kumo，2026-11-25）：卡顶上那一条是头像放大模糊后的颜色，不能改；接口不收 `background`，库里的列和以前存的 `b:<键>` 图留着不读，删资料时一并删掉；以前“改了介绍、背景”的频道事件，这两项不再显示，只剩它们的整条不显示。agent 的称呼就是 `nick`，频道的是频道名；人的称呼和头像仍是登录自己的（资料页）。
- 会话自己的频道也有自己的头像，和它那个 agent 的分开；频道没设头像时显示 agent 的（kumo，2026-11-16）；有几个 agent 时没设头像，侧栏、标题前、频道卡显示前两个 agent 各自的头像（左上、右下叠着），不是它们的图标（用户，2026-11-16）。
- 头像可以是图片（PNG、JPEG、WebP，至多 2 MB；页面先缩小压缩再发，不让用户自己压），也可以是一个表情或一个颜色（`#2f4f6f`）：服务端把它画成 SVG，从同一个地址给出，页面不用区分。
- 设定（otae，2026-11-21）：只有 agent 有，可选，默认空，至多 5000 字（otae，2026-11-22，原为 2000）。写它的行为方式、语气、做事的规矩，只给它自己：非空时原样接在它系统提示里称呼的后面，不加引导语；不进频道的固定说明，不告诉别的 agent。人在资料卡里照样看得到、改得了。
- 存在 `profiles` 表：agent 和频道是 `c:<ID>`，人和应用是 `u:<ID>`，角色是 `r:<ID>`。
- 谁能改：频道里的任何成员（人、agent）都能改这个频道和里面任何 agent 的资料；人和应用还要有用那个会话的权限。人的资料只有本人能改。
- 接口：`GET`、`PATCH /v1/internal/self`（自己）；`GET`、`PATCH /v1/internal/members/{称呼|会话|登录名}`；`GET /v1/internal/channels/{id}/profile`、`PATCH /v1/internal/channels/{id}`（`here` 是 agent 正在为之干活的频道）。`ir api help profile`。
- 开会话时一并给：`channel.create` 的 `_data.nick`、`_data.intro`、`_data.persona`、`_data.avatar`、`_data.background`；邀请同理。agent 开会话没给资料时，`ir` 在标准错误里提示一句。
- 改了资料，频道里记一行灰字（`event.type` 是 `profile`，`what` 列出改了哪几项），不计未读；同一个人接连改同一张卡只留一行。改称呼仍是 `rename`。
- 告诉 agent：不叫起谁。每个 agent 在每个频道记着上次告诉它的资料（`profile_told`），下次被叫起时和现在的比，不同的写在 `<channel-context>` 里“Profiles changed”一节：改名、头像或背景换了。它自己改的不再告诉它。别人改了它的设定，只告诉它自己，写出新的全文。频道的固定说明不再因为改名重给：说明的键只看片段文字、是哪个频道、有哪些 agent。

## 角色（kumo，2026-11-16）

- 角色是存下来用来开会话的一张卡：称呼、设定、头像，加上 agent 和默认模型，dsh 的角色还有默认预设（`roles` 表；别的 agent 没有预设，角色卡上也没有这一项）。平常开的会话不是角色；在“编辑资料”里点“存为角色”才是（`POST /v1/internal/roles {session}`），或在设置的“角色”页新建（`POST /v1/internal/roles {name, agent}`）。角色没有介绍（otae，2026-11-23：它是谁由设定说，给别人看的介绍由它的会话自己写）：以角色开的会话介绍是空的，进频道打招呼时自己写。
- 不带思考强度（otae，2026-11-21）：强度看任务，不看是谁。以角色开会话、邀请角色时当场选，和拉普通 agent 一样；不选就是 agent 或模型自己的默认，不记上次的。也不带审批模式：以角色开的会话和别的会话一样用默认的（otae，2026-11-22）。
- agent 建好不能改，要换就新建一个角色。默认模型（dsh 的还有预设）开会话时可以临时换，只管这一次；长期改只在设置的“角色”页。预设可能带 dsh 的人格（`@deepseek-ai/dsh-persona`），所以算在角色里（otae，2026-11-22）。
- 从 dsh 人格导入（otae，2026-11-22，在上面几条之后做）：Desktop 装了带人格的包（OMD）时，我们的 dsh 插件把它的人格库（名字、简介、拼好的正文）报给 Iridium（`agent.personas`，协议见 `docs/exec.md`）。新建角色、编辑设定时可以选一个导入：正文拼成设定，称呼空着的用它的名字。导入是复制，之后和 Desktop 那边无关，哪种 agent 的角色都能用。Iridium 起的 dsh 会话设定不为空时，dsh 里别的人格对这个会话让位，不叠两份；设定为空时用 Desktop 此刻选的人格。
- 以角色开会话（`channel.create` 的 `_data.role`，邀请的 `role`）：卡抄一份给会话，称呼用角色名，被占用时后面加“-会话 ID 的 4 位十六进制”（`克劳德大小姐-e444`，重了多取几位；不算临时称呼，不要求改名；kumo，2026-11-17，不再是 `克劳德大小姐2`）；会话里之后改的资料不回写角色，“更新角色”才回写（`PATCH /v1/internal/roles/{id} {session}`），只写回设定、头像，不碰模型和预设（otae，2026-11-21），也不碰称呼（会话的称呼可能带着会话 ID 的几位）；从会话存角色、更新角色时，头像是会话显示的那张：它自己的，没有就是它模型的；没有自己头像的角色显示它模型的（kumo，2026-11-17）。“移出角色”是 `DELETE /v1/internal/sessions/{id}/role`。
- 同一个角色可以同时开几个会话。

## 记忆（kumo，2026-11-16）

- agent 自己写的短句，一条至多 300 字：`ir api internal/remember text='…'`；`GET /v1/internal/memory` 列出，`DELETE /v1/internal/memory/{id}` 删。只有 agent 主动写，Iridium 不替它总结。
- 归属：会话是某个角色的，记忆就是角色的，这个角色的所有会话共用；否则是会话的，清空后转给接替的会话，存为角色时一并带过去。
- 每条记着出处：哪个会话写的、当时为哪个频道干活、那个频道到第几条、什么时候。
- 何时写（写在系统提示里）：用户要求记住、一件大事做完、用户明显在意、发现明确的偏好、遇到值得下次知道的严重问题；一回合至多一次，放在回合末尾，统筹成一条，写明出处。优先用它，而不是 agent 自带的记忆文件。
- 人在“编辑资料”（卡里原地切换的编辑）里看和删。

## agent 知道的自己（kumo，2026-11-16）

每次 agent 进程启动时，系统提示末尾带一段（`assemble.Self`，约 200–600 token），全部直接取自记录，没有总结：

- 称呼；有设定的，原样接在后面。
- 在哪（kumo，2026-11-18，系统提示 `## Runtime` 的第一行）：`Host:` 或 `Computer:`，系统、文件夹；在别的电脑上时再写路径怎么带电脑名、别的电脑的文件读不到。
- 它写下的记忆，最近 12 条，带日期和出处；更多的写明条数。
- 它所在的频道（至多 8 个，最近发过话的在前）：上次发话的日期、当时还有谁在说话、它那句的开头。
- 清空之前的上下文（至多 3 份）：何时清空、多少回合、第一句的开头、会话 ID。清空时记下上一份是哪个会话（`session_before`）。
- 四行用法（`## Collaboration & Memory` 一节；上面的记录在 `## Runtime`）：查记录、写记忆、改资料、找帮手（能用自家的子代理就先用自家的；要另一种 agent 或模型、要一个角色、要留在频道里让人对话的，才用 `ir` 开会话；kumo，2026-11-16）。日期只写到日，没有新的事时提示不变，不废缓存。

查记录的命令（只读，手动审批下不问，`session.looksUpOnly`；`remember` 也不问）：

| 命令 | 作用 |
| --- | --- |
| `ir api GET internal/self` | 自己的卡、所在频道、之前的上下文、记忆 |
| `ir api internal/recall q='词'` | 先搜记忆，再搜它所在的频道和清空前的上下文的消息；`all:=true` 搜它看得见的全部；每条带取全文的写法 |
| `ir api GET internal/members/<称呼>` | 一个成员：卡、同在的频道、最近说的话 |

只有一个 agent 的会话没有频道上下文，这一段是它知道资料和记忆的唯一途径；所以别人改了它的资料，它要到进程下次启动才知道。

## 元素

消息里 Markdown 和 Satori 的元素可以混着写（2026-11-13）：Markdown 没有的用 Satori 的（`<at>`），两边都有的随便用哪个（图片 `![](…)` 或 `<img src/>`）。Iridium 叫起谁时把 `<at>` 读成 `@称呼`（`satori.AtWords`），网页显示时把 Satori 元素换成 Markdown 再画（`web/src/chat/refs.ts` `fromSatori`）；代码里的照原样。

合并转发（Satori 的 `<message forward>`，kumo，2026-11-21）：里面每条是带 `<author>` 的 `<message>`，可以再套转发。`message.create` 顶层的 `<message forward>` 和它前后的话是同一条消息（别的顶层 `<message>` 仍各是一条），频道照原样记下。给 agent 时换成几行（`satori.ForwardWords`）：一行 `[聊天记录]`，下面每条“谁: 话”，多出的行和里面的转发缩进两格。网页画成卡片（见“网页”）。

## 记录里的转发

agent 自己的记录里，频道转给它的那条，`block.list` 给成 Satori 的合并转发：`<iridium:relay channel name seq/><message forward>…</message>`，转发里每条是一个带 `<author>` 的 `<message id="编号">`，是这次给它的那些消息，叫它的那条在最后；每条的字取自注入单全文里它那一行（按片段拆回，截断的带着“[…N more characters …]”），不再从频道重读。标准接口（Satori）只带转发和 `relay` 的几个属性；Iridium 自己的话（说明、`<channel-context>` 的各行）只在内部接口的注入单里（kumo，2026-11-26：两种接口分清）。只认 Satori 的客户端看到的就是一条合并转发。注入单已经不在、或拆不回的，转发里只有叫它的那条，照会话记录的原文。

## 读别的 agent 的记录

agent 的 `ir` 能读它看得见的任何会话的记录：只读，密钥照常打码。三层：

- 活动：频道消息后面的 `<iridium:activity>`（做了什么的计数、改的文件）。
- 提要：`POST /v1/internal/block.outline {channel_id, from?, to?, limit?}`，一回合一行：谁问的、头几个字，这回合做了什么（同活动），最后一句的头几个字，以及这回合在记录里从哪块到哪块。
- 全文：`block.list`、`block.get`。

## 指向

频道里 agent 的消息带出处（`message.list` 的 `_data`），网页展开和 agent 读取用同一份：`session` 是哪个会话；直出的话带 `block`（记录里的那一块）；用 `ir` 发的带 `from`、`to`（它被叫起之后到发话时，自己记录里的行号范围）。拿去 `block.outline`、`block.list` 读那一段。

## 私聊

`POST /v1/internal/dm {user}`：调用者和 `user`（一个登录的 Satori 用户 ID，Iridium 是 `local`）两个人的频道，回 `{channel}`。同样两个人永远是同一个（记在 `dm:<两人>`）；第一次建：无 agent，成员就是这两人，放在 Iridium 那台机器的家目录那个文件夹，名字“甲 · 乙”（2026-11-13）。只有这两个人看得到、读得到（不看文件夹范围；Iridium 不是其中之一时也看不到）；同样两人同时来开，得到的是同一个。还没做：侧栏单独一组。

## 头像

- 频道有头像。会话（它的 agent）的头像存在 `avatars` 表 `c:<ID>`；会话自己的频道作为频道的头像另存在 `g:<ID>`，`GET …/avatar?of=channel` 取，没有就是 agent 的；侧栏、标题栏、频道资料卡用这个。`PUT /v1/internal/channels/{id}/avatar`（图片本身，或 JSON `{avatar: base64}`；存成 128px）、`DELETE`、`GET`。频道里的成员（人、agent）都能改（kumo，2026-11-17：agent 用它换头像被拒）；频道自己的头像用资料的接口（`PATCH …/channels/{id}` 的 `avatar`，见“资料”）。
- 给会话换头像时同时记为它那个模型的头像（`m:<agent>:<model>`）：同模型、自己没头像的会话都用它，以后新开的也是。没指定模型或只指定了一族（Claude 的 `opus`）、没在跑的会话，模型是它上次跑的（用量记录里最后一回合的），不是空着或族名等它再跑（用户，2026-11-16：群里的 Claude、选了 opus 的会话显示成图标）。
- Satori 里 agent 用户的 `avatar` 就是这个地址；携带状态 `avatars` 是一个只增的数，只有头像变了才加一（它在每个头像的地址里，一加所有头像都重取）；称呼、介绍变了加的是 `cards`，资料卡按它重取（kumo，2026-11-16：给一个会话起名，侧栏所有头像都闪了一下）。头像换地址时先留着旧图，新图到了再换。
- 每张头像用自己的版本（kumo，2026-11-23：一张变了所有头像都重取，侧栏头像闪）：携带状态 `faces` 是 Iridium 托管的会话和频道各自头像的版本（`<ID>`，作为频道 `c:<ID>`；没有头像是空串，页面直接画图标不去取），按调用者看得到的频道过滤。页面用 `?v=<它的版本>` 取，版本对得上的回 `private, max-age=31536000, immutable`，不对或不带的照旧 `no-cache`。不在 `faces` 里的（Iridium 不托管、只是发现的会话）仍按 `avatars` 计数取。角色、背景、登录和应用的头像本来就带各自的版本，同样一年不变。会话里文件的缩略图地址带文件的修改时间（`?v=<毫秒>`），对得上同样一年不变。

## 唤醒（kumo，2026-11-23；2026-11-24 前叫“订阅事件”）

- 收到和唤醒分开：频道里的成员收到频道里的全部话，不用配置；没被唤醒时攒着，下次被唤醒时一起给它。唤醒只有两种：被 @（一定），和订阅事件命中。
- 每个成员身上有一个 `on`，每项是“什么时候”，可带“要它做什么”（`text`）：agent 的命中时唤醒它，命令（脚本）的命中时运行它。存在 `channel_members.triggers`、`channel_scripts.triggers`（JSON，`api.Trigger`）。只有一种写法（JSON），没有简写。
- `on` 是一个列表，每项一种，可带 `text`（要它做什么，唤醒时接在后面一行 `[woken: 什么时候] 要它做的`；命令不用）：
  - `message {from, words}`：频道里一条消息。`from`：`*`（全体成员，不含 agent）、`<应用>/*`、`<应用>/<登录>`、`agent:<会话>`（它回合的最后一句）；不写是谁都算（agent 只算回合的最后一句）。`words`：含其中之一（不分大小写），不写是任何话。点了名的消息只叫起点到的，不看订阅。
  - `command`：人发的 `/名字 参数`。
  - `cron`：`分 时 日 月 周`，主机时区；错过的不补。agent 被定时唤醒时，频道里先记一行“定时 09:00 → @称呼”。
  - `event`：`join`、`leave`（成员加入、移出：agent，或人被加入、移出）、`rename`、`wake`（谁的唤醒改了；旧名 `on`、`recv`、`script` 照读）、`error`（agent 出错）、`ask`（agent 提问、审批、计划）。事件说的是谁，就不唤醒谁。旧名 `recv`、`script` 读作 `on`，`people` 读作 `join`。
- 默认：新会话的 agent 是建它的那一方说的话：在网页或主机上建的是 `["ir_web/*","local/*"]`（一个人在哪个浏览器都算），别的应用建的是那个 `应用/登录`；agent 开的按它那一回合的登录算。邀请、拉起的是 `[]`。迁移 47 把接收集原样换成订阅：`["*", …]` 是一条 `message`，`[]` 是没有。
- 只有一个 agent 的会话：同样看订阅。没唤醒它的话照常说进它的频道（`_data.held`），下次唤醒它时写在前面一起给（“Said here since you were last woken…”）。它自己的命令（`/clear` 等）、别的会话的 agent 用 `ir` 写给它的，照旧直接给它。
- 改：`ir api PATCH internal/channels/<频道>/members/agent:<会话> on:='[…]'`（整份替换），频道里任何成员（人或 agent）都能改任何 agent 的，频道里记一行（`on` 事件）；命令的 `on` 在命令里改。表情按订阅给：有不带 `words` 的 `message` 订阅、`from` 里有贴表情的那一方的 agent。
- 保存时查订阅之间连成的圈。只由 agent 组成的圈（A 回合的最后一句唤醒 B，B 的又唤醒 A：谁也没叫谁，却互相叫起）不允许，从一开始就拒绝（kumo，2026-11-24）：改 `on`、带 `on` 邀请时回 422 `bad_on`，写出这个圈，什么都不改；agent 要叫另一个 agent，在话里 @ 它。经过命令的圈（命令里写着 @ 谁）照旧只在回答里 `warn` 一行一个，照样保存。别的（重复、与 @ 重叠）不提示：运行时同一件事只唤醒一次。
- 给 agent 的频道说明里每个 agent 后面写它的唤醒（“wakes on @; …”），有人设了订阅时附一句怎么改（`ir api help wake`）。
- 订阅事件（kumo，2026-11-24）：一条“什么时候 → 叫起谁、要它做什么”的规则，存在它要叫起的成员身上（agent 的 `on`、命令的 `on`）。网页上没有频道层的规则列表（kumo，2026-11-24：成员菜单里那组随勾选一会儿出现一会儿没有，谁说话唤醒谁也不算订阅事件，删了）：agent 的在它的“唤醒”和编辑资料里，成员菜单里只列频道的命令（有才列）。
- 网页（kumo，2026-11-24）：成员菜单的“唤醒”只勾选谁说话唤醒它（“被 @ 时”固定，右边写摘要）；完整的在 agent 的“编辑资料”里（资料卡只看，不放），“唤醒”一段，每条一句话（“被 @ 时”固定在第一行；“全体成员说话时”“说到「小克」时”“每天 09:00”“成员加入时 → 欢迎新人”，`→` 后是唤醒时给它的话），悬停出现 × 删除；＋ 选一种：成员说话、关键词、每天定时、事件，只填一项。成员菜单里没有它，网页上不编辑 `text`（交给接口和 agent）。频道里记的一行用同样的句子。

## 命令（原“脚本”，kumo，2026-11-17）

- 每个频道的 IR（Iridium 自己，频道里本来就有的成员）挂着这个频道的命令：一个名字（同称呼的规则）、一条命令行和 `on`。命令没有自己的头像和名字（kumo，2026-11-24）：它要么不说话，说话就以 Iridium 的名义（作者 `iridium`，`_data.script` 记是哪个命令），网页画成 Iridium 的头像。命令由 Bot 或 `ir` 在外面建，网页上不新建，只看、改、停、删。
- 触发（`on`，一个列表，每项一种）：
  - `message {from, words}`：频道里一条消息，发话者在 `from` 里（写法同“唤醒”；不写是谁都算，agent 只算回合最后一句），并含 `words` 之一（不分大小写；不写是任何话）。脚本说的话不触发脚本。
  - `command`：人发的 `/名字 参数`：说进频道，只交给这个脚本，不给 agent。
  - `cron`：`分 时 日 月 周`，按主机时区；错过的不补。
  - `event`：同“唤醒”。
- 运行：在主机上、频道的文件夹里跑 `/bin/sh -c`（Windows `cmd /C`），至多 60 秒；同一个脚本一次一个，跑着时再来的只留最新一个。标准输入是 JSON（`trigger`、`channel`、`script`、`message {seq, text, from, name}`、`args`、`event`），环境变量 `IR_TRIGGER`、`IR_TEXT`、`IR_FROM`、`IR_FROM_ID`、`IR_SEQ`、`IR_ARGS`、`IRIDIUM_SCRIPT`、`IRIDIUM_CHANNEL`。退出码 0 时，打印的内容以脚本的名义说进频道；里面的 `@称呼` 照常叫起 agent。脚本里的 `ir` 带 `IRIDIUM_SCRIPT`，`message.create` 以脚本的名义说在它自己的频道。
- 脚本说的话只叫起点到的 agent，算在上面的连续次数里（脚本自己不算空转）：由 agent 的话触发的脚本，接着那条的次数往下数；人说的话、定时触发的从头算。超过时不跑，频道里记一行“已暂停”。叫 Claude 按最后改它的人（或 agent 会话的发起者）的权限算，没有权限的记一行“未送达”。
- 频道的文件夹在别的电脑上（执行端）时暂不能加脚本。
- 谁能改：频道里的人和 agent 都能加、改、停用、删，频道里记一行（`script` 事件）。每个脚本记着谁建的、谁最后改的（`ScriptBy`：成员、名字；agent 的会话、称呼、模型、角色；时间）。只记通过接口的修改；脚本文件本身的改动不追踪。
- 运行记录：每个脚本留最近 50 次（`script_runs`：时间、用时、触发、触发它的消息、退出码、说成的消息、输出和错误，各截断）。
- 归档：会话归档后它频道的脚本都不跑（定时也不跑），恢复后接着跑；清空会话时脚本随频道交给接替的会话。
- 给 agent 的频道说明里列出启用的命令：名字、什么时候运行。`ir api help wake`。
- 网页上叫“命令”。“唤醒词”“定时提醒”两个模板删了（2026-11-23）：要按词、按时间唤醒 agent，给 agent 加订阅事件，不用打印 `@称呼` 的命令。
