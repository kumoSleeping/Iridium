# 前端设计规范

网页（`web/`）的设计规则。动效见 `web/src/motion.css`，文案见 `AGENTS.md`“UI copy”。

## 设置

- **二级页面，不用弹窗**：设置里点开的（应用管理里的网页、电脑组的 +）一律是二级页面：整页换进来（`g-slide`），左上角返回；不从那一行弹出 popover（kumo，2026-11-13，取代此前“应用详情是 popover”）。右键菜单仍是菜单。
- **新建放右上角**：一页里新建一项（邀请新登录等）用页头右侧的 +，只有图标，名字在悬停提示里，不另加按钮行和说明字（kumo，2026-11-13）。
- **不分二级类**：一个页面上的几项设置直接平铺成一列，不加“权限”“电脑”“能力”这类分组标题（kumo，2026-11-13）。只有成列的对象（登录、连接、应用）才加标题。
- **一行一项**：名字在左，开关或状态在右。状态只写状态（开、关、Linux x86_64），不写解释句。

## 列表

- **不分层级**：列表一律平铺，不缩进、不把一行挂在另一行下面（kumo，2026-11-13）。有关联的（同一台电脑上的几条连接）只排在一起。
- **对齐**：一列里有的行有操作键（改名的笔）、有的没有时，没有的那行留出同样大的空位，图标和键上下对齐（如电脑列表里的 Iridium 行）。
- **电脑列表**：主机一行写作 Iridium，头像用 Iridium 的标，第二行只写系统；右侧是它带的 agent 的图标，版本在悬停提示里。其他电脑第二行写最后在线和系统。不在这里放 token 用量（用量页有）和“可用本人 Claude”的标（用到时再申请）。

## 命令

- **一条命令一行**：给人复制去运行的命令写成一行（`&&` 或 `;` 连起来），显示也只占一行，超出部分横向滚动，不折行、不拆成多行（kumo，2026-11-13）。
- **复制键在上方**：复制键放在命令上方标题行的右侧；命令框不为按键留空位，文字占满整个框。
- **系统给全**：分系统的命令 macOS、Linux、Windows 都给，用一个切换选择，不漏系统。

## 复用

- **优先复用已有板块**：新页面、新一项先找现有的行、列表、卡片、头像，照用；没有合适的再新做，新做的要能被别处复用（kumo，2026-11-13）。
- **弹窗类型全局复用**：设置以外，从某处点开的弹窗一律是 popover：`PopSurface`（`web/src/ui.tsx`），从点开它的那一项展开（`g-unfold`），点外面或 Esc 关，不放关闭键；右键菜单、笔记、公开链接都是它。另外只有设置面板（`g-dialog`）和手机底部面板（`g-sheet`）。不为单个功能另做弹窗样式、定位或动画（kumo，2026-11-13）。

## 禁止（过度设计）

- **不加说明句**：打开开关、进入页面、切换状态之后，不另外显示一句教人下一步怎么做的话（如打开“配对”后出现“在要接入的电脑或程序上运行 ir join 或 ir pair”）（kumo，2026-11-13）。要用的东西直接给出来，放在用它的地方（如电脑组的 + 里给可复制的脚本）。
- **不加分组、标签、弹窗来“整理”几项内容**：见上面“设置”“复用”。
