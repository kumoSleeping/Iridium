# 前端设计规范

网页（`web/`）的设计规则。动效见 `web/src/motion.css` 和`docs/动画.md`，文案见 `AGENTS.md`“UI copy”。

## 布局

- **“手机”指竖屏布局，不指设备**（kumo，2026-11-25）：设计里说的手机、手机端、手机上，一律是竖屏布局（`web/src/ui.tsx` 的 `PHONE`：窗口窄于 520px，或窄于 768px 且竖长）。竖着的电脑窗口也是它，展开的折叠屏、横着的平板不是。只按这个分，不看是不是触屏、是不是手机（不用 `pointer: coarse` 决定布局和交互；它只管触控的点按尺寸）。

## 主页

- **主页的代码带**（kumo，2026-11-25）：竖屏下贴在输入框上方，图形最下面那条边站在输入框上沿；电脑上图形在输入框以上那块的正中：Ir 字母（彩虹渐变）或 agent 标志时是中间一条带子，左右渐隐；头像（图片）时只画头像，周围的字从头像边缘往外渐隐到没有，比带子里的图形小一点。没有 agent 时一律画 Ir 字母，设置里没有“主页”这一项；指到或加进 agent 后换成那个 agent 的头像。鼠标在代码带上：星星、圆环不加新字符，只把轮廓经过的原有字符染成彩虹色；按住不放一直迸发；在带子上方或下方点或按住，带子慢慢往那边放宽，最多到整个窗格；画出明显的折线（两个以上急转弯）时，代码停住、其余变暗，折线沿代码亮起，再有火箭沿折线越走越快，到头炸开（kumo，2026-11-25）。

## 称呼

- **不用“人”字**（kumo，2026-11-16）：页面、提示、通知、`ir` 的输出里都不出现“人”（“人”“所有人”“有人@我”“N 人”“本人”一股 AI 味）。说具体的：成员、全体成员、全部、自己、`[@我]`、直接写数字；分组标题不按“人 / Bot”分，直接列应用和登录。
- **不说“主机”**：跑 Iridium 的那台机器、在那台机器上直接用的登录（`local`）一律写作 Iridium，头像用 Iridium 的标；只有地方实在窄时写 Ir（kumo，2026-11-15）。电脑列表、成员、已读、私聊、新会话页都一样。
- **本机登录可以有自己的名字和头像**（kumo，2026-11-22）：桌面应用里坐在窗口前的就是本机登录，叫它 Iridium 和软件重名。设了名字或头像（`named`）就照普通登录画：名字、头像、能改；没设才是 Iridium 和它的标。电脑列表里那台机器一行仍是 Iridium。桌面应用第一次跑起本机服务器时，把系统账户的全名（太长或不合法用登录名）设成它的名字，已有的不改。

## 顶栏

- **成员菜单不列“人 / 所有人”，也不列“邀请”**（kumo，2026-11-16；2026-11-25 改）：只列 agent 和在干活的子代理。成员键右边一个 +（手机上没有这个键：成员菜单第一行右端一个小 +，按下推入同一个邀请页，返回回到成员；kumo + Neon，2026-11-26），按下就是添加面板：最上一行电脑（横向滚动、无滚动条，默认频道所在的那台），下面是模板和 agent 种类，再下面是人（网页、Bot）。模板只有头像和名字，按下即加，模型在加进来后的成员上改。换电脑时面板高度不变：那台没有的模板、种类留在原位画淡，不抽走。

- **连接信号**（kumo，2026-11-26；`link.tsx`）：小圆点加延迟，紧跟在名字后面。<500ms 绿，≤2000ms 黄，更慢或断开红，还没测到灰点不带字。数字 11px，`ms` 更小更淡、同一基线、不带空格（`● 91ms`）；断开写「断开」。指到或点它出提示：在线 · 91 ms、已断开。要刷新、要更新时照旧换成 ↻ 刷新、↑ 更新。

- **侧栏收起**（kumo，2026-11-26；`sideshut.ts`）：电脑上按侧栏左上角 [Ir] 收起（提示“收起侧边栏”），记在本机。收起后主区顶栏左边照手机的顺序：对话页 [Ir] 头像 名字 信号，主页 [Ir] Iridium 信号，按 [Ir] 展开；右边照旧，⋯ 里多一项“设置”。⌘K 先展开侧栏。
- **按 Iridium 回主页**（kumo，2026-11-26）：侧栏和收起后顶栏里的 Iridium（应用里自定的窗口名同样）按下回主页；应用里改名在右键。

## 设置

- **二级页面，不用弹窗**：设置里点开的（应用管理里的网页、电脑组的 +）一律是二级页面：整页换进来（`g-slide`），左上角返回；不从那一行弹出 popover（kumo，2026-11-13，取代此前“应用详情是 popover”）。右键菜单仍是菜单。
- **新建放右上角**：一页里新建一项（邀请新登录等）用页头右侧的 +，只有图标，名字在悬停提示里，不另加按钮行和说明字（kumo，2026-11-13）。
- **不分二级类**：一个页面上的几项设置直接平铺成一列，不加“权限”“电脑”“能力”这类分组标题（kumo，2026-11-13）。只有成列的对象（登录、连接、应用）才加标题。
- **一行一项**：名字在左，开关或状态在右。状态只写状态（开、关、Linux x86_64），不写解释句。

## 列表

- **一个登录的应用合成一行**（kumo，2026-11-16）：选成员、选 Bot 时，应用只有一个登录就只列应用一行，点一下就选上；有几个登录才在下面列各个登录。

- **行高一致**（kumo，2026-11-16）：同一个列表里每行行数相同、高度相同，不因为某一行内容多就折成两行、多出一行。一行放不下的，那一行横向滚动（同“命令”），不折行、不截掉。
- **不用“·”分隔**（kumo，2026-11-16）：并列的几项（状态、系统、数量）之间留空隔开，不用中间点。

- **不分层级**：列表一律平铺，不缩进、不把一行挂在另一行下面（kumo，2026-11-13）。有关联的（同一台电脑上的几条连接）只排在一起。
- **对齐**：一列里有的行有操作键（改名的笔）、有的没有时，没有的那行留出同样大的空位，图标和键上下对齐（如电脑列表里的 Iridium 行）。
- **电脑列表**：第一行只放名字。第二行：在线（绿点）或最后在线、系统，后面是它带的 agent 的图标，不写版本（kumo，2026-11-16：版本没用、占地方，把名字挤没了）；各项空开，放不下横向滚动（见上“行高一致”）。Iridium 那一行（见“称呼”）头像用 Iridium 的标，第二行只写系统和 agent。不在这里放 token 用量（用量页有）。

## 对话

- **给人的话不折**（kumo，2026-11-15）：agent 回人的话、点到人或全体成员的、提问、报错、自己的话，再长也不折。agent 之间的话（只点 agent 的、被 agent 叫起后的回话）超过 6 行折起：显示前 3 行、底部渐隐，下面一行“还有 N 行”，点了原地展开（高度滑开），“收起”再折回；头像和消息头不动。子代理交回的结果是它自己的一条消息，同样折着（`docs/channels.md`“网页”）。
- **读过的旧话折起**（kumo，2026-11-21，对已读的历史取代上一条）：已读、在最近 5 轮之前、超过 6 行的消息，不管给谁都默认折起，画法同上。任何消息都能从右键菜单折叠、展开，记在本浏览器。
- **折起只有一行说明**（kumo，2026-11-21）：折起的话下面只放“还有 N 行”，不再另放“看全文（N 字）”；没取全的话，展开时一并取全文。

## 布局与动画

规则、登记表和验收都在 `docs/动画.md`，改 `web/` 里会动的东西之前先读。要点：

- 动画必须有，只做一件事：让变化连续。排版永远是最终的样子。
- 对话只动滚动位置（`chat/stick.tsx`）：跟随时长出来的缓出追到底，变矮的当帧落下，不留空位；人翻上去后看到的不动（滚动锚定）；跟不跟随只由人的滚动决定。
- 行换顺序只有一个实现（`moves.ts` `useMoves`，侧栏和对话共用）；换位置的行放在同一个父节点下、key 不变。
- 走掉的行位置当帧让出、原处淡出；进场只改透明度。
- 组件里不新写 `animate()`、会改大小的过渡、改滚动位置（`web/test/movers.test.ts` 列着现有的每一处）。
- 位移和透明度的动画不加在高度不封顶的元素上（整列对话、整个列表）。
- 写完的话还是那个节点：草稿变成正式消息时沿用草稿的 key 和画法；进行中的回合，行只放一处（`Earlier` 的 `after`）。
- 已定稿的回合不重画（`chat.tsx` `turnBox`）；往回合里加新的输入，要加进 `stamp`。
- 对话里弹出的卡片停在打开时的位置（`PopSurface` 的 `still`）。
- 自己会重排的列表按节拍走（`usePaced`，侧栏）：顺序变化每 700ms 至多画一次。

### 对话里谁在哪（kumo，2026-11-24，取代此前按回合、按“在干活”的框排的做法；`docs/next/ui.md`）

- **对话里只有消息**：每一行是频道里一条有编号的消息，没有别的来源。没发消息的（子代理、被停掉的、会话状态）不占行。行表在 `chat/channel/log.ts`、`rows.ts`，组件只读它。
- **顺序是编号**；自己发的那条留在发出时气泡所在的位置，已画的不换位，重新打开后按编号。
- **同一个发送者连续几条共用一个头像**，中间有别人的消息就另起。
- **agent 正在写的话就是它的那条消息**，字逐步出来，高度只在最末一条增长。
- **干活是消息下面的一行**（`chat/work.tsx`）：任何状态下同一个高度；在干活时写第几步、工具名，右端是停止键；干完写几步、用时。没先说话就干活的，这条消息只有这一行。
- **工作键**（kumo + Neon，2026-11-26，取代浮着的工作条；`chat/channel/workkey.tsx`）：顶栏右边、成员键左边一个键，样子同成员键，没人回复中、没有后台任务时不在。收起时只有一种样子：在干活的 agent 头像叠放（电脑至多 3 个，手机 2 个）、人数、一个很淡的灰点慢呼吸；不用绿色，不转圈，宽度只随人数变。按下是顶栏的下拉面板（手机占满宽）：各 agent 一组，一行“回复中”或“后台 N 项”和计时（点了跳到它在写的消息，■ 停回合），下面任务各一行（子代理点了开它的只读记录，■ 停这一项）；停止键先变红“确认停止”，再按才停。刚结束的标“已完成”留 4 秒再淡出。成员菜单不再列“在干活的子代理”，它们是这里的任务。单 agent 的对话只在有后台任务时显示。消息里派到后台的那一步写“已派出 1 个子代理”“后台命令”，不写成做完。
- **详情要人点**：点那一行原地展开步骤列表，至多 8 行，超出在框里滚，在干活时展开的直接是 8 行高；点一步弹出输入、输出、diff。输入、输出、选中的和正在执行的那一步都不加深底色。

## 命令

- **一条命令一行**：给人复制去运行的命令写成一行（`&&` 或 `;` 连起来），显示也只占一行，超出部分横向滚动，不折行、不拆成多行（kumo，2026-11-13）。
- **复制键在上方**：复制键放在命令上方标题行的右侧；命令框不为按键留空位，文字占满整个框。
- **系统给全**：分系统的命令 macOS、Linux、Windows 都给，用一个切换选择，不漏系统。

## 复用

- **优先复用已有板块**：新页面、新一项先找现有的行、列表、卡片、头像，照用；没有合适的再新做，新做的要能被别处复用（kumo，2026-11-13）。
- **弹窗类型全局复用**：设置以外，从某处点开的弹窗一律是 popover：`PopSurface`（`web/src/ui.tsx`），从点开它的那一项展开（`g-unfold`），点外面或 Esc 关，不放关闭键；右键菜单、笔记都是它。另外只有设置面板（`g-dialog`）和手机底部面板（`g-sheet`）。不为单个功能另做弹窗样式、定位或动画（kumo，2026-11-13）。弹窗里换页用 `g-slide`。顶栏右边的弹窗（成员、+、⋯）在竖屏布局里没有二级弹窗：二级是同一面板里的下一页，顶上一行“‹ 名字”返回（`chat/channel/pages.tsx` 的 `Paged`/`Deeper`；kumo，2026-11-25）。翻页是推入（`g-page`）：下一页整页从右边推进来，同时下面那页往左推出去，返回反过来，两页都看得见，不淡入淡出（kumo，2026-11-25：旧的立刻没了、新的从透明淡入，像闪了一下）。

## 点击，不靠悬停

- **能看的、能做的都要点得到**：不设计“鼠标放上去才弹出”的弹窗、卡片或信息，手机没有悬停（kumo，2026-11-13）。头像、人数这类东西点了弹出 popover（见上面“复用”）。悬停的提示（`Tip`）只用来说一个按钮叫什么，按钮本身点了就有用；不用它、也不用 `title` 放别处看不到的内容。
- **点头像弹卡，不换页**（kumo，2026-11-16，严重）：任何头像（人、agent、应用、频道，包括标题前的频道头像、自己消息旁的头像）点了都是从它弹出资料卡（`PopSurface`），绝不直接整页换掉、跳到别的页面或设置。自己的头像弹的是别人看到的那张卡（同一个实现），不是左下角的设置。
- **编辑资料不是单独页面**（kumo，2026-11-16，重要）：卡上的“编辑资料”在同一个弹窗里原地换成编辑（`g-slide`），左上角返回卡；从菜单进的，从那一项（头像、成员键、“⋯”）弹出同样的编辑。人、agent、频道一样。
- **点头像就是换头像**（kumo，2026-11-16，大问题）：能改头像的地方，头像本身就是换头像的键，和设置里自己的头像同一套（`AvatarKey`：悬停盖一层相机，点了选图，`Crop` 裁成圆再存）。不另做一套换法；“头像”一行只放表情、颜色、去掉，它的上传也走同一个裁剪。
- **消息时间**：平常不显示，位置留着，显示时不顶开别的。电脑上鼠标移到那条消息上显示；手机上点那条消息所在位置的空白显示，再点收起（这是“不靠悬停”的做法：手机有自己的点法）。时间在名字的内侧：左边的消息在名字后，自己的在名字前（kumo，2026-11-16）。

## 不放 ×，要有动画

- **不放关闭键（×）**：本项目哪里都不放 ×（kumo，2026-11-13）。弹窗点外面或 Esc 关；输入框上方的引用这类东西按 Esc、空输入框里按退格、或点它本身去掉；从列表里拿掉一项在它的菜单里做。
- **出现、消失都要动画**：会把别的东西顶开的（输入框里多一行引用、附件），高度要过渡（`grid-rows-[0fr]`↔`[1fr]`，同附件那一行），不直接跳；消失时内容留到收完。

## 确认在原处

- **要确认的动作不另开弹窗**（kumo，2026-11-17）：菜单里的“清空”这类动作，第一次按下，那一项原地变红、字变成“确认清空”，菜单不关；再按一次才做。菜单关了就复原。
- **菜单项写 `sure`**（`sidebar.tsx` `MenuItem`）：删除电脑、删除登录、删除密钥都走它，不在那一行下面另开确认卡（最后一行的卡开在看不见的地方，像没点到；kumo，2026-11-19）。
- **行下面展开的块滚进视野**（权限、打开文件夹、角色的删除确认）：挂 `intoView`（`ui.tsx`）。
- **行上直接删的键用 `SureKey`**（垃圾桶，按一次变红、再按才删），不放 ×；长按菜单开在手指处（`useLongPress` 给出按下的点）。
- **菜单的锚点用 `usePointAnchor`**，长按开的菜单用 `lp.onContextMenu(e)` 的返回值挡掉随后的 `contextmenu`：不然菜单开着会换地方。

## 一样东西一个实现

- **入口可以有几处，实现只有一个**（kumo，2026-11-14）：换头像、查看会话这类动作在标题、资料卡、菜单里都可以有入口，但都调同一个函数，名字相同，行为相同（一处要确认，别处也要确认）。
- **展示的内容不重复画**（kumo，2026-11-13）：上下文和用量有消息头模型名后面那条小条，资料卡、右键菜单里不再画一份。资料卡放“它是谁”和“去哪”，菜单放对它做的事。
- 加新东西前先找它已经在哪；已经有了，就复用那一处的实现。
- **别处出现也给全，不做缩水版**（kumo，2026-11-16）：一个功能换个入口出现（头像菜单里的“模型”），就是原来那一份（输入框下的模型菜单：模型列表、强度条、UltraCode），不另做只列名字的简版、不拆成几项。

## 宽度

- **对话栏宽 1280px**（`--chat-w`，`web/src/styles.css`；kumo，2026-11-13，原来 760 两边留白太大；2026-11-25 从 960 再放宽，宽窗口两边空着浪费）：消息和输入框同宽，居中；窄屏照常占满。

## 侧栏状态与变更

（kumo + Neon，2026-11-26）侧栏是一直看着的，一次操作只许看到起点和终点。

- **一件事一个请求**：要后端改两样的（移出并归档），后端一步做完、只推一次列表（`DELETE …/members/{m}?archive=1`：先归档再移出）。前端不串两个请求，否则中间那一刻会被推到侧栏上（先出现再消失）。
- **改动立刻画、不回跳**：归档、恢复、改名、置顶、颜色、拖动排序一律走 `pending.ts`（`patchSessions`、`change`）：按下就画成改后的样子；之后推来的列表还没有这个改动的（发请求前就在路上的），照样盖上改动，直到推来的列表有了才撤；最多盖 10 秒。只有服务器拒绝时才画回原样并提示。不要自己 `setCarried("list")`。
- **新建 0ms 有反馈**：按“+”当下就在那个文件夹最上面放一行占位（`making`），点不开；建好后换成真的 id 并打开，没建成就拿掉（已提示）。占位和真行同一时刻只有一行。后端建频道不同步重算整张列表（`RefreshSoon`），立刻返回。
- **顶上的块首帧就有**：插在列表上面、会把下面整体推开的块（收藏），首帧读本机缓存，和列表一起出来，服务器的到了再静默对齐，不能晚一拍。

## 后到的不撑开

- **加载后才有的东西不能把已显示的内容顶开**（kumo，2026-11-13）：已读标记、计数、状态这类晚一步到的，要么一开始就留好位置，要么叠在本来就有的空白里（如消息之间的间距），出现时页面不跳。
- **弹窗、页面打开时就是完整的**（kumo，2026-11-16，又犯过：新建会话的“+”打开后“角色”一行才蹦出来，弹窗变高）：弹窗或页面要画的数据，在它打开之前就取好，不在它第一次画的时候才去取。做法，三条都要：
  1. 页面空闲时预取（`app.tsx` 里 `settled()` 之后，同 `prefetchRoles`、`agentsQ`）；
  2. 指针移到、按下、聚焦它的入口键时再预取一次（`onPointerEnter`、`onPointerDown`、`onFocus`，同“+”和成员键的 `prefetchChoices`）；
  3. 仍可能晚到的（别处刚新建的一项），放进会滑动高度的容器（`create.tsx` 的 `Tall`，或 `grid-rows-[0fr]↔[1fr]`），或者先留好位置，不让它一下顶开。
- **自查**：每加一个弹窗、一行、一个列表，问一句“它的数据从哪来、什么时候到”。是 `useQuery` 而且打开时才第一次请求的，就是这个错误。没有数据时不画（`length > 0 &&`）的行，数据一到就会蹦出来，同样要按上面处理。
- **有检查**：弹窗一律经 `ui.tsx` 的 `MenuPortal`、`PopoverPortal` 等（或 `OwnPopup`），`useQuery` 一律从 `api/query.ts` 引；弹窗里的查询第一次画时既没数据、也没在取，开发时控制台报错，测试里直接失败（`web/test/popdata.test.ts`）。预取用 `prefetch.ts` 的 `ahead`、`useAhead`；数据真要靠弹窗里输入的才有，写 `meta: { inside: true }`，并由设计先留好大小。
- **标记要带字**：只有一排小头像看不懂的，前面写上它是什么（如“已读”）。

## 不把能自动做的事交给用户

- **图片自己压缩**（kumo，2026-11-16）：选来的图片太大，页面自己缩小、压缩到能存的大小再发（`facepick.tsx` `shrink`），不报“图片超过 2 MB”让用户去处理。头像走裁剪，本来就只发 256px。同类的（格式转换、尺寸）一样由页面做。

## 禁止（过度设计）

- **不加说明句**：打开开关、进入页面、切换状态之后，不另外显示一句教人下一步怎么做的话（如打开“配对”后出现“在要接入的电脑或程序上运行 ir join 或 ir pair”）（kumo，2026-11-13）。要用的东西直接给出来，放在用它的地方（如电脑组的 + 里给可复制的脚本）。
- **不加分组、标签、弹窗来“整理”几项内容**：见上面“设置”“复用”。
