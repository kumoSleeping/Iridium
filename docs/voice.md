# 语音（`internal/voice`，`web/src/voice`）

组（guild，一个文件夹）带语音：看得见这个组的登录都能进它的房间，互相听见。平时 3–4 人，只传人声。没做的见最后。

一个组一个房间，不是一个会话一个（用户，2026-11-12；v0.2.11 是按会话）：会话会归档、会被 `/clear` 换成新的，房间不能跟着没；说话的人是围着这个文件夹的活，各自看着哪个会话都行。按 Satori 这是组里的一个语音频道（频道类型 3），`channel.list` 里还没列出来。以后 AI 进房间：从它所在的会话请进组的语音，它听到的转写进它自己的会话。

## 归属

- **核心的能力**，和别的接口一样在 `/v1/internal/` 下，凭 TOKEN 和登录进：网页的登录、别的应用的登录一视同仁，以后 AI 也作为一个登录进房间。agent 的 `ir` 不能进。
- **网页层（ir_web）不加东西**：公网地址、Passkey、Cookie 本来就是它的，语音的 WebSocket 和 `/v1/events` 一样由它带着登录转给核心。走 Cloudflare 隧道不用另外申请。
- **页面**只做自己这一端：采集、降噪、编码、解码、缓冲、播放。别的应用要进房间，自己实现这一端。
- 音频不走 Satori 的消息，也不走 `/v1/events`：积压时不拖住事件。

## 通路

一个成员一条 WebSocket：`GET /v1/internal/guilds/{id}/voice`（`id` 是组号；未归类没有语音）。二进制帧是音频，文字帧是信令。`GET …/voice/members` 列房间里的人。

谁在哪个组的语音里是携带状态 `voice`（`{组号: [成员]}`，只含调用者看得见的组）：网页在组那一行标人数，不在房间里也看得到。

## 网页上

- 入口在组的“+”里，agent 下面一行“语音”（有人时写几人）；在这个组的语音里时这一行是“离开”。组那一行有人时标着人数，点它也进。
- 进了语音，会话列表左下角头像那一栏的右侧出现两个键：麦克风（静音）、语音（点开是面板：成员和各自的延迟、离开、音质、降噪、门限、自动增益、一行数字）。不在语音里时那里什么都没有。手机上没有那一栏，这两个键在对话顶栏。
- 一个页面同时只在一个房间；换会话不影响。

TCP 上帧不会丢，只会迟到，所以不做重传和纠错，只对付积压：

- 发：Opus，按音质：

  | 音质 | 码率 | 一帧 | 不说话 |
  | --- | --- | --- | --- |
  | 低 | 12 kbit/s | 40 ms | 不发（编码器的 DTX，每 400 ms 一帧背景音） |
  | 中 | 24 kbit/s | 40 ms | 照发 |
  | 高 | 40 kbit/s | 20 ms | 照发 |

  自动从中开始，上行压住（WebSocket 里压着 0.4 秒的量，或有帧没发）就降一档（3 秒内不连降），连续 20 秒通畅升一档。WebSocket 里压着 1 秒的量时新帧不发。
- 转：服务端不解码，原样转给房间里别的人；每个听的人最多压 256 帧，满了丢最旧的。静音的成员的帧不转。
- 听：每个说话的人一条队列。一段话攒够“目标”才开始放，放到队列空为止；队列超过上限就丢最旧的，回到目标。目标 = 这个人最近 150 帧延迟的 5%–98% 跨度 + 60 ms，60–800 ms；上限 = 目标 + max(240 ms, 目标)。队列比目标长 30 ms 以上时，队首整块安静的（停顿）直接跳过：一直在发的人靠这个追上来。不变速。

## 采集

麦克风（浏览器的回声消除一直开）→ 降噪 → 门限 → 20 ms 一块 → 编码。设置记在本机浏览器里。

- **降噪**：关；标准（浏览器自带的，只压风扇这类稳定的底噪）；强（默认：RNNoise，`@sapphi-red/web-noise-suppressor` 里的 WASM，在 AudioWorklet 里跑，认得出键盘、鼠标）。RNNoise 起不来时退回标准。页面的 CSP 为它加了 `'wasm-unsafe-eval'`。
- **门限**：麦克风够响才发出去，压旁人说话和漏过降噪的声音。只有手动的：面板上的横条画着现在的音量（门限开着时是绿的），手柄是门限，拖到哪就是哪（-70 到 -10 dBFS，默认 -50），拖到最左等于不拦。低于门限 300 ms 后关上。不做自动门限（用户，2026-11-12）：跟着房间底噪走的门限在人一直说话时越升越高，把声音越切越碎，关上之后只有出现一段安静才复位（v0.2.12 里连续的声音十秒后就再也打不开）。
- **自动增益**：浏览器的，可关。

## 不出爆音

一切开始和结束都渐变，不直接切：

- 听的一端：一段话开头音量在 12 ms 里升上来，队列快空时降下去；丢帧前先降到零再接上。单独来的一帧不放（低音质静音时那帧背景音，单放是一声“哒”）。混音超过 0.85 的部分压弯，不削顶。输出里一直垫着听不见的底噪（-74 dBFS）：纯静音时手机的功放会休眠，下一个字出来时“吧嗒”一声。
- 说的一端：门限开 5 ms、关 60 ms 渐变；静音、换麦克风（改降噪、自动增益）、换音质（编码器重设）之前先把采集渐弱到零，之后再渐强。

`web/scripts/voicepop.mjs` 实测这件事：一个无头 Chrome 把一段录音当麦克风说进房间，另一个把实际播出的每个采样交出来，期间说的人静音、换音质、换降噪，听的人的链路可以模拟卡顿（`JITTER=1`）；播出的波形里数硬边和尖刺。

## 帧

成员发：`类型(1)=1` `标志(1)` `序号(2)` `时刻(4)` + Opus。时刻是这一帧第一个采样采到时房间时钟的毫秒数（低 32 位）。服务端转发时在前面加 `成员号(2)`。大端。最长 1500 字节，一个成员每秒最多 100 帧。

## 信令（JSON）

| 方向 | 内容 |
| --- | --- |
| 服务端 → | `{op:"hello", self, now, members}`：进房间后第一条；`members` 每项 `{id, app, login, name, muted}` |
| 服务端 → | `{op:"members", members}`：有人进出、静音 |
| 成员 → | `{op:"ping", t}`，回 `{op:"pong", t, now}`：`now` 是房间时钟（毫秒）。页面每 2 秒一次，取最近十次里往返最短的那次算时钟差 |
| 成员 → | `{op:"mute", muted}`：按了静音，或麦克风在页面外被关掉（耳机上的键、系统） |
| 成员 → | `{op:"stats", stats}`：自己测到的数，服务端只写日志 |

30 秒没有任何帧就断开。房间满（16 人）关闭码 4008。谁在说话不发信令：解出来的声音里有人声就是在说。

## 测

面板上：每个成员后面是听到他的延迟（网络 + 缓冲 + 设备输出，不含对方麦克风自己的延迟）；最下面一行是自己听到的延迟、自己发的码率、进房间以来的流量（这条 WebSocket 收发的帧和信令，不含 WebSocket 和 TLS 的头；只在内存里）。其余的在这一行的提示里：

- **网络**：帧的第一个采样采到 → 到达听的人，中位数和 95%（最近 30 秒）。含一帧的时长和编码。
- **缓冲**：帧在队列里等了多久。**往返**：到服务端的 ping。
- **丢弃 · 未发 · 卡顿**：队列太长丢的帧、上行压住没发的帧、一帧比前一帧多迟到 300 ms 以上的次数。编码器或解码器积压超过 8 块时（电脑很忙），新来的那块不排队直接丢，分别算进未发和丢弃：排队只会让后面的都更迟。

离开时和每 30 秒，页面把进房间以来的数发给服务端，日志里一行 `voice: …`（`net` 是中位/95%/最大；`gaps` 队列放空的次数，`skipped` 跳过的停顿；后面是音质、降噪、自动增益和浏览器）。

`web/scripts/voicesoak.mjs <地址> <录音> [分钟]`：在房间里待几分钟，两边都开着面板，每 20 秒记主线程迟了多少、堆多大、面板上的数：看有没有随时间涨的东西。

`web/scripts/voice.mjs <地址> [秒]`：两个带假麦克风的无头 Chrome 进同一个房间，打印两边的数，换音质、静音、离开。只对测试实例。

## 没做

- WebRTC（UDP）直连：连贯和延迟的上限在 TCP，卡顿多的链路（手机流量）每两三秒断一下，调参数补不回来。
- 变速追赶、断线重连后补发、转写、AI 进房间。
- 压“旁人说话”只有门限：旁人和自己同时说时拦不住。按声纹只留本人的声音没有现成的开源浏览器方案。
- 没有 WebCodecs 音频编码的浏览器（Safari 26 之前）不能用。外放时的回声消除没测过。
