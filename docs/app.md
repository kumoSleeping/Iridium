# 桌面应用

`internal/desktop`（2026-11-20 起；11-22 并进 `iridium`）：Iridium 的桌面应用，和服务器是同一个程序（用户，2026-11-22）。Mac、Windows、Linux 桌面上直接运行 `iridium`（不带参数）就是它：本机跑一个 Iridium 服务器，窗口打开它的网页；也能切到别的 Iridium，并把这台电脑接入过去（同 `ir-computer`，代码是 `internal/join`）。只要服务器、不要窗口：`iridium serve`（或 `iridium install -now` 装成服务）。安卓另做。

用 mygo（`github.com/egoist/mygo`，2026-11-23 起；之前是 Wails v3），纯 Go，不用 cgo，三个系统都在 Linux 上交叉编译。图形库在第一次要窗口时才加载，服务、托管进程、`ir` 都不碰。发布构建带 `-X github.com/egoist/mygo.production=1`（`scripts/release.sh`），否则 mygo 当它是开发版，开着网页检查器。`ir-computer` 和一行命令先保留（用户，2026-11-20）。

## 运行时和命令（2026-11-22）

先把 ir 起起来（运行时），再选开哪几样（用户，2026-11-22）：本机服务器（放出别人能加入的网页）、接入别的服务器（执行器）、有头还是无头（开不开窗口）。对外只有 `ir` 一个命令，程序文件叫 `iridium`（`iridium ir …` 一样）。

| 命令 | 结果 |
|---|---|
| `ir start [--headless] [--no-server] [--join A [筛选]]…` | 把运行时注册成用户服务（systemd、LaunchAgent、登录时运行的计划任务）并启动，已在跑就换上这个程序重启；有图形界面且没有 `--headless` 时再开窗口 |
| `ir stop` | 停掉并去掉服务，设置、程序、状态都留着 |
| `ir server on\|off` | 本机服务器开关 |
| `ir join A [--name] [--roots a,b] [--no-shell] [--agents a,b] [--proxy]` | 常驻接入 A，累加，各地址各自的筛选；ir 没在跑就先起来（从没用过 ir 的机器默认不开本机服务器） |
| `ir leave A` | 不再接入 A |
| `ir status` | 版本、服务、运行时、本机服务器、每个接入、窗口 |
| `ir serve [--no-server] [--join A]…` | 前台跑，关终端就停；Docker、调试用 |

- 设置就是应用的 `app.json`（`NoServer`、每个服务器的接入开关和筛选），窗口右上角改的也是它。运行时（`iridium run`）每 2 秒看一次，变了就照着做：本机服务器是它的子进程 `iridium serve`，接入在它自己的进程里。
- 窗口只是运行时的界面：接入的状态读运行时的记录（`<应用配置目录>/run/<pid>.json`），关窗口、退出窗口都不影响服务器和接入。窗口打开时，本机还没起来就先 `ir start --headless`。
- 服务器请求放开权限时，运行时把请求写成 `run/ask-*.json`，窗口弹面板回答（`answer-*.json`）；没开窗口或 5 分钟没答就是拒绝。
- `start`、`stop`、`server`、`join`、`leave` 改的是开机自启和接入，agent 不能替人跑（看 `CLAUDECODE` 和会话的环境变量）。
- 程序换了（自更新），运行时重新执行自己；窗口发现磁盘上的程序是新版本，托盘出现“重启以更新”。
- Mac 上换来的程序还没被系统允许打开（新下载的 .app 解压覆盖旧的，隔离标记没有“用户已允许”）时，运行时不切换、也不用它启动本机服务器，旧的接着跑，等这个 app 被打开过一次再换：直接运行只会弹“未打开 Iridium.app”并被结束，launchd 每几秒又起一次，弹窗不停（2026-11-22）。
- 旧写法留作别名：`iridium install`（只装 `serve` 的服务，服务器用）、`uninstall`、`version`、`headless`、`app`。

curl 只装程序，`sh -s --` 后面的交给 `ir`。见 `docs/exec.md`。

## 应用页面（2026-11-22）

只用框架支持得稳的东西（kumo，2026-11-22）：所有窗口都是普通窗口，用到时才建，不预先藏着建好，不用透明、悬浮；Mac 上不用无边框（隐藏标题栏的普通窗口），Windows、Linux 无边框（kumo，2026-11-22：所有系统都不要标题栏，见「系统的标准操作」）。换过框架的讨论见本文末「窗口框架」。主窗口只显示服务器的网页，不显示应用自己的页面；本机启动中、要登录这些都写在小窗口里。状态到了才画，画出来就是完整的。

- **小窗口**（`picker.go`，380×640，竖的，不能改大小；`web/src/appwin/login.tsx`）。一次显示一部分，换的时候旧的淡出、新的淡入：
  - 顶部一条（各系统一样，没有系统标题栏）：左边 Ir 标和 Iridium，右边关闭键，按住这一条拖动窗口。
  - **自己**（第一次打开，列表里还没有服务器时）：头像（没选是灰色小人，点了选图、裁成圆）、名字框（浅色提示系统账户名）、「开始」：在本机跑 Iridium，本机登录用这个名字和头像。最下一行「添加服务器 ›」。
  - **服务器**（上）：「此电脑」一行（kumo，2026-11-22）：灯 + 运行中、已停止、启动中，公网开着时后面接公网地址；右边两个键，不用开关：地球（公网访问，开着是绿的）和 暂停/播放（停止、启动）。停止、关闭公网访问要按两次（第一次变红）。开关只启动或停止，不动窗口；授权链接、第一个邀请、出错在它下面各一行。然后每台服务器（名字，下面是灯 + 地址，已登录绿、未登录灰）。不标上次用的那台（点一下就进去了，勾没有意义）。点一行：小窗口消失，那台的窗口出来（已经有窗口看着它就提到前面，否则新开一个）；没登录的先在浏览器登录，代码写在这一行下面。鼠标移到一行上，右边出「移除」（按一次变红，再按才移除）。最后一行「添加服务器」，点了才变成输入框：邀请链接（路径 `/_ir/join`）在浏览器打开、带上 `app=<应用登录 id>&name=<名字>`，注册 Passkey 后直接批准应用；地址走浏览器登录。
  - **授权操作**（下）：每台已登录的服务器一行，写这台服务器（应用里起的名字，没有就是地址，kumo，2026-11-22：原来写的是登录名，看不出是哪台）、连接状态（灯 + 已连接 32 ms、断开 3 分钟、连接中、未授权；还没有连接记录时是「连接中」），右边授权开关和 ›，可以同时授权给几台。没登录的不在这里，一台都没有时这一栏不出现。
  - **一台服务器的授权**（› 进去，左上返回）：「授权操作」开关（允许它在这台电脑上操作）；开着时命令行、每个 agent、文件夹，各有图标，前两项和文件夹下面一行小字说明。
  - 出在最近用的那个窗口所在的屏幕上（kumo，2026-11-22），不是它上次待的屏幕。
  - 添加服务器：拿到代码后转圈挪到新的那一行，输入框收起；浏览器里允许后转圈和代码都去掉（原来一直转，下次点“添加服务器”还没输入就在转）。
  - 什么时候出来：每次打开应用只出它（kumo，2026-11-22），选一台后它消失、那台的窗口出来；网页右上角的键、⌘,、⌘N、托盘「添加服务器…」；服务器网页掉了登录（那个窗口关掉）；看着的服务器被移除。关掉只是藏起来。
- 这里改的都是本人在应用自己的页面上点的，不再弹确认框。服务器那边主动来要的（开命令行、加文件夹）才弹请求面板，默认「允许」，有「以后都允许」（`alwaysAllow`）。
- 连接状态来自运行时的记录：每个接入的连接是否在、最近一次往返、从什么时候起（`run/<pid>.json` 的 `links`，每 2 秒写一次）。
- 明暗：一进去跟系统（还没选过时也给网页带上 `?theme=auto`，那台网页以前在这台电脑上存的选择让位）；在服务器网页里改过明暗，应用记下（`theme`），之后应用自己的页面和每个服务器的网页都按它打开（`?theme=`，那边也记下），两边一致、不闪。
- 浏览器里批准应用后：大字「已登录」和「回到 Iridium 应用」，能关的浏览器自己关掉这一页；应用窗口自己到最前面。

## 本机（2026-11-22）

- 第一次打开什么都不启动（用户，2026-11-22）：停在应用自己的页面，给“在本机运行 Iridium”和“添加服务器”。点了前者才注册服务、启动本机服务器（运行时已经在跑（接入着别的服务器）就只改设置、等它自己起本机服务器，不重启运行时，别的连接不断；否则 `ir start --headless --as-is`，等它应答，最多 30 秒；装不了就把 `iridium run` 单独起在应用之外），等的时候本机一行显示“启动中”。
- 添加的服务器只显示、不接入；它的“接入”开关打开后才接入。只看别的服务器时不注册服务、没有后台进程。
- 要不要服务看设置（`Needed`：本机服务器开着，或接入了哪台）：要了窗口就 `ir start --headless --as-is`，不要了就 `ir stop`；`ir server off`、`ir leave` 之后也一样。`ir start`（不加 `--as-is`）是明确要本机服务器，照旧打开它。
- 之后每次打开：先出小窗口，上次用的那台打着勾。本机的不接入（它就是这台电脑）。地址取本机服务器的配置：有公网地址用公网地址（要登录），否则 `http://127.0.0.1:<端口>`，回环上不用登录。

## 组成

- 窗口：系统自带的网页引擎（Mac WKWebView、Windows WebView2、Linux WebKitGTK）直接打开服务器地址，网页不打包。关窗口留在托盘。只跑一份：再次打开就显示已有的窗口。
- 托盘（Mac 菜单栏、Windows 通知区）：和页面一样分两类。「服务器」：此电脑（在窗口中显示、运行、隐藏：小窗口里不列它）、每台服务器（点了出它的窗口，上次用的打勾）、新建窗口…（小窗口）；「授权操作」：每台已登录的服务器一项，勾着就是允许。再下面重启以更新（有新版时）、版本、退出（kumo，2026-11-23）。
- 没有「登录时打开」（kumo，2026-11-23）：开机要跑的是运行时（系统服务），不是窗口。以前开过的登录项，应用第一次启动时撤掉一次（`LoginItemGone`），之后用户自己在系统设置里加的不动。
- 接入：列表里开着的服务器（本机除外）各一条执行端连接，握手里 `program` 是 `ir-app <版本>`。TOKEN 和 `ir-computer` 共用（同一目录），已配对的不用再配；同一服务器同时只有一个在跑（锁）。
- 无头：`iridium headless [--name] [--roots] [--no-shell] [地址…]`，给没有屏幕的机器。不加载图形库。
- Windows 上 `iridium.exe` 是控制台程序（命令行要输出）：从资源管理器打开时应用放掉自己的那个控制台窗口。

## 安全

- 这台电脑能做什么由这里定（`app.json` 和启动参数），服务器只能请求。
- 服务器请求放开时，窗口版弹本机对话框（允许、拒绝，不放进网页）；无头版在它的终端里问，没有终端（服务）就拒绝。
- 网页和应用之间：网页 `window._wails.invoke("ir:…")`，回给网页的是事件 `ir-app`。`window._wails` 是应用在每个页面开头注入的一层（`internal/desktop/bridge.go` 的 `shim`），底下是 mygo 绑定的方法 `IRApp.Invoke`，所以 Wails 时期的网页、各版本的服务器照旧能用（2026-11-23）。每个窗口只信任它自己那台服务器的来源和应用自己的页面（mygo `TrustedOrigins`），别的来源、iframe 的调用 mygo 直接拒；应用再按来源分：列表里的服务器、应用自己的页面（`mygo://localhost`）。网页里没有任何放开权限的口。
- 页面上的链接：到别的网站的交给系统浏览器，窗口留在它的服务器上；下载存进「下载」，下完在访达里选中；麦克风、摄像头、通知只给这个窗口自己的服务器（`guard`，2026-11-23）。
- 新网页的窗口键、改名只在新应用里画（应用的 `hello` 带 `os`），旧应用里不画（2026-11-23）。
- 页面要放宽什么（接入、命令行、全部文件夹、添加服务器）都要本机对话框确认；收窄直接生效；加文件夹用本机的文件夹选择框（选了就是允许）。权限按服务器各一份。

## 登录（2026-11-20）

应用和浏览器的登录都是 180 天有效（用户，2026-11-22）。它的 Cookie 是 `SameSite=Lax`：窗口每次从应用自己的页面打开服务器都算跨站，`Strict` 的 Cookie 不会带上，就成了每次都要重新登录（2026-11-22 修）。

内嵌网页里没有 Passkey（Linux WebKitGTK、未签名的 Mac），在系统浏览器里登录（`internal/webapp/applogin.go`）：

1. 应用窗口停在登录页时，页面认出应用（`window._wails`，等事件 `wails:runtime-config-ready`，都是应用注入的），按钮换成“在浏览器中登录”。
2. 应用自己生成一个密钥，把它的 SHA-256 发给 `POST /_ir/api/app/start {name, verifier}`，拿到 `{id, code, url}`；页面显示代码，系统浏览器打开 `/_ir/app?id=…`。
3. 浏览器里用 Passkey 登录（已登录就跳过），看到“「电脑名」上的 Iridium 应用请求以你的身份登录”和代码，核对后允许或拒绝。
4. 应用轮询 `POST /_ir/api/app/poll {id, secret}`，允许后拿到一次性凭证（2 分钟），窗口打开 `/_ir/app/finish?ticket=…`，这边给这个窗口一个同一登录的会话，回到首页。
5. 请求 10 分钟过期，只在内存；同时待批最多 50 个。只看到浏览器地址栏里的 id 拿不到任何东西。

邀请链接（2026-11-22）：粘贴的是邀请（路径 `/_ir/join`）时，应用照样先 `app/start`，然后在系统浏览器打开那条邀请，查询里加 `app=<请求 id>` 和 `name=<名字>`（`#` 后的邀请码不动）。邀请页把名字填好（邀请自己定了名字的以邀请为准），建好 Passkey 后直接跳到 `/_ir/app?id=…`，已经登录，照常核对代码、允许。`app`、`name` 只在这一页用，刷新也记得（本标签页）。

公网下的窗口（2026-11-22）：本机开了公网地址后，`127.0.0.1` 原本也要登录。配置 `public.localWindow: true`（桌面应用写）时，Host 是回环名、来自回环地址、没有转发头（`Cf-Connecting-IP`、`X-Forwarded-For` 等）的请求仍按“只本机”处理，就是本机登录，窗口不被挡。隧道的配置写明 `httpHostHeader` 为公网主机名，经隧道来的永远不是回环 Host。

公网访问（2026-11-22）：桌面应用用 `cli.PublicOptions(配置, 输出)` 拿到 `ir public` 的选项，设 `Host`、`OnLink`（Cloudflare 登录链接，cloudflared 自己也会试着开浏览器）、`OnInvite`（第一个邀请），再 `public.On`；没有终端，问题都取默认（子域名用 `Host` 或 ir，是否题一律否：已有同名 DNS 记录就停下报错）。关掉 `cli.PublicOff`。Windows 暂不支持。

## 应用的键

应用里的网页顶栏右上角有一个键（`web/src/appkey.tsx`，浏览器里不出现），按了发 `ir:home`：小窗口出来，再按一次收起（kumo，2026-11-22）。放进 Mac 窗口顶部那一条试过，撤回了：那里连按两下会触发系统的全屏/缩放。

## 多个窗口（2026-11-22）

- 窗口之间互不等待：托盘菜单重画要读的东西（设置、运行时的记录）在主线程之外读，主线程只建菜单（约 1 毫秒）。原来都在主线程上，每次切换所有窗口一起停一下（kumo，2026-11-22）。
- 在 Mac 上从外面看窗口（验证用）：`IRIDIUM_APP_PROBE=open,controlhold,release,picker` 启动，每 3 秒做一步；`screencapture -l <窗口号>` 截单个窗口，带透明度。
- 可以开好几个窗口，各看一台服务器：在小窗口里点一台，没有窗口看着它时就新开一个。
- 下次启动小窗口里打勾的是最后用的那个（`current`，窗口拿到焦点时更新）。
- 关一个窗口就是关掉它，不留藏着的；都关了应用留在托盘，点程序坞图标或托盘出小窗口。

## 系统的标准操作（2026-11-22）

- **没有标题栏**（kumo，2026-11-22）：Mac、Windows、Linux 一样，所有窗口都不要系统标题栏。窗口键由网页自己画在顶栏最右（`web/src/winkey.tsx`），就是顶栏普通的图标键，三个：最小化、全屏、关闭（最小化 2026-11-23 加上，QGI、kumo）。全屏按各系统自己的：Mac 是系统的全屏（绿灯的行为），Windows、Linux 是最大化、还原。小窗口只有关闭。Mac 是隐藏了标题栏和红绿灯的普通窗口（不是无边框，见「窗口框架」），Windows、Linux 是无边框窗口（保留系统阴影和贴边）。
- 网页顶栏（标 `data-app-drag` 的，键、输入框除外）拖动窗口，双击照系统标题栏（Mac 按系统设置缩放或最小化，别的最大化）；没有标的旧版服务器网页用最上面 40 像素。Windows、Linux 窗口边缘 5 像素拖动改大小。都在 `chrome.go` 注入的脚本里。旧版服务器网页没有自己的窗口键，脚本在上方补一条，带这三个键（简单的字符）。
- ⌘W、Ctrl+W 关当前页面：设置弹窗按 Esc 关，打开的会话回到首页，已在首页才关窗口（kumo，2026-11-22）。⌘R、Ctrl+R、F5 重新载入。
- **窗口名**（kumo，2026-11-22）：同一个人可以开几台服务器、各一个窗口。在应用里，左上角 Ir 标右边的名字点一下就能改，只存在应用里（`Server.Title`），服务器不知道；窗口标题（Windows 任务栏、切换窗口）、小窗口、托盘都用它，空着就是 Iridium。

## 更新

## 构建

Mac 的 .app 必须整个签名（临时签名，不用 Apple ID）：只有 Go 链接器给程序的那个签名、Info.plist 和资源没封装时，下载来的会被说成“已损坏”，设置里也打不开（2026-11-20 实测）。整个签了以后是“无法验证开发者”，系统设置 → 隐私与安全性里能“仍要打开”。脚本在有 `codesign`（Mac）或 `rcodesign` 的机器上签，都没有就警告：发版要在 Mac 上（CI 的 macOS 机器）打包。

`scripts/release.sh` 出各系统的 `iridium-<系统>-<arch>.tar.gz`，Linux、Windows 另出裸的 `iridium-app-*`；`scripts/app-bundle.sh <版本> <目录>` 在 Mac 上（CI 的 macOS 机器）把 macOS 的二进制包成 Iridium.app、签名、压缩，把它们的校验和加进 `SHA256SUMS`。应用自己的页面先 `npm run build:app`。大小（去符号）：Linux 30MB，Mac 29MB（压缩 13MB），Windows 31MB。

## 权限由这台电脑定，服务器只能请求（2026-11-20）

- 右上角弹窗列出列表里每个服务器：本机在那边的状态、接入开关；接入的再列命令行、每个 agent、文件夹，平铺一行一项。关掉的当场生效（执行端 `Set`：之后启动的照新规矩，正在跑的不动，连接重连一次让服务器看到新的握手）；打开的要本机确认。删除用按两次的垃圾桶，不放 ×。
- 服务器不能直接打开什么：放开命令行、加文件夹（`grant`）、启动已关掉的 agent（`hold.start`），执行端都把请求拆成一项一项（`executor.Item`：命令行、文件夹、agent），交给应用的请求面板：应用自己的一个普通小窗口（`web/src/appwin/ask.tsx`，`#ask`），每项一个开关，拒绝或允许；Esc 拒绝，回车允许，超时算拒绝。允许的写回应用的配置（`Widened`），下次照它。
- 无头版没有面板：在终端里整条问 `[y/N]`，没有终端就拒绝。
