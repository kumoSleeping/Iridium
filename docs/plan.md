# Iridium 计划

Rhodium 的轻量 Go 版本：一个网页，管理主机和别的电脑上 agent 的会话。0.2 起叫法见 `GLOSSARY.md`，改版记录在 `docs/next/`。

## 不做

内置 IM（IM 由应用自己做）、终端模拟（网页终端、TUI、Herdr）、组网（Tailscale）、`rh` 命令、槽位模型、定时任务（agent 自己有）。

## 应用和登录（0.2）

- 接入方都是**应用**，凭 TOKEN 访问；应用下面是**登录**（谁在说话）。主机不算应用，不可被管理；网页（`ir_web`）是内置应用，每个浏览器一个登录。见 `GLOSSARY.md`。
- 应用只经**配对**进来：开放配对（应用管理里的“开放配对”，10 分钟），申请方显示配对码，主机或能批的网页登录核对后允许。
- **权限**：用哪些 agent、哪些文件夹（位置 `应用名:路径`）。能用的 = 登录的 ∩ 应用的；范围外的会话看不到，不能用的 agent 的会话只能看。
- **Claude** 只给本人的应用和登录（Claude 用户协议），只在建的时候定：配对时允许为本人的，或 `ir invite --claude`。
- 批申请的只有人：主机上的人，或有 Claude、权限全部的网页登录；agent 的 `ir` 一律不能批。
- 名字是来源标记，也是用量统计的单位；同一范围里不重名，保留 `host`、`主机`、`本机`、`ir_web`，单个字母不能用。

## 会话

- agent：Claude、Codex、pi、dsh（DeepSeek Harness）。
- 自动发现 agent 自己起的会话（agent 记录目录、`~/.claude/sessions/`、`/proc`），不建父子关系（子代理除外，见下）。
- 没有“工作区”要先建（2026-11-08）：分组就是文件夹。会话第一次出现时归组：拉起者的组（组的文件夹包含它的目录时；子代理总跟父会话）→ 包含它目录的最外层的组 → 用它自己的目录新建一个组（名字取文件夹名）。子目录的组比父目录的先建时（2026-11-08），父目录的组一建好，子目录的组就并进去，成为它下面的子目录；手动放过的会话不动。家目录和 `/` 的组只收正好在那里的会话，免得一个会话把所有项目都收进去。以前在“未归类”的会话也按这条重新归组；只剩没有目录的会话在未归类。组里没有显示的会话就不列出来（组还在，改的名字、通知设置留着）。
- 结构：组（文件夹）→ 子目录 → 会话；子目录写成相对组的路径（如 `web/api`），只有一个会话也显示（2026-11-06）；组目录下的会话直接列在组下。一个会话只属于一个组。子目录的上级目录也列着时（2026-11-10，之前最多两级），它挂在最近的那个下面、往里缩一级，名字写相对它的路径，中间没有会话的目录并进名字（如 `b/c`）；最多缩三级，更深的画在第三级。拖动、置顶在同一个上级文件夹里；文件夹的“归档这里的 N 个会话”连它里面文件夹的会话一起归档（挂在下面的派出会话也算进 N）。
- 显示标记：有标记的会话才在 Iridium 里显示。Iridium 开的、或开始监视后有新动静的（新会话、旧会话有新内容）自动加上；归档 = 去掉标记，有新动静自动回来。按 agent + 会话 ID 存在 Iridium 库里，不写 agent 的文件。原有的旧会话没有标记，不显示，在会话列表底部“已归档”里，可搜索、一点恢复。不按时间自动归档，不删对话记录。
- 需要你的会话留在原位，状态灯琥珀色呼吸；不另建“需要你”组（2026-11-08）。不属于会话列表里任何会话的确认（`ir` 邀请、TOKEN 等）单独一行列在最上面。
- 在别处开着的会话只读；那边退出后可在网页接着聊。
- 子代理（Claude 的 Agent 工具子任务、Codex 的子 agent 线程）也进列表：标“子代理”，只读（只有父会话能和它说话），记着父会话、能跳回去，归父会话的工作区（2026-11-06 定，推翻原来的“算在原会话里”）。
- 派出的会话（用户，2026-11-10）：会话里用 `ir new` 开的（本机、远端都算）一律挂在拉起者下面，同子代理，但是完整的会话：一直列着、能直接对话。拖出来的按自己的目录归组，不再挂回去；链式拉起挂在最上面那个下面；拉起者收起时写子会话数和汇总状态；拉起者归档，挂着的一起归档、一起恢复（拖出来的不跟）。关系就是 `launcher`，不另存；`/clear` 后新会话接着挂，它拉起的改挂到新会话下。列表上的细节见 `docs/exec.md`“远端工作区”。

## 运行

- 每个会话一个托管进程，只做托管，只用文件：命名管道进 stdin，stdout 追加 `out.log`，退出码写 `exit`。`systemd-run --user` 拉起，Iridium 重启不断回合。
- 托管进程和 Iridium、`ir` 是同一个二进制。
- 空闲回收同 Rhodium：默认 1 小时，配置文件/按会话可改，可关；有后台任务不回收。
- 崩溃续跑、额度续跑：默认开，配置文件可关。设置页不放这三项（用户，2026-11-07）。
- 平台相关代码单独一层，以后加 Mac。

## 数据

- 会话列表以磁盘为准；库（SQLite，纯 Go）只存：归属、置顶、显示标记（没有就是归档，见 `docs/api.md`）、改名、待发队列、推送订阅、交互终端和权限、用量、凭据（加密）。
- 历史只读 agent 自己的对话记录；托管输出只用于正在打的字、状态、提问、后台任务。
- 提问不进库，现场问 agent；不设超时。
- 配置一个文件，设置页改的就是它。

## 便签（用户，2026-11-09，试做中）

- 随手记想法、要做的事。不分类也行，可放进便签夹（一层）。正文纯文字，第一行当标题。
- 电脑：会话列表顶上“+”左边的便签键，便签换到会话列表的位置，再点换回。手机：底部面板第四页“便签”，从输入框右 1/4 往上滑直达。
- 最上面一个输入框，回车记下（Shift+回车换行）。点一条就地展开编辑；选中几个字可“拆出”成一张；菜单里“按行拆开”、完成、移到便签夹、删除、颜色。
- 拖动：电脑按住就拖，手机长按浮起再拖（长按不动松手是菜单）。拖到两条之间排序，拖到一条中间合并（可撤销），拖到便签夹放进去，拖到对话或会话行放进那个会话的输入框当草稿，不直接发。拖着停在便签键（电脑）或“会话”标签（手机）上，翻回会话列表。
- 放进过的会话记在便签上，行尾显示它的 logo 和灯，点一下过去。
- 库里存（`notes`、`note_folders`），事件流 `notes` 整份推送。没做：跳转框搜便签、快捷键随手记、断网先存、`ir note`、Bot 记。

## 消息来源

- 每条交给 agent 的消息开头带 `[名字]`，只给 agent 看。
- 网页不显示前缀：服务端按 Iridium 自己写进去的输入认来源（Claude 的 uuid、Codex 的 client_id，其余比对输入记录），去掉前缀，消息块带 `from`。终端里手打的照原样。
- 前端按来源分组件（同一组件的变体）：
  - 面板发的：“你的话”气泡；来自别的面板时角上淡色设备图标。
  - 所有人发来的话（你的、别的会话的 agent、Bot、对等机器）都在右侧，和“你的话”同一边；左侧只有本会话 agent 自己说的（2026-11-06）。
  - 别的会话用 `ir api message.create` 发的、Bot 发的：来信卡片（logo/图标 + 名字，可跳转），不算“你的话”。
  - Iridium 自己写的（恢复提示等）：居中一行淡字。
- 列表的“最近一句话”：只有面板发的写“你：”，来信写来源名。

## `ir`

和 Iridium 同一个二进制，经本机 unix socket（0600）走网页那套接口。`ir api` 把请求原样发出去（透传，用户，2026-11-11）；只留它做不了的：`run`（在本机把凭据换进命令、输出打码），和人在终端跑的 `public`、`join`、`pair`。

```
ir api [方法] <路径|satori.方法> [k=v | k:=JSON | k==查询]... [@文件|@-] [--pick a,b] [--grep 词] [--all] [--clip N] [--json] [--wait]
ir api help [接口|话题|词|all]  一个接口和它的说明 | 一个话题的接口 | 含这些词的接口和说明 | 全部；不带：用法和常用接口
ir run [--secret 名,…] -- 命令 …
```

以前的命令和现在的写法：

| 以前 | 现在 |
| --- | --- |
| `ir ls` / `find <词>` | `ir api channel.list [_data.all:=true] [guild_id=self] [--grep 词]` |
| `ir read <id>` | `ir api message.list channel_id=<id>` |
| `ir send <id> "消息" [-a 文件]` | `ir api message.create channel_id=<id> _data.text="消息" [_data.paths:='["/绝对/路径"]'] [--wait]` |
| `ir rename` / `archive` | `ir api channel.update channel_id=<id>\|self data.name=<名>`、`channel.delete` |
| `ir stop <id>` | `ir api POST internal/sessions/<id>/stop` |
| `ir ws [ls]` / `ws rename` | `ir api guild.list`、`ir api PATCH internal/guilds/<组> name=<名>` |
| `ir files <目录>` | `ir api internal/files path==<目录>` |
| `ir wait <id>` | `ir api internal/sessions/<id> --wait` |
| `ir cp <源> <目标>` | `ir api POST internal/files/copy from=<源> to=<目标>`（两边都可写 `应用名:路径`） |
| `ir sh <应用> -- 命令` | `ir api POST internal/machines/<应用>/shell line="命令" --wait` |
| `ir update [--check]` | `ir api POST internal/update`、`POST internal/update/check` |
| `ir new <agent> [位置] "任务" [--wait]` | `ir api channel.create _data.agent=<agent> _data.cwd=<位置> _data.text="任务" [--wait]` |
| `ir attach <文件>` | `ir api POST internal/links path=<文件>` |
| `ir share 应用/登录 <…>` | `ir api POST internal/share to=应用/登录 what=session\|place\|file …` |
| `ir secret set/ls/rm` | `ir api PUT internal/secrets/<名> note=… --wait`、`internal/secrets`、`DELETE internal/secrets/<名>` |
| `ir usage` | `ir api internal/usage days==7` |
| `ir apps`、`profile`、`invite`、`needs`、`allow`、`deny` | `ir api internal/apps`、`PUT internal/apps/<id>/profile`、`POST internal/invites`、`internal/needs`、`POST internal/needs/<id> allow:=true` |

- 透传：`ir` 只补头（`X-Iridium-Session`，Satori 的登录头），不改请求。有 `/` 的是 `/v1/<路径>`（不带正文 GET，带了 POST，写了方法照写的）；没有的是 Satori 方法，`POST /v1/<方法>`。`k=v` 字符串，`k:=JSON` 任意 JSON，`k==v` 查询串，带点的键写进对象。
- 原来 `ir` 替人做的搬进服务端，谁调都一样：会话 ID 的开头和 `self`（`/v1/internal/sessions/{id}/…` 和 `channel_id`；`guild_id=self`），`message.create` 的 `_data.text`（纯文字，服务端转义）和 `_data.paths`（主机上的文件，只认 socket），来源从 `X-Iridium-Session` 取（不用 `_data.caller`）。
- 输出只在回答这一侧加工：列表一项一行，`view=` 指定的字段排成表（`--pick` 换别的），对象一字段一行、它里面的对象数组各成一张表；空值不打，每个值一行、截到 200 字（`--clip`）；Satori 消息的 `content` 转成文字（人说的前面 `> [来源]`，工具、思考、系统行标出来）。`--grep` 筛项，`--all` 跟着 `next` 取完，`--json` 原样。
- 接口说明 `internal/irhelp/api.txt`：一个接口一行（方法 路径 正文 -> 回答 说明 view=），按话题分段，测试核对它和服务端注册的路由一条不差。接口下面缩进的行是它的说明（字段的意思、默认值），列表里只在行尾标 `[more]`，`ir api help <方法 路径>`（或 `satori.方法`、实际发的路径）才打出来；按词找时连带含这个词的说明行。系统提示只有几行（`ir api`、`ir run`、分层查法、凭据、交文件、起标题、语言），不放接口表，也不叫每个会话先跑一遍 `ir api help`：知道接口就直接查它，不知道再查话题或词；最常用的几个（起会话、发消息、等、列会话）直接写出接口名（用户，2026-11-11：提示词大量砍，用什么就 help 什么，要什么读什么）。
- 回答是 ndjson 的（远端命令行的输出、拷贝的进度）边收边打：命令行的输出原样，退出码照它；拷贝在终端上画进度，最后一行 `路径 大小 sha256`。`--wait` 在 `GET internal/sessions/{id}` 上等回合结束。
- `message.create` 和带 `_data.text` 的 `channel.create` 不带 `--wait` 也等到 agent 接了这条再返回（最多 15 秒），紧接着的 `ir wait` 等的才是这一回合；带 `--wait` 等回合结束、打印回复。回 202 `{need}`（agent 要邀请、要人填凭据）时 `--wait` 等人决定，只说结果。
- 位置和路径服务端认（`server/places.go`）：`应用名:路径`、`host:路径`、`~/x`；相对路径和 `.` 从调用者会话的目录起（会话在那台电脑上时），否则要整路径。新会话的 `cwd`、`internal/links`、`attach`、`internal/files`、`_data.paths` 都这样。
- `ir api` 带 `X-Iridium-Agent`（规则同管理命令：环境里有 agent 的会话变量，或 stdin/stdout 不全是终端），agent 拿不到秘密、批不了需要。
- `new`、`message.create` 可加 `--wait`；`new` 可选 `--model`、`--approve`。`wait` 退出码：0 结束，2 需要你，1 出错/已退出。
- 组不能手建、删除、挪会话（2026-11-08），只能改名。
- 新会话进调用者的组（组的文件夹包含它的目录时），否则按目录归组；列表里挂在调用者下面（见“派出的会话”）。没有汇报、agent 间权限。
- 不设上限：不限同时运行数、拉起数量、深度、调用频率；提示词里只写“在需要时”。
- 托管会话的系统提示（英文，每次 agent 进程启动时现写，`session.SystemPrompt`）：一句说明 Iridium 和 `ir` 是干什么的，接着直接放 `ir --help` 里“Admin”之前给 agent 用的那部分（同一份 `irhelp.Help`），管理命令只说“见 `ir --help`”；再是凭据、交文件、起标题三句，最后一句用户的语言（网页设置里选的，没选过就是那台网页自己的）。原来只写“见 ir --help”，查本机托管会话：用 `ir` 的一大半先跑一次 `ir --help`，压缩后还会再跑，还被 auto 模式拦过，所以直接写进去（用户，2026-11-08）。`ir --help` 英文，不超过 20 行。

管理应用（0.2）：

```
ir apps [logins [应用]] | rename <应用> <新名> | rm <应用>   应用和登录；登录写 应用/登录
ir api PUT internal/pairing open:=true [minutes:=30]  开放配对（默认 10 分钟，最多 60）；open:=false 关掉；能批的人
ir needs | allow <id> | deny <id>   等人决定的事：应用接入、更新配对、应用变更、登录加入…
ir invite [名字] [--claude]  网页的一次性邀请链接；--claude 带 Claude
ir join <地址> [--shell]     把这台电脑接入另一个 Iridium（执行端），对方核对配对码后允许
ir pair [地址] --name 名字 --into 文件|--env 文件:变量 [--login ID]   替程序申请接入（连同登录，默认 bot），允许后 TOKEN 写进文件，不打印；不给地址是本机，不用开放配对
ir profile <名字> [--name 新名] [--avatar 图片] [--device computer|laptop|phone|none]
```

凭据（见“凭据”）：

```
ir secret ls | set <名> [--note 说明] | rm <名>
ir run [--secret 名,…] -- 命令 …   {{名}}、{{file:名}} 换进参数，输出里的值打码
```

- agent 调这些命令时秘密不进对话：变成一条“需要”，允许后链接、二维码只显示在允许的那一处，agent 只拿到结果。agent 的 `ir` 不能批申请。认 agent 调用靠环境变量和有没有终端；只防 TOKEN 进记录，挡不住故意读库。

## 接入（参考 Rhodium 网关）

- 默认只听本机，不做登录。
- 上公网可选；上公网必须开 Passkey。配了 `public.origin` 后所有网页请求都要 Passkey，回环也一样。
- 新面板：`https://<域名>/_ir/join#<token>`（10 分钟、一次性；`#` 后不进服务器日志），打开直接起名（查重）+ 注册 Passkey。
- Cookie `__Host-`、HttpOnly、SameSite=Strict；空闲 12 小时、最长 7 天。失败限速；POST 和 WebSocket 查 Origin；主机名白名单。
- 最后一个 Passkey 不能删；全丢了在本机 `ir invite` 重来。
- Iridium 不自己管 HTTPS 证书。有公网 IP 的，挂在自己的反代后面（文档给 Caddy 例子）。
- Cloudflare 只是没有公网 IP 时的 Tunnel，不用 Access。

## Cloudflare 一键上公网（`ir public`）

终端里跑，或者在本机网页的设置里点；尽量自动做到能用为止，每步要你确认的用确认面板：

1. 检查 `cloudflared`，没有就下载到 `~/.local/bin` 并校验。
2. `cloudflared tunnel login`：给出登录链接，你在 Cloudflare 上选域名（这一步由 Cloudflare 自己让你选）。没有托管在 Cloudflare 的域名就停下，说缺什么。
3. 填子域名，默认 `ir`，显示 `ir.<域名>`；已有同名记录时问要不要覆盖。
4. 建隧道 `iridium-<机器名>`，写配置：`ir.<域名>` → `http://127.0.0.1:<端口>`，其余 404。
5. 建用户级 systemd 服务跑这条隧道。不碰机器上已有的 cloudflared 和它的隧道。
6. 写 `public.origin`，打开 Passkey；从外网访问健康检查地址，等到通。
7. 生成第一个面板邀请，显示链接和二维码。

- `ir public off`：停服务、删隧道。DNS 记录 `cloudflared` 删不了，提示你去控制台删（给了 API 令牌就自动删）。
- 要实测一遍：登录拿到的凭证能管哪些域名、`route dns` 遇到已有记录怎么报。

## 卡片和需要

- 一套组件：选择题、计划确认、审批、`ir` 邀请和 TOKEN、删除确认。

## 凭据

让 agent 替你用密码、API key，又不让值进对话（2026-11-06）。

- 凭据 = 名字 → 值（如 `GITHUB_TOKEN`、`NAS_PASSWORD`），带一行说明。存在库里，用状态目录里 0600 的密钥文件加密（拷走库不能用）。值只能写、不能读回，要改就整个换掉。
- 存：`ir secret set <名> [--note 说明]`。
  - 你在终端里跑：不回显地读一行；也能从管道读（读全部，去掉末尾换行，ssh 私钥也行）。
  - agent 调（认法同 `ir invite`）：不读值，在这个会话输入框上方弹确认卡（也进“需要你”）：“会话 X 要 `GITHUB_TOKEN`：推送到 kumo/foo”，一个密码框，“存 / 拒绝”。agent 等着，只拿到“已存”或“拒绝”。
  - Bot：接口存（2026-11-08 起不再要权限）。
  - 网页：设置里一页“凭据”，增、换、删，看用量记录。
- 用：`ir run [--secret A,B] -- 命令 参数…`。参数里的 `{{A}}` 换成值，同时设同名环境变量；`{{file:A}}` 换成 0600 临时文件的路径，跑完删（ssh 私钥、kubeconfig）。命令的输出里出现的值（原样、base64、URL 编码）换成 `[secret:A]`，跨块也不漏；退出码照命令的。要面板确认时 `ir run` 在 stderr 说一句再等。agent 的记录里只有 `{{A}}`。
- 谁能用：每个凭据有范围（全部会话 / 某些工作区 / 只给本人终端开的会话）。默认自己面板（带 Claude 的）开的会话直接用；别的终端开的会话第一次用时弹确认卡：允许 / 本会话一直允许 / 拒绝。可单独设“每次都确认”。每次用记一条：会话、命令开头、时间。
- 兜底：网页显示对话记录前，服务端把记录里已知的值也换成 `[secret:A]`；输入框发出前看着像密钥（`sk-…`、`ghp_…`、高熵长串）时提示“存成凭据？”，点了把那段换成 `{{名}}` 再发。
- 托管会话的系统提示里（见“ir”）：要密码、API key 时让人用 `ir secret set` 在网页填，用 `ir run` 带进命令，别让人贴进对话；交文件用 `ir attach` 打印的文件链接（见“网页”）；起名用 `ir rename`（见“会话标题”）。`[文件]` 标记保持中文；旧记录里的 `[标题]` 行照认。
- 边界同 `ir invite`：只防值进记录，挡不住故意的 agent（`ir run -- sh -c 'echo $A | rev'`、直接读库）。真要防得让 Iridium 代发请求，不做。

## 实时数据（携带）

- 每个页面一条事件流，开流时说明订阅了什么：列表、打开的会话、它的上下文、额度。换了打开的会话就重新订阅。
- 订阅的东西都是小状态。开流（含断线重连）先发一份完整的，之后变了就发新的整份，不发补丁；同一样东西 250ms 内只发最后一次。
- 状态、上下文、额度、最近一句话都随更新带过来，不另发请求。
- 消息：小的新块直接带上；大的（长工具结果、翻页）只带“有新的”，页面自己取。草稿增量每 100ms 攒一包。
- 页面读得慢时，中间的状态直接丢掉，只送最新的。

## 推送和应用接口

- Web Push，总开关默认关；只给网页登录和主机（`/v1/internal/web/push/*`）。
- 设置里一个总开关，开了才有别的；下面是默认事件：需要你、出错、任务完成，默认都开；不单列压缩：你手动压缩完成算任务完成，自动压缩不推（2026-11-08）。网页自己不再弹通知（只留 Web Push；未读点、标题数字、图标角标照旧，2026-11-08）。工作区、文件夹、会话右键各有自己的开关（跟随上级、开、关，开时可另选事件），近的说了算（2026-11-06）。
- 应用的接口是 **Satori with ir**（`docs/satori.md`）：会话是 channel，文件夹组是 guild，登录是 login。Iridium 自己的接口在 `/v1/internal/*`（`docs/api.md`）。
- 官方应用（`ir join`、dsh 插件、QQ 桥）的安装命令在各自的文档里（`docs/exec.md`、`docs/qq.md`）；Iridium 不下载、不运行。QQ 桥要重写成 Satori 客户端，在那之前不能用（`docs/qq.md`）。

## 别的机器

- 不做节点（用户，2026-11-08）：不做两个 Iridium 之间对等互用。别的机器一律以执行端接入一个 Iridium，会话都由它托管，网页、`ir`、Bot 只连它；用哪台机器的 Claude、Codex 都在这一个 Iridium 上开。协议和做法见 `docs/exec.md`；实现有 dsh 插件和 `ir join`。
- 接入单向：那台机器跑 `ir join <地址>` 申请，这边核对配对码后允许。主机上的应用不带 Agent（主机的 agent 只归主机）。
- 第三方插件不进核心（用户，2026-11-09）：OMD（oh-my-dsh）这类 DSH Desktop 插件，Iridium 只收 dsh 插件经 `held.*` 给的通用数据（附加功能：开关、可用与否、名字、选项），不写认识它们的代码；翻译放在 dsh 插件的可选子插件里（`adapters/omd.js`），有那个插件才启用。见 `docs/exec.md`“附加功能”。
- `ir` 认位置 `应用名:路径`：`ir new <agent> <位置>`、`ir sh`、`ir cp`；列目录 `ir api internal/files path==… machine==<机器>`。`ir sh` 经执行端的 `run`，老执行端退回 hold 方式。
- 平台（用户，2026-11-08）：Linux、Mac 发布完整的 Iridium，也能 `ir join`；Windows 版不再发布，Windows 用 dsh 插件接入（`ir join` 的 Windows 代码留着，要的人自己构建）。不做代码签名和公证：命令行下载、`iridium push`、自更新都不经浏览器，不会被 Gatekeeper 拦；Mac arm64 要的 ad-hoc 签名 Go 链接时自带。Mac 上服务用 launchd，holder 各有一个监管进程（见 `deploy.md` “macOS”）。
- 用户要用的都在这一个二进制里（2026-11-06）：`iridium install`、`ir update`、`ir public`，以及 `iridium push <用户@主机>`（经 ssh 把自己装到另一个账号或机器、或换成新版）和 `iridium node new <账号>`（在本机建账号、装一个 Iridium，sudo 一次）。脚本只给从源码构建的开发者用。

## 文件传输（网页、Bot、`ir` 共用）

- 一套接口，网页上传也用它：
  - 上传：建任务 → 分块 `PUT`（带偏移）→ 查已收多少（续传）→ 完成时核对 sha256。块大小按测到的速度自动调，从 8MB 起、最多 50MB，每块约 10–20 秒。
  - 下载：支持 Range 断点续传，带 ETag（大小 + 修改时间）和 sha256。
  - 先写临时文件，核对后原子改名；默认不覆盖。
- 两种寻址：
  - **引用**：回复里出现过的文件、消息附件，给一个只对这个交互终端和会话有效的 ID。Bot 只能用引用，不能按路径。
  - **路径**：`ir` 按路径读写（本机和执行端），必须在允许的目录里。
- 路径检查：先解析符号链接再比允许的目录；Iridium 自己的状态和配置目录、`~/.ssh`、`~/.claude`、`~/.codex`、`~/.pi` 一律不给，不管允许目录怎么设。
- Bot：发消息带附件（进会话目录的 `.iridium/uploads/`）；事件里带回复的文件列表（名字、大小、类型、引用），按引用取。
- `ir`：
  - `ir cp <源> <目标>`，任一边可以是 `机器:路径`；先只做单个文件，目录以后用 tar 流。
  - `ir api message.create channel_id=<id> _data.text="…" _data.paths:='["<文件>"]'`：附件传到会话所在的机器。
  - `ir api internal/files path==<目录> machine==<机器>`：只列一层，名字、大小、时间、类型。
  - 传输由 Iridium 做，不是 `ir` 进程；`ir` 被打断后，再跑一次同样的命令从断点接着传。
  - 给人看时有进度条；agent 调用时只打一行结果（路径、大小、sha256）。
- 拷入拷出不设权限（2026-11-08）；单文件上限照旧；用量页另记每个交互终端传了多少字节。

## 弱网（照 Rhodium，一项不少）

- 首屏 gzip 后 ≤250KB（2026-11-06 用户从 200KB 提到 250KB）；对话页按需加载，有上限；`build` 测试守着大小。
- 库和我们的代码分开打包；带哈希的文件 `immutable`，HTML `no-cache`；JS/CSS 预存 brotli，JSON 走 gzip，事件流不压缩。
- 空闲后低优先级预取对话页的代码；鼠标停 0.1 秒或按下就预取那个会话；回合结束就把它的对话取好；开了省流量全都不做。
- 长工具参数和结果先给开头 2000 字，点开再取；消息每页 20 条，往回按字节读。
- 一个连接点，连上时写往返延迟；断了标出来，重连后自己补齐。有会话列表时（电脑布局）在左下角头像名字那一栏的右端，手机在对话顶栏（2026-11-08）。
- 升级时开着的页面：只在刚回前台、没有会丢的东西时刷新一次，不循环。
- 草稿存 `localStorage`；发送失败留着重试。
- 再加我们自己的：上传分块续传、缩略图、断线重连发整份状态（见“实时数据”）。

## 风格

- 简洁、轻、磨砂（只给顶栏、输入栏、弹出框、轻提示）；无强调色，标准中性色。
- 小弹出框从按钮处长出；输入框选中没有描边；键盘 Tab 才有焦点圈。
- 统一动效：弹出、收起、发送、重排；减弱动态效果时只淡入淡出。
- 会话列表是浮板（2026-11-06 试“未来简洁”）：电脑上列表一块圆角浮板、离窗口边 8px，底部“本机 + 设置”单独一小块浮在下面，靠色块分区不用线；手机上只有底部那块浮起。浮板比纸色深一档，里面留白分组，箭头单独一列，只有 agent logo 带颜色，选中只加粗。会话行两行（学 Rhodium）：名字（树里没体现目录时后面淡字标目录）；下面一行是最后一句话，你说的前面加“你：”，出错时写出错。
- 颜色标签（右键菜单底部六个色点：红橙黄绿蓝紫，没有灰）：会话的是名字上的一道荧光笔，样子像手画的荧光笔：两头毛糙、边缘起伏、中间一道压得更实、微微倾斜（2026-11-08）；行尾时间不涂；跑起来时时间在原处淡出、灯淡入，宽度不变，停下再换回来，盖住整个字高、颜色淡，打上时从左往右涂出来，去掉时收回去；文件夹的是文件夹图标染色（2026-11-06）。
- 状态灯（logo 右下角）：运行中蓝色呼吸，压缩中蓝黄渐变转动，需要你琥珀呼吸（2026-11-08），出错红，启动中绿色快呼吸，在别处运行蓝色空心环，空闲无灯；未读不画点，时间变成墨色（不出现灰色圆点，2026-11-06）。在别处运行的 Claude 等你（它在 `~/.claude/sessions/<pid>.json` 写 `status:"waiting"`）也亮琥珀，提示“在别处等你”，仍只读（2026-11-06）。
- 少写字：图标和灯代替文字，字进悬停提示和 `aria-label`。手指操作时（手机、平板、展开的折叠屏）不出悬停提示，长按只出行的菜单；会话列表、顶栏、菜单里长按不出浏览器自己的下载/打印/分享菜单（2026-11-08）。

## 更新

- Iridium 自己查新版本（GitHub Releases，或配置里的地址），默认每天一次；打开设置时上次查过超过一小时也查一次。Release 版查到就在后台下好，点“更新”只换文件重启；源码编译的不预先下载（2026-11-08）。设置里“自动更新”开关，默认开；关掉后不定时查、不预先下载，打开设置也不查，只剩“检查更新”（2026-11-10）。设置里“检查更新”是一个键：查、下载、替换、重启一次做完，不再确认（2026-11-08）。
- 有新版：设置齿轮上一个小红点；设置里写版本号和更新说明，一个“更新”键。
- 更新：下载、校验 sha256、替换二进制、重启服务；托管进程不受影响（同 Rhodium）。
- 开着的页面按“弱网”里的规则刷新到新版；在这页按的更新，新版上线就刷新。还没刷新时，连接状态那里换成“↻ 刷新”（2026-11-08）。

## 开工前

已核实（2026-11-05）：

- `claude -p` 子进程启动就写 `~/.claude/sessions/<pid>.json`（`entrypoint: sdk-cli`），环境里带拉起者的 `CLAUDE_CODE_SESSION_ID` 和 `CLAUDE_PID`。没发消息就退出：不写记录、不花额度、登记文件自己删掉。
- Rhodium 已查清（直接照用）：
  - 记录位置：Claude `~/.claude/projects/`；Codex `$CODEX_HOME/sessions/YYYY/MM/DD/`；pi `~/.pi/agent/sessions/`。
  - 追加系统提示：Claude `--append-system-prompt-file` + `--system-prompt-snapshot off`；pi `--append-system-prompt`；Codex 开线程时的 `developerInstructions`。
  - 审批：Claude `set_permission_mode`（要带 `--allow-dangerously-skip-permissions` 才能切到跳过）；Codex `approvalPolicy`；pi 没有，用 Rhodium 的审批扩展（`src/pi-approval.ts`）。
  - 用量：Claude `get_usage` 和 `result`；pi `get_session_stats`；Codex `thread/tokenUsage/updated`。
  - Codex 给子进程设 `CODEX_THREAD_ID`、`CODEX_SESSION_ID`。
  - 起 agent 前去掉继承来的 `CLAUDECODE`、`CLAUDE_CODE_*` 等变量（Rhodium `src/agents.ts` 的过滤规则）。
- Cloudflare 单个请求上限：Free、Pro 100MB，Business 200MB，Enterprise 最多 5GB。50MB 分块够用。

认拉起者再加一条：Iridium 给托管的 agent 设 `IRIDIUM_SESSION=<id>`，它拉起的任何 agent 都继承，不管是哪家（Rhodium 用 `RHODIUM_SLOT` 做同样的事）。终端里开的会话才靠各家自己的变量和父进程。
