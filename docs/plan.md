# Iridium 计划

Rhodium 的轻量 Go 版本：一个网页，管理本机 agent 的会话。先做 Linux。

## 不做

IM、Bot、终端模拟（网页终端、TUI、Herdr）、组网（Tailscale）、`rh` 命令、槽位模型、定时任务（agent 自己有）。

## 交互终端

- 一切接入方统称**交互终端**，不说“人”或“用户”。
- 两种：
  - **界面型**（网页面板，每台浏览器一个）：Passkey 登录，看得到确认面板，收 Web Push。
  - **通道型**（Bot、节点、本机 `ir`）：TOKEN 或节点密钥，走接口，用 SSE 收推送。
- 叫法（用户，2026-11-08）：拿 TOKEN 接入的程序（QQ Bot、脚本等）界面上中英文都叫 Bot，不叫插件、机器人、通道；终端类型只有“面板”“Bot”：节点、执行端也拿 TOKEN 接入，一样叫 Bot，不另设类型（用户，2026-11-08）。代码里仍是 `channel`、`plugin`。
- 每个都有唯一名字（≤12 字符，不分大小写查重，内部用固定 ID）。不再有权限表：所有终端什么都能做，Bot 和面板一样，只有 Claude 例外（用户，2026-11-08）。
- Claude 只给本人的交互终端（Claude 用户协议），只在建终端时定，之后不能开也不能关（2026-11-08）。没 Claude 的终端看得到 Claude 的会话，但不能开、发、停、答：
  - 第一个注册的网页面板默认有 Claude（就是你的）。已有数据一次性补上：有面板但都没有 Claude 时，最早注册的那个得到。
  - 之后的终端只有本人用 `--owner` 生成才有：`ir invite [名字] --owner`、`ir token <名字> --owner`（确认这是我本人用的终端），在本机跑，或在带 Claude 的面板上勾“带 Claude”。已有的 Bot 换 TOKEN 不改 Claude。
  - 没 Claude 的面板和本机网页（没配 `public.origin`）不能说 `--owner`；服务端也拒绝。agent 调用（认法同秘密：环境变量、没有终端）带 `--owner` 时改成确认，只有带 Claude 的面板（或本机 `ir`）能同意，链接和 TOKEN 照样只给点同意的面板。
  - Codex、pi、dsh 不受限，可以开给别人的终端。
- 只有界面型能批准新终端、看到 TOKEN。
- 本机 `ir` 是内置通道型终端“本机”，有 Claude；agent 调用时记在调用它的会话名下。
- 名字是来源标记，也是用量统计的单位。

## 会话

- agent：Claude、Codex、pi、dsh（DeepSeek Harness）。
- 自动发现 agent 自己起的会话（agent 记录目录、`~/.claude/sessions/`、`/proc`），不建父子关系（子代理除外，见下）。
- 没有“工作区”要先建（2026-11-08）：分组就是文件夹。会话第一次出现时归组：拉起者的组（组的文件夹包含它的目录时；子代理总跟父会话）→ 包含它目录的最深的组 → 用它自己的目录新建一个组（名字取文件夹名）。家目录和 `/` 的组只收正好在那里的会话，免得一个会话把所有项目都收进去。以前在“未归类”的会话也按这条重新归组；只剩没有目录的会话在未归类。组里没有显示的会话就不列出来（组还在，改的名字、通知设置留着）。
- 结构最多两级：组（文件夹）→ 子目录 → 会话；更深的目录不再往下嵌，写成相对路径（如 `Iridium/web`）放在子目录那一级，只有一个会话也显示（2026-11-06）；组目录下的会话直接列在组下。一个会话只属于一个组。
- 显示标记：有标记的会话才在 Iridium 里显示。Iridium 开的、或开始监视后有新动静的（新会话、旧会话有新内容）自动加上；归档 = 去掉标记，有新动静自动回来。按 agent + 会话 ID 存在 Iridium 库里，不写 agent 的文件。原有的旧会话没有标记，不显示，在会话列表底部“已归档”里，可搜索、一点恢复。不按时间自动归档，不删对话记录。
- 需要你的会话留在原位，状态灯琥珀色呼吸；不另建“需要你”组（2026-11-08）。不属于会话列表里任何会话的确认（`ir` 邀请、TOKEN 等）单独一行列在最上面。
- 在别处开着的会话只读；那边退出后可在网页接着聊。
- 子代理（Claude 的 Agent 工具子任务、Codex 的子 agent 线程）也进列表：标“子代理”，只读（只有父会话能和它说话），记着父会话、能跳回去，归父会话的工作区（2026-11-06 定，推翻原来的“算在原会话里”）。

## 运行

- 每个会话一个托管进程，只做托管，只用文件：命名管道进 stdin，stdout 追加 `out.log`，退出码写 `exit`。`systemd-run --user` 拉起，Iridium 重启不断回合。
- 托管进程和 Iridium、`ir` 是同一个二进制。
- 空闲回收同 Rhodium：默认 1 小时，配置文件/按会话可改，可关；有后台任务不回收。
- 崩溃续跑、额度续跑：默认开，配置文件可关。设置页不放这三项（用户，2026-11-07）。
- 平台相关代码单独一层，以后加 Mac。

## 数据

- 会话列表以磁盘为准；库（SQLite，纯 Go）只存：归属、置顶、显示标记（没有就是归档，见 `docs/api.md`）、改名、待发队列、推送订阅、交互终端和权限、用量、凭据（加密）。
- 历史只读 agent 自己的对话记录；托管输出只用于正在打的字、状态、提问、后台任务。
- 提问不进库，现场问 agent；不设超时。
- 配置一个文件，设置页改的就是它。

## 消息来源

- 每条交给 agent 的消息开头带 `[名字]`，只给 agent 看。
- 网页不显示前缀：服务端按 Iridium 自己写进去的输入认来源（Claude 的 uuid、Codex 的 client_id，其余比对输入记录），去掉前缀，消息块带 `from`。终端里手打的照原样。
- 前端按来源分组件（同一组件的变体）：
  - 面板发的：“你的话”气泡；来自别的面板时角上淡色设备图标。
  - 所有人发来的话（你的、别的会话的 agent、Bot、对等机器）都在右侧，和“你的话”同一边；左侧只有本会话 agent 自己说的（2026-11-06）。
  - 别的会话 `ir send`、Bot、节点发的：来信卡片（logo/图标 + 名字，可跳转），不算“你的话”。
  - Iridium 自己写的（恢复提示等）：居中一行淡字。
- 列表的“最近一句话”：只有面板发的写“你：”，来信写来源名。

## `ir`

和 Iridium 同一个二进制，经本机 unix socket（0600）走网页那套接口。

agent 用：

```
ir new <agent> [目录] "任务"   开会话，返回 ID
ir send <id> "消息"            回合进行中默认插话，--queue 排到回合结束
ir wait <id>                   等回合结束，打印最后一段回复
ir read <id> [-n 条数] [--full]  每条消息和它的最终回复，截短；默认最近 10 条，--full 整页原文
ir ls | find <词> [--all]        列会话 | 按名字、标题、目录、最后一句找
ir stop | archive | unarchive <id>
ir ws [ls] | new <目录> [--name 名] | rename <ws> <新名> | rm <ws> | mv <id> <ws>
```

- `new`、`send` 可加 `--wait`；可选 `--model`、`--approve`。`wait` 退出码：0 结束，2 需要你，1 出错/已退出。
- `ws` 只列出和改名文件夹组（`ir ws [ls] | rename <组> <新名>`，组写 ID 或名字，重名要写 ID）；组不能手建、删除、挪会话（2026-11-08）。
- 新会话进调用者的组（组的文件夹包含它的目录时），否则按目录归组。没有父子、汇报、agent 间权限。
- 不设上限：不限同时运行数、拉起数量、深度、调用频率；提示词里只写“在需要时”。
- 托管会话的系统提示（英文，每次 agent 进程启动时现写，`session.SystemPrompt`）：一句说明 Iridium 和 `ir` 是干什么的，接着直接放 `ir --help` 里“Admin”之前给 agent 用的那部分（同一份 `irhelp.Help`），管理命令只说“见 `ir --help`”；再是凭据、交文件、起标题三句，最后一句用户的语言（网页设置里选的，没选过就是那台网页自己的）。原来只写“见 ir --help”，查本机托管会话：用 `ir` 的一大半先跑一次 `ir --help`，压缩后还会再跑，还被 auto 模式拦过，所以直接写进去（用户，2026-11-08）。`ir --help` 英文，不超过 20 行。

管理交互终端：

```
ir invite [名字] [--owner]   新网页面板：带 TOKEN 的链接；--owner 带 Claude
ir invite --peer             节点邀请码；对方 ir join <码>
ir token <名字> [--owner]    Bot TOKEN；--owner 带 Claude
ir access                    列出所有交互终端、未用邀请，哪些带 Claude
ir profile <名字> [--name 新名] [--avatar 图片] [--device computer|laptop|phone|none]
ir revoke <名字>
```

凭据（见“凭据”）：

```
ir secret ls | set <名> [--note 说明] | rm <名>
ir run [--secret 名,…] -- 命令 …   {{名}}、{{file:名}} 换进参数，输出里的值打码
```

- agent 调这些命令时 TOKEN 不进对话：网页弹确认面板，同意后面板里才显示链接、二维码或邀请码，agent 只拿到结果。认 agent 调用靠环境变量和有没有终端；只防 TOKEN 进记录，挡不住故意读库。

## 接入（参考 Rhodium 网关）

- 默认只听本机，不做登录。
- 上公网可选；上公网必须开 Passkey。配了 `public.origin` 后所有网页请求都要 Passkey，回环也一样。
- 新面板：`https://<域名>/_ir/join#<token>`（10 分钟、一次性；`#` 后不进服务器日志），打开直接起名（查重）+ 注册 Passkey。
- Cookie `__Host-`、HttpOnly、SameSite=Strict；空闲 12 小时、最长 7 天。失败限速；POST 和 WebSocket 查 Origin；主机名白名单。
- 最后一个 Passkey 不能删；全丢了在本机 `ir invite` 重来。
- Iridium 不自己管 HTTPS 证书。有公网 IP 的，挂在自己的反代后面（文档给 Caddy 例子）。
- Cloudflare 只是没有公网 IP 时的 Tunnel，不用 Access。

## Cloudflare 一键上公网（`ir public`）

终端里跑，或者在本机网页的设置里点；尽量自动做到能用为止，每步要你确认的用确认面板：

1. 检查 `cloudflared`，没有就下载到 `~/.local/bin` 并校验。
2. `cloudflared tunnel login`：给出登录链接，你在 Cloudflare 上选域名（这一步由 Cloudflare 自己让你选）。没有托管在 Cloudflare 的域名就停下，说缺什么。
3. 填子域名，默认 `ir`，显示 `ir.<域名>`；已有同名记录时问要不要覆盖。
4. 建隧道 `iridium-<机器名>`，写配置：`ir.<域名>` → `http://127.0.0.1:<端口>`，其余 404。
5. 建用户级 systemd 服务跑这条隧道。不碰机器上已有的 cloudflared 和它的隧道。
6. 写 `public.origin`，打开 Passkey；从外网访问健康检查地址，等到通。
7. 生成第一个面板邀请，显示链接和二维码。

- `ir public off`：停服务、删隧道。DNS 记录 `cloudflared` 删不了，提示你去控制台删（给了 API 令牌就自动删）。
- 要实测一遍：登录拿到的凭证能管哪些域名、`route dns` 遇到已有记录怎么报。

## 确认面板

- 一套组件：选择题、计划确认、审批、`ir` 邀请和 TOKEN、节点邀请、删除确认。
- 小卡片贴在输入框上方；不属于会话的列在会话列表最上面。标题 + 一行摘要 + 主次两个键，细节点开看。
- 审批：工具名 + 参数摘要（命令等宽），允许 / 拒绝 / 本会话一直允许。
- 放行：Claude auto 模式拦下的一步（它不问，直接拒）像提问一样是输入框上方的一张卡：“auto 模式拦下了”+ 理由 + 命令，“不用了 / 放行”两个键，处理前一直在（2026-11-08，原来是对话里的一行，放行后还留着）；回合结束后有这样的卡，会话算需要你。放行：临时切到手动模式让它再做一次，同一步自动允许，这一步做完马上切回原模式（原来等回合结束，期间别的操作都要问，2026-11-08）；它没再做，就在拿到这条消息的回合结束时切回（2026-11-07）。卡只记在守护进程内存里，重启就没了。
- 默认自动审批：Claude `auto`，Codex 不询问的那档，pi 不审批（不加载审批扩展）。
- 回合在跑时打的字：默认回车直接插话（并进这一回合，这一步做完就进去），Ctrl/⌘+Enter 排到下一回合；设置“运行中按回车”可以反过来（回车排队，Ctrl/⌘+Enter 插话，同 Claude Code 的 send now）。插话的话马上作为你的淡色气泡出现，下面写“插入中”，记录里有了才变实。待发队列两条以上有“一起发送”。 `ir send` 也一样默认插话，要排队加 `--queue`（agent 之间的话多半要马上看到；2026-11-06）；agent 发的不排队，`--queue` 也插进（免得要人去点；2026-11-06）。
- 提及一个会话：在输入框里打 `@`（开头或空格后），上面列出会话（不含本会话、归档和子代理；标题开头匹配的在前，再是标题、目录、agent、id 含它的，各按最新），↑↓ 加 Enter/Tab 或点一下选中；手机电脑都能用（2026-11-06）。电脑上也可以从会话列表把一个会话拖到对话里。选中或拖进来的会话不再插成文字，而是像图片、文件那样在输入框上方成一张卡片（agent 标志、标题、agent 和短 id），点 × 或在输入框最开头按退格整张删掉（2026-11-08）；发送时它的提及排在文字前面，只写够用的信息，如 `「标题」（Claude 会话 1a2b3c4d）`，对方用 `ir send` 就能找到它（2026-11-06）。拖动时界面什么都不变。发出去的消息里画成小标签（logo + 标题），点了跳到那个会话。图片和文件上传时按原比例显示，未传完的部分盖一层半透明薄纱随进度退开，中间一个进度圈；没传完不能发送（2026-11-08）。
- 发出的话：对话整体往上推，新气泡淡入。发送中气泡左下角一个呼吸的小环，排队时是小钟；送到后什么都不标（不再闪一下绿勾，2026-11-08）。
- 审批模式能换：输入框下方不放模式键（2026-11-06），Shift+Tab 或 `/mode` 轮换并提示换到哪个，按会话记住，设置里定默认。

## 凭据

让 agent 替你用密码、API key，又不让值进对话（2026-11-06）。

- 凭据 = 名字 → 值（如 `GITHUB_TOKEN`、`NAS_PASSWORD`），带一行说明。存在库里，用状态目录里 0600 的密钥文件加密（拷走库不能用）。值只能写、不能读回，要改就整个换掉。
- 存：`ir secret set <名> [--note 说明]`。
  - 你在终端里跑：不回显地读一行；也能从管道读（读全部，去掉末尾换行，ssh 私钥也行）。
  - agent 调（认法同 `ir invite`）：不读值，在这个会话输入框上方弹确认卡（也进“需要你”）：“会话 X 要 `GITHUB_TOKEN`：推送到 kumo/foo”，一个密码框，“存 / 拒绝”。agent 等着，只拿到“已存”或“拒绝”。
  - Bot、节点：接口存（2026-11-08 起不再要权限）。
  - 网页：设置里一页“凭据”，增、换、删，看用量记录。
- 用：`ir run [--secret A,B] -- 命令 参数…`。参数里的 `{{A}}` 换成值，同时设同名环境变量；`{{file:A}}` 换成 0600 临时文件的路径，跑完删（ssh 私钥、kubeconfig）。命令的输出里出现的值（原样、base64、URL 编码）换成 `[secret:A]`，跨块也不漏；退出码照命令的。要面板确认时 `ir run` 在 stderr 说一句再等。agent 的记录里只有 `{{A}}`。
- 谁能用：每个凭据有范围（全部会话 / 某些工作区 / 只给本人终端开的会话）。默认自己面板（带 Claude 的）开的会话直接用；别的终端开的会话第一次用时弹确认卡：允许 / 本会话一直允许 / 拒绝。可单独设“每次都确认”。每次用记一条：会话、命令开头、时间。
- 兜底：网页显示对话记录前，服务端把记录里已知的值也换成 `[secret:A]`；输入框发出前看着像密钥（`sk-…`、`ghp_…`、高熵长串）时提示“存成凭据？”，点了把那段换成 `{{名}}` 再发。
- 托管会话的系统提示里（见“ir”）：要密码、API key 时让人用 `ir secret set` 在网页填，用 `ir run` 带进命令，别让人贴进对话；交文件只用 `` [文件] `绝对路径` `` 行（见“网页”）；起标题用 `[标题] …` 行（见“会话标题”）。两个标记保持中文，旧记录照认。
- 边界同 `ir invite`：只防值进记录，挡不住故意的 agent（`ir run -- sh -c 'echo $A | rev'`、直接读库）。真要防得让 Iridium 代发请求，不做。

## 网页

- 包含 Rhodium 网页全部功能（终端模拟除外）。
- 只有一种会话列表（原叫“侧栏”，界面和文档里一律叫会话列表，2026-11-06），不另做“首页列表”；主界面只有一个：对话（2026-11-06）。电脑：会话列表 + 对话，会话列表常驻不收起，可拖宽窄（220–640px，双击复原）；按窗口形状判手机，不按设备：宽于 520px 且不是竖长（高宽比不过 5:4）就是电脑，展开的折叠屏也用电脑布局；窄于 520px 或窄于 768px 又竖长的才按手机算。手机：会话列表是从底部升起的半屏面板，从输入框上面盖上去——输入框留在原处被盖住，面板升好后隐藏，只有比面板高时才沉下去（2026-11-06），不变暗，上面的对话照常可看可滚，也不跟着面板往上推（2026-11-06）；点对话区（顶栏不算，点 ⋯ 不会收回面板）或点一个会话，面板收回、输入框回来（2026-11-06）。没有左上角的键：从对话顶栏右侧 ⋯ 菜单里的“会话列表”拉出，点顶栏左边的 agent 图标也能拉出（2026-11-06），在输入框上往上滑也能拉出（整个输入框都算，包括打字的框，只要它还没长到要滚动；长按选字不算，2026-11-07）；对话停在最底部、静止半秒以上时，在对话区往上长划也能拉出：手指先走 32px 面板才动，面板跟手但慢一些，要拉出四成（约 270px）才算，快速上甩也要拉出两成多，刚滑到底的那一下、长按选字、不在底部都不算（2026-11-06）。在面板顶部（拉条和头部）往下滑或 Esc 收起：面板跟手，拉下四分之一或快速下甩就收；在那里先按住约 0.3 秒，拉条亮起（安卓上是浏览器长按震动那一下），再上下拖才是改高度，最低是初始高度，最高到顶，离初始高度或顶部很近就吸过去，拉到多高记在本机（2026-11-07）；没开对话时面板常在，占满整屏，不能改高度；搜索时面板至少升到 85%。所有底部面板（会话列表、设置）都这样，里面滚动、不显示滚动条（2026-11-07）。手机上会话列表和设置面板是同一个底部面板的两页：拉条下面一行，左边“设置 | 会话”两个标签（设置在左，同左边上滑打开设置），右边是当前页的键（会话页：新建工作区、搜索），这一行和拉条都算面板头部；左右滑（跟手）或点标签切换，两页同一个高度；从屏幕左边 1/4 处往上滑或点 ⋯ 菜单里的“设置”打开在设置页，别处往上滑在会话页；面板里不带底下的“我”那一条，也不带 Iridium 标志和名字（2026-11-08）。
- “设置”面板：原来的“个人”弹出框和设置合成一个，原叫“终端”（2026-11-07）；2026-11-08 改叫“设置”：终端在 Iridium 里指网页面板和 Bot，和里面的“终端管理”撞名。一张平铺的列表，不分组：头像和名字（改名、换头像、今天的用量）、设备标识、外观、语言、终端管理 ›、凭据 ›（这两项有管理权才有）、Web Push（开着时下面展开默认推送的事件）、追问方式（插入 / 排队，叫法同 Codex 的 Follow-up behavior：Steer / Queue，2026-11-08）、检查更新，最底下“退出此终端”，和别的项一样是一行，不做成按钮（不标红，点一次变“再点一次退出”，再点才退，2026-11-08）。不放自己的权限（终端管理里看）和新会话默认审批模式（配置文件里改，不改就用 agent 自己的），2026-11-08；有新版时更新卡在最上面。每项只有标题和控件，不写说明，不显示滚动条（2026-11-06）；没有“设置”标题，不显示版本号（2026-11-08）。电脑上从会话列表左下角的头像名字那一栏升起（那一栏就是它的键，有新版时头像上一个红点，旁边是“更新”键），宽同原来的弹出框，页面不变灰，点外面或再点那一栏收起；终端管理、凭据、用量是它里面的一页。手机上从底部升起、占满宽、默认半屏，点对话区、顶部下滑或 Esc 收起（2026-11-07）。
- 对话在最底部时，新来的东西（消息、思考、工具、流式的下一行）把对话平滑往上推，不跳；回合那一行（工具 / 三个点）一直留着位置，发消息、点出现都不挪动。
- 会话列表左下角（设置齿轮在右）：当前界面型终端的“身份”，像应用里登录的账号：头像 + 名字（例如 `kumo-m2-mac`）。点开小弹出框：换头像（上传，裁成圆形，存 128px）、改名、看本终端的权限（只读）、主题和语言、退出这个终端。只是终端，不是人。只在本机用、没开 Passkey 时名字显示“Ir”（原显示“本机”，2026-11-08；内部和消息来源仍记作本机，Ir 和本机都不能被别的终端取作名字）。
- 头像也用在别处：别的面板发来的消息角上显示它的头像；Bot、节点也可以有头像。
- 名字和头像是一个接口、一个命令：`PUT /api/me/profile`（终端改自己的，通道型用自己的 TOKEN 也行）、`PUT /api/endpoints/<id>/profile`（界面型改别人的）、`ir profile`。生成 TOKEN 时定的名字之后照样能改，照样查重。
- 通道型的头像通常由 Bot 自己上传（例如 Bot 程序启动时传 Bot 的头像），不写死。
- 头像角上只标类型：通道型一个通道小标，界面型不标。不标平台 logo（Rhodium 标的是 QQ logo）。对话里你发的话旁边你的头像，点一下弹出设置（2026-11-08）。
- 会话列表顶上只有一个“+”：新建会话，先选文件夹再选 agent（2026-11-08）；没有搜索键（2026-11-08 去掉），跳转框用快捷键开。顶上 Ir 标志和名字右边是连接点和延迟（电脑布局）。
- 新建：顶上的“+”在任意文件夹开会话；组那一行、子目录那一行右端的“+”在那里开（一直显示，不显示数量；2026-11-06）。组那一行没有展开/收起的箭头，也不留它那一列（2026-11-08）：最左边一个和子目录一样大的文件夹（随展开收起开合），和顶上的 Ir 标志对齐，名字和“Iridium”对齐，下面的会话和子目录往里缩（2026-11-08；之前试过更大的文件夹、贴创建者头像，都撤了）。折叠、展开只由你点，新建会话不会让组收起来。
  - 文件夹选择器只有：顶上路径（每段能点；点当前那段就能直接输入路径，没有单独的铅笔键，2026-11-08）、只列文件夹（不列文件、不列隐藏目录、不写多余信息）、“新建文件夹”（列表里直接出一个输入框）、一个“选择”。
  - 新会话 = 选 agent（logo），目录默认是组的文件夹（要子目录就用同一个选择器），然后直接进对话，光标在输入框。新会话（网页、`ir new`、Bot 开的都算）的名字是第一条消息的开头；发消息前先用文件夹名占位，列表里（不算已归档的）已有同名的就往后编号：`Iridium`、`Iridium 2`……（2026-11-06）。改过的名字不会被替换；`/clear` 开的新会话接着用旧会话改过的名字，没改过就重新占位。从别的会话里开的（`ir new`）记下是谁开的。
- 组右键/长按：改名（就地输入）、复制路径、收起展开、通知（推送开着时）；没有删除（2026-11-08）。“未归类”只有通知（2026-11-07）。会话菜单里没有“移到工作区”。
- 会话标题（用户，2026-11-08）：会话列表一个会话只有一行：名字（组看不出时带目录）、多久前、灯。名字依次取：你起的名 > agent 最近一行 `[标题] …`（只认 agent 的回复、代码块外，去引号和句尾标点，最多约 24 个汉字宽）> 第一句话开头 > 文件夹名占位。那一行从正文、最后一句、推送和 Bot 的回复里拿掉；流式输出时也不画（打到一半的 `[标` 也先不画），落定时对话不缩一行。只有托管会话拿到这句提示；`/clear` 只把你起的名传下去。改提示后，正在跑的 agent 进程不变，下次启动才读新提示，那一回合缓存从头写一次。
- 回复里交文件只有一种写法（用户，2026-11-06）：单独一行 `` [文件] `绝对路径` ``，系统提示里告诉 agent。图片缩略图（约 1024px，点开原图），其余下载卡片，视频音频直接放；那一行从正文里拿掉。提到路径、链接、`![]()` 都只是文字，不出卡片；agent 转述的 `[附件]` 行也不算。只给对话里出现过的路径发链接。
- 上传：分块（50MB/块，可续传），单文件默认 2GB，可调；放工作目录 `.iridium/uploads/`（内含只写 `*` 的 `.gitignore`），写不进时放状态目录；默认 30 天清理。
- 命令（输入框打 `/`）：每种 agent 都有 `/clear`、`/compact`、`/context`、`/model`、`/mode`（有额度的加 `/usage`，有思考强度的加 `/effort`），再接 agent 自己的（Claude 握手报的那些）。`/model`、`/effort`、`/mode`、`/usage`、`/context`、`/stop` 打开网页自己的键；`/compact` 交给 agent（Codex 走 `thread/compact/start`，pi 走 `compact`）；命令在回合中不插话，排到回合结束。`/clear` 由 Iridium 做（2026-11-06）：同一工作区、目录、agent、模型、模式、强度开一个新会话并跳过去，旧的空闲时归档（可在“已归档”找回），还在跑就让它跑完。不交给 Claude：它会换一个会话 ID 接着写，Iridium 看不见。/clear 还是到了 Claude 手里（终端里打的，或别的路）：它在同一个进程里换成新 ID，Iridium 等它空下来就停掉进程、旧会话归档（`--resume` 回来还是 /clear 之前的样子），把新 ID 接成托管会话（设置、工作区照旧），开着的页面跟过去（`next`）。守护进程重启时重放到这一步也一样处理。
- 输入框下方一行：模型、额度条，上下文小环靠右。从输入框半腰往下垫一层纸色，滚到底下的对话文字止于此，不和这一行重叠。输入框里只有附件、文字、发送键，上下对齐。发送键是圆角正方形，和附件键的图标差不多大（2026-11-08）。
- 模型键：写具体的模型（默认时也写，例如 Opus 5.5）和在用的思考强度，开了 UltraCode 加个小标。点开是模型列表，选了就收起；底下是强度滑条（像 Codex 的，按档吸附，能拖、能点档名、能用方向键）和 UltraCode 开关（只 Claude），调这两样面板不收（用户，2026-11-06）。
- 上下文小窗：模型后面一个小环，写用了多少；点开是分项占用的条形图（系统提示、工具、MCP、记忆文件、消息、空余、压缩预留），类似 Cursor 以前的。Claude 用 `get_context_usage`，回合结束、压缩后，以及回合中调用工具时（最多 30 秒一次）更新；Codex、pi 只有总数。
- 额度条：输入框下方那一行、模型键之后，有几条额度放几条（例如 Claude 的 5 小时、7 天、7 天 Fable；Codex 的两个窗口）。短条加百分比，快满变色；点开弹窗（像 Claude Code 的 /usage）列出每个窗口的名字、进度条、百分比和重置时间，以及账号和读取时间。按 agent 和登录的账号认（来自 agent 报的账号和套餐），都显示，设置里不再能隐藏（2026-11-06）。没有进程在跑时显示上次的值并变淡。
- 中英双语：跟浏览器，可改；自写 `t()`，`zh.ts` 为准，`en.ts` 键必须一致；排版按英文长度。

## 实时数据（携带）

- 每个页面一条事件流，开流时说明订阅了什么：列表、打开的会话、它的上下文、额度。换了打开的会话就重新订阅。
- 订阅的东西都是小状态。开流（含断线重连）先发一份完整的，之后变了就发新的整份，不发补丁；同一样东西 250ms 内只发最后一次。
- 状态、上下文、额度、最近一句话都随更新带过来，不另发请求。
- 消息：小的新块直接带上；大的（长工具结果、翻页）只带“有新的”，页面自己取。草稿增量每 100ms 攒一包。
- 页面读得慢时，中间的状态直接丢掉，只送最新的。

## 推送和 Bot 接口

- Web Push，总开关默认关。
- 设置里一个总开关，开了才有别的；下面是默认事件：需要你、出错、任务完成，默认都开；不单列压缩：你手动压缩完成算任务完成，自动压缩不推（2026-11-08）。网页自己不再弹通知（原来的“跑完提醒”去掉，只留 Web Push；未读点、标题数字、图标角标照旧，2026-11-08）。工作区、文件夹、会话右键各有自己的开关（跟随上级、开、关，开时可另选事件），近的说了算（2026-11-06）。
- 不内置 Bot。Bot 用 TOKEN，接口是 `ir` 那一套的 HTTPS 版，再加下面的“聊天”一层。

## Bot 接入

- **聊天键**：Bot 给每个聊天窗口一个自己定的字符串（例如 `qq:private:123`）。Iridium 按“Bot + 聊天键”记一个指针：当前会话，和 `/new` 用的默认 agent、目录。Bot 不用自己存绑定。
- **发送者**：每条消息可带发送者名字，来源标记写成 `[QQ·张三]`。
- **收消息**：`POST /api/chat/<键>/input`，带文字和附件引用。
  - 不以 `/` 开头：交给指针指着的会话；没有指针（或会话没了）时不自动开，回一张选会话的卡片（没有会话就提示 `/new`），消息不发（用户，2026-11-08：没有槽位兜底）。
  - 以 `/` 开头：先看是不是 Iridium 命令，不是就原样交给 agent（透传）。
- **收文件**：小于 50MB 一次 `PUT`，大的走分块；返回引用，随消息带上。文件进会话目录的 `.iridium/uploads/`。
- **命令**（Iridium 统一处理，Bot 不用自己实现）：`/new [agent] [目录]`、`/use`（列会话选一个）、`/ls`、`/stop`、`/model`、`/mode`（审批模式）、`/status`、`/usage`、`/context`。`GET /api/chat/<键>/commands` 给当前 agent 能用的命令列表，Bot 拿去设平台菜单。
- **卡片**：要选的、要确认的、提问和审批，都返回同一种卡片：标题、几行摘要、选项（id、文字、主次）。和网页确认面板同一个数据模型。Bot 画成按钮或编号，选了调 `POST /api/answer`。
- **发回去**：`GET /api/events`（SSE），只推这个 Bot 的聊天相关的事件：
  - `progress`：过程文字（攒过的，Bot 决定编辑一条还是追加）。
  - `reply`：最终回复，`markdown` 和去掉标记的 `text` 各一份，附文件列表（名字、大小、类型、引用，图片另带缩略图引用）。
  - `card`、`card_done`：提问出现、已在别处答了。
  - `error`、`status`。
  - 每条事件有序号，Bot 断线后带 `Last-Event-ID` 接着收；未收的保留 24 小时。这是唯一存进库的事件，网页那边照旧只发整份状态。
- **长文本切分、平台格式**：Bot 自己做，Iridium 不管。
- Bot 和面板一样什么都能做，只有 Claude 看它建的时候是不是本人的（2026-11-08）。
- **Claude 规则**：Bot 用 `ir token <名字> --owner` 拿的 TOKEN 才有 Claude，等于声明它只转你本人的消息。群聊、别人的私聊要用另一个不带 `--owner` 的 TOKEN。同一个 Bot 程序可以拿两个 TOKEN。
- 给一个最小的示例 Bot（约 100 行）。

## 官方 Bot：QQ Bot（用户，2026-11-08）

- 不内置：`iridium-qq` 是同一个 Release 里的另一个二进制，默认不下载。Iridium 不认识 QQ，只认识“官方 Bot”这个名单。
- 网页：设置 → 终端管理 → 右上角 +，最下面一项“QQ Bot”，标“官方”。点进去：安装（下同版本的二进制，放在 Iridium 旁边，`ir` 旁边放个链接）、绑定（页面上直接出二维码，下面只有“在手机 QQ 中打开”和“取消”）、服务开关、Bot 那一行的“绑定”（换 Bot）、移除（点了就移除）。不显示版本号，不轮询出刷新圈（进行中 1.5 秒、平时 10 秒，悄悄刷）。设置弹窗进终端管理、凭据时保持设置页的高度，里面滚动（2026-11-08）。装了以后终端管理里多一个“扩展”分组。
- agent：`ir help` 一行提到它。`iridium-qq setup` 没有终端时打印二维码图片路径和链接后退出（码 2），agent 用 `[文件]` 行把图给用户，扫完再跑一次；TOKEN 用 `ir token --into` 直接写进它的目录，网页面板确认，agent 看不到。
- 进程：systemd 用户单元 `iridium-qq`，自己常驻，Iridium 重启、更新不断它；Iridium 更新后把它换成同版本并重启。
- 一个 Bot 只能有一条网关连接：和 rh 不能共用同一个 Bot，扫码时选“创建新机器人”。
- 第一版只做私聊、只转本人的 QQ 号（扫码人，自动记下，界面上不出现“主人”）；会话照网页的逻辑选：先文件夹，再会话或新建（选 agent）；没选会话的消息不发；网页会话列表里 Bot 所在的会话标 Bot 头像和“Bot”；群聊以后用另一个不带 Claude 的 TOKEN。细节见 `docs/qq.md`。

## 节点

- 任意一方 `ir invite --peer`，对方 `ir join` 并确认，双方对等。
- 能用对方的 `ir` 和基本文件操作：`ir new codex mac:~/dir "…"`、`ir send mac/<id>`、`ir cp a mac:~/b`、`ir files mac:~/dir`。不删不改名。
- 节点是通道型交互终端，同样不设权限（2026-11-08）。
- 双方直接 HTTPS（签名请求）；没有公网地址的一方以后用出站 WebSocket。
- 不做网页上的汇总视图。
- 执行端（2026-11-08）：不装 Iridium 的机器（Windows、Mac）跑一个执行端，替这边启动 agent 进程、转发输入输出、读写文件，会话由这边托管、驱动照旧。协议和做法见 `docs/exec.md`；第一个实现是 dsh 插件。
- 用户要用的都在这一个二进制里（2026-11-06）：`iridium install`、`ir update`、`ir public`，以及 `iridium push <用户@主机>`（经 ssh 把自己装到另一个账号或机器、或换成新版）和 `iridium node new <账号>`（在本机建账号做成节点，sudo 一次）。脚本只给从源码构建的开发者用。

## 文件传输（网页、Bot、节点共用）

- 一套接口，网页上传也用它：
  - 上传：建任务 → 分块 `PUT`（带偏移）→ 查已收多少（续传）→ 完成时核对 sha256。块大小按测到的速度自动调，从 8MB 起、最多 50MB，每块约 10–20 秒。
  - 下载：支持 Range 断点续传，带 ETag（大小 + 修改时间）和 sha256。
  - 先写临时文件，核对后原子改名；默认不覆盖。
- 两种寻址：
  - **引用**：回复里出现过的文件、消息附件，给一个只对这个交互终端和会话有效的 ID。Bot 只能用引用，不能按路径。
  - **路径**：节点按路径读写，必须在允许的目录里。
- 路径检查：先解析符号链接再比允许的目录；Iridium 自己的状态和配置目录、`~/.ssh`、`~/.claude`、`~/.codex`、`~/.pi` 一律不给，不管允许目录怎么设。
- Bot：发消息带附件（进会话目录的 `.iridium/uploads/`）；事件里带回复的文件列表（名字、大小、类型、引用），按引用取。
- 节点（`ir`）：
  - `ir cp <源> <目标>`，任一边可以是 `机器:路径`；先只做单个文件，目录以后用 tar 流。
  - `ir send <id> "…" -a <文件>`：附件传到会话所在的机器。
  - `ir files 机器:目录`：只列一层，名字、大小、时间、类型。
  - 传输由 Iridium 做，不是 `ir` 进程；`ir` 被打断后，再跑一次同样的命令从断点接着传。
  - 给人看时有进度条；agent 调用时只打一行结果（路径、大小、sha256）。
- 拷入拷出不设权限（2026-11-08）；单文件上限照旧；用量页另记每个交互终端传了多少字节。

## 弱网（照 Rhodium，一项不少）

- 首屏 gzip 后 ≤250KB（2026-11-06 用户从 200KB 提到 250KB）；对话页按需加载，有上限；`build` 测试守着大小。
- 库和我们的代码分开打包；带哈希的文件 `immutable`，HTML `no-cache`；JS/CSS 预存 brotli，JSON 走 gzip，事件流不压缩。
- 空闲后低优先级预取对话页的代码；鼠标停 0.1 秒或按下就预取那个会话；回合结束就把它的对话取好；开了省流量全都不做。
- 长工具参数和结果先给开头 2000 字，点开再取；消息每页 20 条，往回按字节读。
- 一个连接点，连上时写往返延迟；断了标出来，重连后自己补齐。有会话列表时（电脑布局）在左下角头像名字那一栏的右端，手机在对话顶栏（2026-11-08）。
- 升级时开着的页面：只在刚回前台、没有会丢的东西时刷新一次，不循环。
- 草稿存 `localStorage`；发送失败留着重试。
- 再加我们自己的：上传分块续传、缩略图、断线重连发整份状态（见“实时数据”）。

## 更新

- Iridium 自己查新版本（GitHub Releases，或配置里的地址），默认每天一次；打开设置时上次查过超过一小时也查一次。Release 版查到就在后台下好，点“更新”只换文件重启；源码编译的不预先下载，没有开关（2026-11-08）。设置里“检查更新”是一个键：查、下载、替换、重启一次做完，不再确认（2026-11-08）。
- 有新版：设置齿轮上一个小红点；设置里写版本号和更新说明，一个“更新”键。
- 更新：下载、校验 sha256、替换二进制、重启服务；托管进程不受影响（同 Rhodium）。
- 开着的页面按“弱网”里的规则刷新到新版；在这页按的更新，新版上线就刷新。还没刷新时，连接状态那里换成“↻ 刷新”（2026-11-08）。
