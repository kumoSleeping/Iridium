# 术语表

`k_` 开头的文档：每个字都对过代码。新定的、代码里还没有的标“（未实现）”；改了叫法的写“代码里：…”。

## 叫法

- 平时直接叫名字（主机、网页、otae、QQ、home-pc），名字后面不加类别词。类别词只用在标题和说明句里。
- 协议叫 **Satori with ir**：照 Satori 的概念和英文名，加上我们自己的部分（用户，2026-11-10）。英文标识符照 Satori：`login`、`channel`、`guild`、`user`、`message`；中文照下表。我们自己有、Satori 没有的，用自己的名字（主机、需要、分享、位置）。

| 中文 | 协议里 | 是什么 |
| --- | --- | --- |
| 应用 | 应用（app） | 凭 TOKEN 接进来的一个程序：网页、QQ 桥、dsh 插件 |
| 登录 | `login` | 应用下面谁在说话：一个浏览器、一个 QQ 私聊、一个 QQ 群 |
| 会话 | `channel` | 和一个 agent 的一段对话 |
| 组 | `guild` | 一个文件夹，下面是一堆会话 |
| 用户 | `user` | agent，以及说话的人 |

## 应用

- **应用**（app）：接到 Iridium 上的一个程序，凭 TOKEN 访问；有名字、头像、用量、权限，下面有登录。管理页叫“应用管理”，新加一个叫“新建应用”。代码里：终端（`gate.Endpoint`、`api.Terminal`；类型 `panel`、`channel`）（未实现：改名，不分类型）。
- **应用的类型**：Bot、脚本、面板、电脑……只用来显示，不影响权限。代码里：只有 `panel`、`channel` 两种，决定权限（未实现）。
- **主机**（host）：Iridium 所在的那台电脑，是中心，不算应用，在应用管理里和应用列在一起但不可被管理。带这台电脑上的 agent。代码里：本机（`gate.LocalEndpointID`，名字“本机”），现在只代表 socket 上的 `ir`（未实现：改名、带 Agent）。
- **网页**（ir_web）：内置的应用，不带 Agent，可以关。代码里：每个浏览器各是一个终端（未实现）。
- **登录**（login）：应用下面谁在说话，有自己的用量和权限。网页的一个浏览器，QQ 的一个私聊或群。ID 和显示名由应用定，Iridium 只校验同一应用里不重复、字数上限，重复就拒绝。新登录要在 Iridium 批准，权限默认等于所属应用；权限（用哪些 Agent、文件夹范围、管理）只能比所属应用的小，请求按登录的权限检查；应用在一个登录里再分不同的人，Iridium 不管。代码里：聊天键（`/api/chat/{key}`），只有 Bot 有，不用批准（未实现）。
- ~~**指针**~~：砍掉，Iridium 不记登录指着哪个会话，当前会话由应用自己记。代码里：`chat_pointers` 表（未实现：删）。
- **链路**（link）：网络层的一条 WebSocket；一个应用可以同时有几条（未实现：现在是 SSE 和 `/api/exec`）。

## 能力和权限

- **带 Agent**：应用连上时报了自己这台机器上的 agent；主机的由 Iridium 自己报。不想启用的，由有管理的在批准时或应用管理里勾掉。代码里：执行端 `hello` 的 `agents`；`ir join --no-agents`（未实现：删）。
- **用 Agent**：能使用哪些 agent，权限第一项（未实现：现在只有“带 Claude”一项）。
- **文件夹范围**：能用哪些文件夹，按位置写，可以跨应用，权限第二项（未实现）。
- **管理**（admin）：权限第三项，第二阶段再定（kumo，2026-11-10），见 `draft.md` 七。第一阶段申请由主机和网页批。
- 权限就这三项，不设 scope。想要的权限写在配对申请里，批准时只能少给；之后改是一条“应用变更”申请。
- **主机上的应用**：不能带 Agent，主机的 agent 只归主机（未实现）。

## 位置

- **位置**：`应用名:路径`，主机的写 `host:路径` 或 `主机:路径`（保留名，应用不能起）；按第一个冒号拆，前缀按名字查。代码里：`机器:路径`（`internal/cli/client.go` 的 `peerPath`，只认 ASCII）。
- **不带前缀**：只是输入的简写，指调用者自己所在的地方；系统给出的路径一律带前缀（未实现）。

## 接入

- **配对**：应用不带 TOKEN 发申请，网页核对配对码后允许，TOKEN 只给申请方。代码里：`POST /api/pair`、`POST /api/exec/pair`。
- **更新配对**：已有同名应用时，配对申请可以更新它：同一个应用换新 TOKEN，旧的作废，用量、权限照旧。代码里：替换（`ConfirmAnswer.replace`，卡片上“替换原有的”）（未实现：改名）。
- **会话 TOKEN**：Iridium 给带 Agent 的应用上每个会话发的 TOKEN，前缀 `irs_`，那边的 `ir` 用它代这个会话说话；权限按所在应用，再不超过这个回合的发起登录。代码里：`session.IRTokenPrefix`。
- **收录**：Iridium 列出的官方应用：名字、类型、安装命令（未实现：现在是 `/api/extensions`，会下载和管理）。

## 订阅

- 不做存在 Iridium 里的订阅（kumo，2026-11-10）：登录看得见的会话，事件都推，应用自己挑。
- **全局状态**：整份推送，按链路要：内容、布局、资源、管理四组。代码里：`internal/hub` 的携带状态，`?sub=`。
- **正在看**：草稿、会话整份状态、上下文量大，只推给说了“正在看这个会话”的链路；临时的，不存库，重连再说。代码里：`?sub=session:<id>`、`context:<id>`。
- **分享**（share）：把会话、一条回复、位置或文件分享给某个登录，带谁分享的和一句留言；Iridium 检查对方能用分享的东西，收到怎么办由应用定。代码里：网页“拉进会话”（`Bring`，直接改指针）（未实现）。
- **需要**（need）：等一个人做决定的事：会话的提问、审批、计划，以及申请（应用接入、应用变更、登录加入）。申请送给所有登录，批要有管理；会话的提问、审批、计划送给能用这个会话的登录，带发起登录，应用自己挑显示哪些（未实现：现在提问按跟随规则送达，申请在 `confirms`，网页上叫“需要你”）。

## 会话

- **send**：`ir send <目标> "消息"`，目标是会话（发进去，agent 接着干）或登录（`应用/登录`，只显示，不叫起 agent）。送不送得到由 Iridium 判断：对方在线、能用发出它的会话，否则报错；显不显示由应用定。应用和登录的列表公开，agent 自己查。没有“发给用户”这种特殊目标（未实现：现在发给应用是 `ir bot`，没指定时按跟随挑）。
- **会话**（channel）：和一个 agent 的一段对话。
- **托管**：会话由 Iridium 启动的 agent 进程运行；只有托管的会话发事件。
- **hold**：给每个 agent 进程配的看管进程，Iridium 重启不打断回合。代码里：`internal/hold`，`iridium hold`。
- **回合**：从发出一条消息到 agent 回复完。
- **续传**：链路断了重连，带上次的 `sn` 补收事件。Satori 文档叫“会话恢复”，我们不这么叫。
- **@**：引用一个东西，不送达、不通知；不转成 Satori 的 `<at>`。
