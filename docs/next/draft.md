# 改版计划：Bot 规范

kumo 和这个终端 2026-11-10 定下的。两个大方向：**合并我们自己的逻辑**、**并入 Satori 协议**（协议叫 Satori with ir）。叫法见 `k_glossary.md`。还没实现；做的时候一次切换，不留旧接口，版本号跳（如 0.2），不在这台机器上做。

## 一、模型

| 中文 | 协议里 | 是什么 |
| --- | --- | --- |
| 主机 | host | Iridium 所在的电脑，中心，不算应用，不可被管理；带这台电脑上的 agent |
| 应用 | 应用（app） | 凭 TOKEN 接进来的程序：网页、QQ 桥、dsh 插件、脚本 |
| 登录 | `login` | 应用下面谁在说话：一个浏览器、一个 QQ 私聊、一个 QQ 群 |
| 会话 | `channel` | 和一个 agent 的一段对话 |
| 组 | `guild` | 一个文件夹，下面是一堆会话 |
| 用户 | `user` | agent，以及说话的人 |

- 应用一视同仁，类型（Bot、脚本、面板、电脑）只用来显示。网页（ir_web）是内置的应用，可以关。
- 登录：ID 和显示名由应用定（如 QQ 用 openid），Iridium 只校验同一应用里不重复（重复就拒绝）、字数上限、不含 `/`。网页一个浏览器（几个标签页合在一起）是一个登录。应用在一个登录里再分人，Iridium 不管。
- 位置：`应用名:路径`，主机写 `host:` 或 `主机:`（保留名）；按第一个冒号拆，前缀按名字查；输出一律带前缀，输入不带前缀指调用者自己那台。单个英文字母不能当应用名。
- 网络层一条 WebSocket 叫链路。

## 二、合并我们自己的逻辑

**接入**
- 配对：平时不收申请（403）；应用管理里“新建应用”开放 10 分钟，可提前关。只留每来源 4 个待批、全部 20 个（来源 = IP，IPv6 按 /64）。`ir pair` 遇到没开放就等着重试。执行端和 Bot 的配对口合成一个。
- 重名不再自动加后缀：卡片上选“更新配对”（同一个应用换 TOKEN）或拒绝。
- 配对申请里带想要的权限，批准时只能少给。之后要改是一条“应用变更”申请。
- 新登录第一次出现产生“登录加入申请”，批准前它说什么都不进会话；权限默认等于所属应用。移除登录：之后它再说话重新申请；不活跃不自动删，只显示最后活动时间。
- 网页的邀请：先建一个已批准的登录空位（权限设好），新浏览器打开链接注册 passkey 占上。
- 官方应用只做收录：名字、说明、各系统的安装命令（可复制，dsh 插件的也在），写死在代码里。不下载、不安装、不管进程。QQ 桥和别的应用一样配对，不作特化；自己更新；被删收到 401 就删掉自己的 TOKEN、重新申请。

**带 Agent**
- 应用连上时第一帧报这台机器的情况：系统、家目录、有哪些 agent、开不开命令行（主人的开关，默认关）。不再有“声明”这个概念。
- 报上来的 agent，不想启用的在应用管理里勾掉；删 `ir join --no-agents`。只做命令行的机器 = agent 全勾掉、命令行开着。
- 主机上的应用不能带 Agent（按电脑标识认，只防误操作）。
- “机器”“执行端”不再单独成为概念：`machines` 并进应用；`ir new --machine` 由位置前缀取代（`ir new codex 主机:~/ir "任务"`）。

**权限**（三项，不设 scope）
1. 用哪些 Agent（取代“带 Claude”；勾 Claude 时提示条款只给本人用）。
2. 文件夹范围（按位置写，可跨应用；带 Agent 的应用默认有自己的家目录）：范围外看不到也不能做；不是沙箱；收窄后跑着的会话不停。共享布局（颜色、排序、置顶）范围内谁都能改。`root` 为空的便签只有范围是全部的看得到。
3. 管理：**第二阶段再定**（见七）。
- 登录的权限只能比应用的小，请求按登录查。每个接口按它涉及的会话或位置查 Agent 和范围；归档、改名也一样（Claude 会话随之受保护）。
- agent 用会话 TOKEN 跑的 `ir`：按所在应用的权限，再不超过这个回合的发起登录。
- 凭据接口（列、设、删、用）只有主机能用。

**推送**（不做存在 Iridium 里的订阅）
- 登录看得见的会话（按权限），事件都推，显示哪些由应用自己挑。事件带这个回合的发起登录，应用据此过滤（如 QQ 群只显示自己发起的）。
- 量大的（草稿、会话整份状态、上下文）只推给说了“正在看这个会话”的链路；临时的，不存库，重连再说。全局状态（列表、便签、布局、用量等）也按链路要。
- 砍掉指针：Iridium 不记登录在哪个会话，当前会话由应用自己记。

**消息**
- `ir bot` 并进 `ir send`：目标是会话，或登录（`应用/登录`，只显示，不叫起 agent）。没有“发给用户”这种目标；应用和登录的列表公开，agent 自己查，不做绑定。送不到（不在线、用不了这个会话）就报错说明原因。
- “需要”：等人做决定的事（会话的提问、审批、计划，以及申请），一个队列。
- 分享（share）：把会话、一条回复、位置或文件分享给某个登录，带谁分享的和一句留言；Iridium 检查对方能用，收到怎么办由应用定（如 QQ 私聊切过去）。取代网页“拉进会话”“切到此会话”。
- @ 只是引用，不送达、不通知。
- 不做 `done`；Web Push 归网页自己。
- 斜杠命令由应用翻译成普通接口；Iridium 补一个“agent 自带命令”列表接口。

**远端执行命令**（只给 agent）
- `ir sh` 改走执行端协议的 `run`：不走 hold，边跑边推回，每条命令一个新进程，去掉轮询。
- `--no-shell`、`--agent-shell` 合成 `--shell`。主机会话的网页 `$` 先不管。

**要删的**
`/api/extensions` 全部、`/api/bot`、`/api/chat/*` 整个聊天层（指针、跟随、letter、`Bring`）、`/api/push/*`、`GET /api/machines`、`GET /api/shell/{run}` 轮询、跟随和绑定、`--no-agents`。改资料的两个路径合一，`POST /api/answer` 并进 `/sessions/{id}/answer`。

## 三、并入 Satori 协议（Satori with ir）

- 一个 WebSocket 入口，信令照 Satori：`op` EVENT 0、PING 1、PONG 2、IDENTIFY 3、READY 4、META 5；IDENTIFY 带 TOKEN 和上次的 `sn` 续传；READY 回登录列表；心跳 10 秒。我们多的东西（这台机器的情况、“正在看”等）作为额外字段，Satori 应用不认就忽略。
- 一个应用代表多个登录，请求头选这次以哪个登录说话（同 Satori 的 `Satori-Platform`、`Satori-User-ID`）。
- 聊天那部分照 Satori 标准：`message.create/get/list`、`channel.*`、`login.get`、`user.get`、`upload.create`、代理路由、`meta`；事件 `message-created/updated`、`interaction/button`、`channel-*`、`login-*`。只转发到原有逻辑，估计 800–1,200 行加测试（依据：`internal/chat` 加 `routes_plugin.go` 约 2,300 行，去掉指针、命令、跟随、目录选择）。其余照旧是我们自己的接口。
- 借的做法：消息元素；资源用 `internal:` 这类不绑地址的引用，经代理取；`pick` 卡片改成按钮（`interaction/button`），存库 24 小时；来源标记 `login`、`user`、`channel` 提到顶层；接口只回直接结果，其余走事件；历史分页用 `BidiList`；`status`、`progress` 没人用就删。
- 对不上的地方：
  - @ 不转成 `<at>`（会真的提醒人）：会话用 `<sharp>`，位置、文件用 `<a>` 或 `<ir:ref>`。
  - `login.user.id` 就是登录本来的 ID（`应用/登录`），不另发。Satori 应用不能让新登录出现，只能用管理端预先建好的。
  - Satori 应用只能发进会话，不能 send 给别的登录，也收不到 share。
  - 404 留给 Satori（接口不存在）；资源不存在回 422，带原因码（如 `no_such_session`）。
  - 发起登录是 Iridium 内部记的，不叫 `referrer`。
  - “会话恢复”我们叫续传。
- 执行端那条链路（`hold.*`、`fs.*`、`run`、dsh 的 `held.*`、`dsh.*`）不算 Satori with ir，是单独的内部协议。
- 参考：Satori 规范在 GitHub `satorijs/docs`（satori.js.org 已是占位页）。

## 四、网页

- 应用管理（原“终端管理”）：主机、网页和别的应用一个列表，主机不可被管理。每行头像、名字、类型、在线、最后活动；带 Agent 的再显示 agent 和系统。“新建应用”：开放配对 10 分钟 + 收录的安装命令 + `ir pair`。
- 应用详情：权限（Agent、范围）、带的 agent 开关、命令行开关（只显示）、登录列表（改权限、移除）、改名头像、删除。
- “需要”：会话的提问、审批、计划，应用接入（配对码、系统、程序、agent、要的权限可划掉、更新配对）、应用变更（多要少要了什么）、登录加入。
- 分享：会话、回复、文件、位置的菜单里“分享到 ▸”，列能用的应用，再展开到登录。

## 六、代码里已知的问题（顺手修）

- `pick` 卡片只在内存里，重启后补发来的点了回 410（按三里的按钮存库解决）。
- 命令结果一部分同步回、一部分走事件流（按三里的“接口只回直接结果”解决）。

## 七、第二阶段：管理

- 管理是权限第三项，一个开关：看应用的管理信息、新建删除应用、改权限、批申请、改设置、开公网、更新。主机始终有，是第一个管理者；不能撤掉最后一个；agent 不直接行使，要做就变成一条“需要”。第三方面板在配对申请里要。
- 在 Satori 里：管理接口放 `/v1/meta/*`（管 Iridium 本身），但要带登录；有没有管理写在 `login.features` 里；没有回 403。
- 第一阶段先照现在：申请由主机和网页批。
