# 前端改版：定下的事

2026-11-24，kumo 在频道 `bc0814e3` 里定的。范围不只是前端：第 2 节要改服务端和 Satori 这一层。本文是规格，还没有动代码。标“未验证”的是读代码或查资料得出、没有实际跑过的。

## 1. 硬规则（kumo，2026-11-24）

1. **频道里只有消息。** 对话里的每一行对应一条有编号的消息，没有别的来源。“频道是给大家发消息的”“消息就是消息”。
2. **干活的东西默认安静，最多一行，高度固定。** 只有人点了，才展开详细信息；展开在弹出的地方，对话的高度不因此变。
3. **没发消息的不占行。** 子代理、被停掉的、会话状态本身，都不在对话里出现，更不在最底下。
4. **在干活的容器不自己变大变小。**
5. **新的头像和消息只在 `message-created` 时出现。** 同一个发送者连续几条、中间没有别人的消息，共用一个头像。
6. **已画的不换位**（此前定的，保留）：新来的只排在最下面。
7. **agent 正在写的话**（方案乙）：开始写时发 `message-created`，写的过程用 `message-updated` 更新，写完再更新一次。头像在它真的开口时出现，高度只在最末一条增长。

## 2. 协议（按 IM 的做法，前端照它绑定）

现状和为什么要改见第 5 节。

| 事 | 现在 | 改成 |
|---|---|---|
| agent 说一段话 | 服务端扣着，等它下一个动作才发 `message-created`（`internal/satori/events.go` `hear`、`flush`） | 这段话开始时给编号、发 `message-created`（`_data.writing: true`）；写的过程发 `message-updated`，内容是整份，至多 100ms 一次；写完发一次不带 `writing` 的，带上 `block` 和活动计数 |
| 回合最后一句 | 靠扣着来判断 `progress` 还是 `reply` | 回合结束时给最后那条发 `message-updated`，`_data.final: true` |
| 频道消息和 agent 记录认作同一条 | 比文字（`channel.go` `syncSaid`、`Heard`：最近 8 条里比，等 100、200ms 重读，至多三次） | 服务端自己记“这一回合第几段话 ↔ 哪个编号”，按次序对上，不比文字。各种 agent 的记录是否都能按次序对，未验证 |
| 人发的话 | 事件的 `_data.input` 已经带着输入的 ID；前端在拿到编号前仍按文字加 120 秒去对 | 前端自己生成 `input`，只按它对；不比文字 |
| 提问、审批 | `message-updated` 前端没处理，卡片的 ID 被丢掉后靠重新拉取 | 前端处理 `message-updated`；卡片是一条普通消息 |
| agent 干的活 | 读记录时数出来，挂在它**下一句**话上（`<iridium:activity>`）；正在干的由前端读会话状态和记录另画一行 | 记在它**上一句**话上：那条消息里一个元素，每一步变了就发 `message-updated`（整份，限速），回合结束或它再开口时定格。别处干活的前缀、子代理数都在这个元素里 |
| 草稿（`draft` 状态） | 前端拿它在对话末尾画字 | 对话里不再用；只给点开详情后的弹窗用 |

待定：不能改消息的应用（QQ 桥）怎么收正在写的话。倾向：这类连接只在写完时收一次 `message-created`。

## 3. 前端怎么画

- **行表**：一张表，键是消息编号；自己发出、还没编号的，键是 `input`。事件、`message.list`、本机缓存都先进表，组件只读表。顺序、合并头像、去重都只在这里。
- **合并头像**：纯函数，输入是表里的消息序列，只看发送者是否相同、中间有没有别人的消息。不看状态，不看时间。
- **在干活**（kumo，2026-11-24）：干的活是消息的一部分，不是另外的行，也不在输入框上方另设位置。agent 先说话（提示词里要求），这句话是一条消息；它接着干的活由服务端写成这条消息里的一个元素（`<iridium:work>`，名字待定），用 `message-updated` 更新。前端把它画成这条消息话下面的一行，高度固定：在哪（别的电脑、别的文件夹时的前缀）、第几步、正在跑什么、几个子代理；在跑时右端是停止键。它再说一段话就是下一条消息，之后的活记在新的那条上，上一条的那一行定格成“几步、用时”。
- **没先说话就干活**（kumo，2026-11-24）：没关系，服务端在它这回合的第一个动作时就建消息，没有话时这条消息只有那个元素，元素自己有样式。前端只有一种画法。
- **点那一行**（kumo，2026-11-24：用户习惯有工具展开和弹窗详情）：两层，都要人点。第一层原地展开步骤列表，一步一行（序号、图标、工具名、输入的开头、用时），高度有上限（约 8 行），超过在框里滚；再点收起。在干活时展开的，框直接是上限高度，新步骤在框里加，框不长；干完的按实际行数，展开一次定下。第二层点其中一步，弹窗看完整输入、输出、diff。展开过哪些记在本浏览器。步骤从 agent 的记录读（`block.list`，按消息的出处）。
- **工具详情不加深**（kumo，2026-11-24）：输入、输出两块不加深底色；被点开的那一步、正在执行的那一步也不加深。和周围同一个底，靠缩进、图标、字色区分。
- **不再做的**：从 agent 的记录取中途的话画在头像下；按会话状态在末尾画带头像的行；`SEND_HOLD`、`LINGER`、`SKEW` 这类用时间代替顺序的等待。

留在 React 19.3，不换框架（讨论过 Svelte 5、Solid 2.0，kumo 未定要换）。
